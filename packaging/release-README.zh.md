# TeamX 下载、使用与升级

选择与系统、架构匹配的 `.tar.gz` 归档。包内包含 TeamX、固定 Node/DSH 和团队模板，
运行无需安装 Go 或 Node。模型服务、API Key、平台账号及开发任务自己的工具链由使用者配置。

| 包 | 内容与可选能力 |
| --- | --- |
| core | TeamX、Node/DSH、团队模板；普通对话协作无需 Git。Git Workspace 需要自行安装 Git，GitLab／飞书能力需要另装兼容 CLI |
| standard（推荐） | core 的内容，加 glab、lark-cli 和配套资源；平台账号需登录和绑定，Git Workspace 仍需自行安装 Git |
| full | standard 的内容，加完整 Git 运行时；无需另装 Git |

Scion 当前暂不随包提供运行能力。DSH 固定为 `0.2.2-rc.1` 预发布版本，精确依赖见包内 `manifest.json`。
正式发行默认提供 core 和 standard，full 仅在依赖与验收齐全时提供。包的可用平台、系统基线与已完成的验收范围以对应下载页面和报告为准。

## 下载与校验

正式 Release 提供归档和全局 `SHA256SUMS`，开发快照提供归档及同名 `.tar.gz.sha256`。
若从 Actions 下载 Artifact，先解开外层压缩包，再取其中的 `.tar.gz` 与摘要。

对归档计算 SHA-256，与下载材料中相同文件名的一行逐项比较；将下列文件名替换为实际值：

```sh
# macOS
shasum -a 256 teamx-archive.tar.gz
# Linux
sha256sum teamx-archive.tar.gz
```

确认摘要一致后解压，并进入实际生成的目录；文件名和目录名均替换为实际值：

```sh
tar -xzf teamx-archive.tar.gz
cd teamx-archive
```

## 首次启动

在解压目录直接启动：

```sh
# macOS 首次运行用系统 shell 处理下载隔离；Linux 可直接执行 ./start。
/bin/sh ./start
```

启动会准备缺失的基础文件和固定操作者。全新安装默认仅本机访问、无需登录；打开日志中的地址（默认 `http://127.0.0.1:8088`）。已有安装保持原认证状态。网页中填写协议、Base URL、模型 ID 和 API Key，点击「验证并开始使用」。验证通过后保存默认模型、初始化个人助理并进入对话；验证失败不会发布模型配置。

默认协议为 `openai-completions`。高级设置可声明输入类型、上下文和输出上限、推理强度，以及三态 developer 角色兼容性。已有预填密钥可直接复用，网页不显示密钥值；托管密钥保存在部署机私有目录，后续启动无需 export 或重新输入。开启登录验证后，服务重启需重新登录；已有有效模型不在启动时联网重验。

在「设置 → 安全」开启登录验证时会生成随机令牌，也可填写至少 12 个字符的访问密码（常见密码和明显连续、重复组合会被拒绝）。请先复制保存；更改令牌会撤销浏览器会话。局域网可通过 IP 和端口访问；HTTPS 代理模式需另行配置反向代理及规范地址。保存后正常停止并重启 TeamX，访问方式与连接地址才会生效。关闭正在运行的远程入口后，须先重启回到本机模式，再关闭登录验证。

默认配置、团队模板和私有数据位于包内 `.teamx/`。已有文件与认证不会被覆盖；已有实例缺失或损坏的 token 需要在部署机用 `teamx access init --config <config.toml>` 显式修复。按 Ctrl-C 停止，等待退出后再启动。

也可以直接使用独立 home：

```sh
/bin/sh ./start --home "$HOME/.teamx"
```

`./start init` 是可选步骤，只准备缺失的基础文件和固定操作者后退出，不询问模型、不启动服务。`--non-interactive` 保留兼容用途。`./start doctor` 是可选诊断，不发送模型请求。可从其他目录通过绝对路径调用 `start`；使用独立 home 时包本体可只读（macOS 须先完成下载隔离处理），home 必须可写，同一 home 同时只运行一个服务实例。需要避开端口冲突时可用 `./start --listen 127.0.0.1:8090`。

在「设置 → 模型」维护模型列表、默认模型及使用者，成员可跟随默认或固定使用某个模型。删除被引用的模型须选择替代条目；未完成者可重试，已完成者继续工作。实际模型变化时等待当前回合结束再切换，私有上下文会重置。

已有旧模型与房间配置会在业务恢复前一次迁移，原文件备份位于 home 的私有 `model-migration-backup/`。迁移不联网验证，导入条目标为待验证；缺失密钥在设置中补填，旧 Session 保留原配置与恢复指纹。迁移中断会按持久目标续接，冲突时阻止业务恢复并保留进度查询与重试入口。模板固定引用会阻止删除，须先修正模板。平台连接和通知订阅仍由使用者显式配置。

## 系统要求与 macOS 下载提示

系统需提供 shell、常用命令、证书和进程观察权限。macOS 的 DSH 命令工具需要
`/usr/bin/sandbox-exec`，Linux 需要可用的沙箱后端；系统与动态库基线见
`manifest.json` 中的 `qualification_baseline`。不支持 Windows 或 Alpine/musl。

macOS 包可能未进行 TeamX Developer ID 签名或 Apple 公证。正式发行的具体状态见下载页面与
`release.json` 中对应包的 `signing` 字段；开发快照不承诺已完成 TeamX 签名／公证。上游或 ad-hoc 签名不代表 TeamX 已签名。
先核对下载来源与归档 SHA-256，再用 `/bin/sh ./start` 启动。若包带有下载隔离标记，
启动脚本会显示当前包目录；明确输入 `yes` 后，统一解除该目录及附带工具的下载隔离，
无需逐个允许运行。其他输入或直接回车会取消，包内程序不会执行。后续启动没有隔离标记时不再询问；
新下载的版本可能需要再次确认。此操作不提供签名或公证，也不会全局关闭 Gatekeeper。

下载隔离处理要求包目录可读写；失败时启动会停止。非交互模式不会自动同意解除隔离，
应先在终端完成确认，再运行自动化流程。若仍被系统拦截，保留报错并报告问题。
Linux 通常没有这种下载隔离提示；若出现 `Permission denied`，检查执行权限、目录所在文件系统是否有 `noexec` 限制，以及本机安全策略。

## 升级

停止旧服务并等待退出，备份私有 home。新版本解压到独立目录，先用新的 home 检查，再显式指定原 home。
重复初始化不会自动迁移连接、覆盖旧模板或更新已有运行时路径。

保留旧包与旧运行时路径：已有 Room 冻结了原 DSH 路径，平台连接也可能引用旧 CLI 的绝对路径。
需要让新 Room 使用新运行时时，显式更新配置中的路径；切换已有 Room 的运行时应使用 Session 结清／轮换或新建 Room。
不要删除旧包后期待历史 Session 自动恢复。数据格式变化时，回退程序也不能替代数据备份与恢复。

## 发行材料与许可

`SHA256SUMS` 覆盖发布资产，`release.json` 和每个 `*-assessment.json` 记录绑定到
原归档摘要的发行资格，区分自动检查与维护者人工验收。包内 `manifest.json` 保留构建时状态，
不会为了更新资格重新构建或修改归档。开发快照没有完整正式发行资格，不能沿用其他归档的报告。

`LICENSES.tar.gz` 汇总各包的许可材料，各归档也保留自己的 `LICENSE`、
`THIRD_PARTY_NOTICES/` 和运行时许可。full 的 Git 对应源码与构建材料位于
`THIRD_PARTY_NOTICES/git-source/dugite/`，说明见 `THIRD_PARTY_NOTICES/Git-README.zh.md`。
