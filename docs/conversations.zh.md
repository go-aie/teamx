# 私信、房间与默认助理

TeamX 的会话分为「私信」和「房间」。私信面向单个 Agent，房间使用团队模板；每个会话拥有独立的消息、成员身份、Session、Inbox、规则和工作目录。同名助理或相同角色不会共享运行状态。

## 选择与创建

左侧默认统一展示私信和房间，默认个人助理置顶，其余会话按最近消息时间排序。点击列表标题旁的下拉箭头，可筛选「全部会话／私信／房间」，菜单内显示各类会话数量；筛选不切换当前会话。私信摘要省略对方名称，房间摘要保留发送者。通过「＋ → 新建私信／新建房间」创建。当前新私信使用内置的个人助理角色，可以修改会话名称；新房间选择团队模板。手动新建的助理默认暂停，进入详情后可启用；创建本身不会投递用户消息或连接平台，空态建议也只填入草稿。

私信直接展示唯一 Agent 的详情，保留平台、规则、收件箱、活动记录和启用／暂停控制。普通单成员房间仍使用房间布局。窄屏默认显示聊天，通过「助理详情」展开，关闭后返回聊天；私信顶栏菜单中的「会话通知」与 Agent Inbox 是不同的订阅目标。

Agent 的显示名称用于消息署名、成员列表、头像文字、详情和执行提示；默认使用内部 Agent ID。打开 Agent 详情中的成员设置，可单独保存显示名称。私信标题就是对方的显示名称，从会话标题或成员设置改名都会更新同一个名称；群聊的房间标题与成员名称相互独立。改名不改变成员身份、Session、规则、平台绑定或工作目录。

输入 `@` 后可按显示名称或内部 ID 搜索成员。同名候选会附带内部 ID 供区分。选择后，新消息保存准确的成员目标，改名后历史 @ 会显示新名称，仍指向原成员；不会把已移除成员的 @ 转移给后来使用相同 ID 的成员。草稿和未确认的发送会保留已选目标。旧版仅含文本的历史 @ 保留原文，不自动猜测和补绑身份。

Agent 通过 `read` 读取消息和恢复 Session 时，消息正文 `text` 使用当前提及名称；不额外返回 `display_text`、提及位置或内部成员绑定。原始正文和提及身份仍保存在内部，页面读取保持原有结构。

标签页各自保存选择，刷新优先恢复有效历史；没有有效选择时优先进入默认助理。切换会话或关闭页面不会停止执行，草稿、引用、未读提示、详情和迟到请求结果按完整身份隔离。

## 默认个人助理

托管服务为每个数据目录初始化一次默认「个人助理」，无需用户团队目录；显式单房间模式不创建默认实例。安装器准备 DSH 并启动服务，模型在网页登录后验证和保存，无需执行 `start init`。配置不足时显示实际阻塞及重试引导，不阻断已有房间。

默认助理首次创建保存启用意图；没有真实输入时不发起模型回合或授权。之后的暂停、失败、Session 轮换及恢复沿用普通成员语义，启动、打开或选中会话不会重新启用已暂停助理，也不会重放失败任务。

默认实例作为固定入口不可删除，可以重命名、暂停或重新开始。限制按持久化身份判断，改名后仍有效；手动新建的私信继续可删除。重命名仅修改显示名，不改变 Agent 身份或默认归属。

旧版本已经删除的默认实例不会在升级或启动时自动复活。页面提供「恢复默认助理（新建会话）」；恢复会生成新的 Room／Membership，不恢复原消息、规则或订阅，也不接管同名手动私信。历史删除尚未结清时，须先显式重试完成原删除，不能重新启用部分删除的数据。

## 助理能力与平台接入

个人助理负责梳理需求、协助设置和汇总进展。需要答复时通过 `send` 发布可见消息，普通模型输出保持私有。Assistant 是角色职责，不授予管理其他会话、读取凭据或跨成员配置的权限。

可直接说「连接飞书，关注产品讨论群，以后需要我处理时在这里提醒我」。助理按需读取内置接入 Skill，无需预先绑定平台工具；先复用已核验账号，必要时展示官方授权及账号／群选择组件，再核对当前成员的配置和回执。详细流程见[飞书接入](lark.zh.md#通过对话接入)。

连接属于全局共享资源，群关注、工具和长期规则只属于当前完整成员身份。只连接不附带关注群或启用工具；明确的持续提醒要求通过长期规则保存。连接、群订阅、规则保存和实际提醒分别核验。当前不提供定时任务或跨会话代管。

## 管理接口

管理请求携带目录的 `service_epoch` 和 human `caller`。`GET /v1/rooms` 提供 `agent_roles`、会话类型及 `default_assistant` 引用；`is_direct` 贯通目录、成员列表和 `/v1/info`，不属于身份字段。

通过 `POST /v1/rooms/create` 新建独立私信：

```json
{
  "service_epoch": "目录返回的服务代次",
  "caller": {"kind": "human", "id": "操作者"},
  "create_id": "本次创建的稳定ID",
  "is_direct": true,
  "agent_role_id": "assistant",
  "name": "个人助理"
}
```

普通房间使用 `team_id`；私信使用 `agent_role_id`，两者互斥。名称可省略。私信使用服务默认 runtime，模型和角色在创建时冻结，恢复不重新读取当前模板。新建个人助理使用 `assistant` 角色；已有默认助理保留冻结的角色与成员身份，内置角色更名不会重建会话或改写订阅、规则及历史回执。相同 `create_id` 的重试必须保留类型、来源和名称；改变参数报冲突。创建后使用原 `/v1/rooms/open` 流程，详见[运行手册](../internal/room/README.zh.md#多房间服务)。

默认初始化的管理入口如下：

| 入口 | 请求与行为 |
| --- | --- |
| `GET /v1/rooms` | `default_assistant` 返回完整 Room 引用和 `pending`／`completed` 状态；`deleting`／`deleted` 保留旧版本删除记录 |
| `POST /v1/rooms/default-assistant/retry` | 仅提交当前 `service_epoch` 和 human `caller`；重试原待完成初始化，不热加载配置、不重新启用已完成实例，也不恢复已删除实例 |
| `POST /v1/rooms/default-assistant/restore` | 另提交已删除实例的完整 `room_id`／`room_instance`；核对原删除引用后保存显式恢复意图，再新建默认实例，陈旧／重复请求不重复创建 |

`configuration_required` 提示补齐模型／DSH 配置后重启，再继续原创建；`initialization_failed` 保留实际错误。已经预留的恢复使用冻结配置和身份。`system-default-assistant` 为保留创建 ID，普通创建接口不能使用。

类型与持久化不变量见[Room 架构](room-architecture.zh.md#私信与默认实例)，可复用验证入口和未验范围见[测试说明](testing.zh.md#私信与默认助理)。
