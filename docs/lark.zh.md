# 飞书使用说明

将飞书私信和群消息送入指定助手的收件箱，由助手读取上下文、整理和跟进，需要你决定时在 Room 中提问。人员私聊支持全部／指定范围，群聊支持指定普通群与话题群，以及用户身份的普通消息回复和指定单群发送。

## 1. 准备环境并启动 TeamX

在运行 TeamX 的机器上安装官方 [lark-cli 1.0.99](https://github.com/larksuite/cli/releases/tag/v1.0.99)。当前 TeamX 固定支持此版本；已有应用配置的用户可以直接在连接设置中登录授权。

在启动 TeamX 的同一系统用户下检查：

```sh
command -v lark-cli
lark-cli --version
```

网页会自动检测 CLI 路径、已有应用配置和账号，无需手填 `profile`。未检测到飞书应用配置时，点击「配置并连接」，打开官方配置页面或扫码，创建新应用或选择已有应用；应用配置完成后，页面自动继续账号授权。正常流程无需使用终端或填写 App ID / Secret。TeamX 保存明确的 profile 引用，OAuth 凭据由 CLI 管理，无需向 TeamX 填写 Token。

已有 TeamX 服务时，先按 `Ctrl-C` 等待旧进程退出，再在项目根目录编译、启动：

```sh
go build -o bin/teamx ./cmd/teamx
./bin/teamx serve --config .teamx/config.toml
```

打开启动日志中的地址，示例配置默认是 <http://127.0.0.1:8088/>。Web 界面随程序一起编译，无需单独启动前端。首次配置 DSH 和模型请先完成 [快速开始](../README.md#快速开始)。

## 2. 为成员接入飞书

### 通过对话接入

在默认个人助理或其他 Agent 会话中直接说「连接飞书」；需要群关注和持续提醒时，可以说「连接飞书，关注产品讨论群，以后需要我处理时在这里提醒我」。助理先读取内置接入 Skill、核对原操作和已验证账号，无需预先开启平台工具。

需要授权时使用消息中的官方按钮或二维码；应用配置和账号授权是不同步骤，服务核验并保存连接后才算连接成功。确有账号或同名群选择时，再通过对话组件核对目标。完整设置和对话使用相同操作与回执，关闭设置不会取消对话发起的操作，返回后继续原步骤。

只要求连接时，会申请当前功能所需的账号权限，不附带开启成员通知、工具或动作许可。明确要求关注群时，仅为当前助理保存指定群的接收范围；新订阅从保存时间起接收所选群的全部消息，私聊关闭，已有订阅保留无关范围、消息模式和接收起点。通过界面接入的默认设置见下一节，两种入口均以实际保存回执为准。

明确的“以后需要我处理时在这里提醒我”保存为当前成员的长期规则，限定群、判断条件和当前会话目的地。群关注只决定消息进入 Inbox，规则保存不表示已经发生提醒；后续相关消息进入后，助理按规则判断并在当前会话用 `send` 提醒，无需额外的平台发送权限。

接续可使用一次有界等待、结果经 Inbox 自动继续，或用户发消息主动继续；三者查询同一原操作，跳过已处理步骤。自动接续受成员启用、暂停、预算、失败恢复和 Inbox 准入约束；被阻塞时保留已保存结果并说明原因，不承诺立即唤醒。连接为全局共享资源，通知、工具和规则仍只属于当前完整 Membership。

### 通过平台界面接入

在「成员详情 → 平台 Tab → 添加平台」搜索已有账号并「添加并启用」，或选择「连接新平台」；当前 Room 和成员均已固定。通知与工具默认勾选，可分别取消，首次接收时间可按需调整。全局「设置 → 平台」只连接账号，随后回到成员平台区添加已有平台。选择飞书或 Lark，填写平台名称，按页面提示连接并核验账号。

| 字段 | 填写方式 |
| --- | --- |
| 平台名称 | 例如“公司飞书”，可修改；改名保留工具入口和通知进度 |
| 平台类型 | 国内选“飞书”，国际版选“Lark”；实例地址自动确定 |
| 账号 | 显示姓名和核验状态；未登录或授权失效时提供登录／重新授权 |
| 应用 | 自动检测本机配置；需要时展开选择或使用官方引导 |
| 详细设置 | 可关闭通知或工具、选择首次起点，或仅添加平台 |
| 修复连接 | 检查 CLI 路径及本机应用，修复后重新检测 |

完成账号核验并保存后，首次默认接收全部可访问的人员私聊，以及全部可访问群聊中的 @我／@所有人 消息到该成员 Inbox，并启用对应平台工具。通知、工具和账号的结果分别展示，依赖缺失会说明原因。已有开关、范围及接收成员保留；不会自动开启协作或追加回合。失败时读取并继续原接入进度，不重复登录。

已有多个本机应用且尚未选择时，点击应用右侧「选择」展开列表；已有连接进入编辑后默认收起选择器。「应用」优先显示本次引导取得的名称，否则显示 App ID；旧配置缺少 App ID 时回退到配置名。账号名只出现在「账号」一行，不用于命名应用。

「配置并连接」会依次显示应用配置和账号授权的链接、二维码；应用配置成功后仍需在官方页面授权账号，不能据此视为连接成功。账号核验成功后，已完成的引导自动收起，连接名称保留，最后点击「连接并启用」提交平台与本次接入设置。应用引导本身不保存平台或修改通知、成员工具绑定。

应用配置已完成而账号授权失败、过期或取消时，页面显示已发现的应用，并提供「继续账号授权」；无需重新配置应用。应用或品牌不符、结果未确认时，先点击「重新检测」并核对应用配置。重新打开设置时会重新发现本机配置，不自动重发应用创建或授权。

飞书官方页面可创建或选择应用，实际可用入口及所需权限、发布和管理员操作以页面提示为准。当前真实验证覆盖飞书已有应用；新应用创建与 Lark 网页路径尚未完成真实验证。Lark 暂不提供「配置并连接」，可继续复用已有配置，或展开「修复连接 → 通过 CLI 配置应用」：选择「创建新应用」或「使用已有应用」，复制命令到服务所在机器，以启动 TeamX 的同一系统用户执行。手动配置已有应用需准备 App ID 和 App Secret，按 CLI 提示填写，完成后点击「重新检测」。

完成授权后页面会自动验证用户身份；点击「连接并启用」也会自动核验。成功后返回列表，显示“连接已保存，账号验证成功”。若已保存但验证失败，保留编辑表单并明确提示，不会自动重复创建连接。未验证或验证失败的连接不能用于新开启的通知或成员读取。CLI 路径和登录态都属于服务所在机器及运行用户，不属于浏览器所在机器。

正常授权成功只提示「账号已验证」，新连接会提醒保存。存在其他共享连接时，提示核对范围；通知恢复规则见下文。若登录无法自动续期，页面会直接提醒联系应用管理员，展开「查看说明」可见到期时间和修复步骤。退出或取消后的授权保留说明也可按需展开。

连接统一申请读取、续期、姓名／人员搜索、普通回复、指定群发送和本人投递所需的当前权限，实际范围以应用已开通权限为准。页面自动检查并分别显示账号能力；用户缺权时点击「补全授权」，应用缺权时使用对应应用的官方权限管理链接。检查未知时可重新检查；非 macOS 服务明确不支持发送。账号条件齐备仍不代表成员工具已开启，具体群访问／发言条件在操作前核验。

「权限状态待刷新」表示检查结果需要更新；「通知因认证失败暂停」记录的是上次采集错误，不直接认定当前授权已失效，可先点击「检查账号」。检查结束后会一起更新账号、工具和通知状态；确实需要重新授权时，再使用页面的授权入口。

「重新授权」或「退出登录」会影响共享同一 profile 的连接和其他 CLI 使用者；操作前会展示受影响的房间，后台会暂停相关通知、结清旧读取并清除旧的验证身份，通知进度和待投递内容保留。权限检查、账号核验和重新授权使用相同的恢复规则：核实仍为原账号后，因凭据问题暂停且仍开启的通知自动恢复，沿用原接收起点、检查进度及待投递内容。共享 profile 下原来已核验为同一账号的连接一起恢复；不会切换到另一账号或重写成员动作许可。凭证版本变化后，已配置的本人投递需在对应成员的「修复能力」重新核验，无需关闭再打开工具。已关闭的通知、账号或连接身份变化、容量不足不会自动恢复，可核对后在通知设置中保存或点击「立即同步」。

「取消本次连接」「取消本次登录」或关闭设置会请求停止等待和后台进程；离开网页时也会尝试发送取消请求，但不能保证浏览器成功送达。取消不会撤销已完成的远端创建、本机写入或账号授权，恢复时先重新检测。配置期间避免从其他终端同时修改 CLI 配置。

「退出登录」清除该应用配置下的全部用户登录，并由 CLI 尝试撤销令牌；不保证取消应用的全部服务端授权。需要完全取消授权时，在飞书 / Lark 的授权管理页处理。配置及授权链接、二维码和会话只保存在服务内存及当前页面中，不写入连接快照或浏览器存储；应用配置与账号授权各最多等待 10 分钟。

## 3. 调整成员工具

首次接入已为明确选择的成员初始化对应平台工具。之后在「成员详情 → 平台 Tab」按平台名称直接开关「使用工具」，立即保存；同类型多个平台独立显示账号和可用性。接收、理解已保存通知及跟进不要求远端工具可用；补读最新消息和执行已开放的动作才需要工具绑定。

工具设置与通知独立，关闭工具不停止收件。明确开启飞书工具时，后端配置当前支持的普通回复、指定普通群发送和本人投递许可，并核验可取得的证据；界面、首次接入和 Agent 使用相同逻辑。已有只读绑定可直接要求启用，无需关闭后重开。只要求开启回复或群发送时，Agent 可仅补充所需动作，不附带本人投递。

成员平台区保留一个「工具」开关；依赖未齐时提供按需修复入口。「修复能力」只修复当前成员已有许可，旧只读绑定可明确开启当前默认动作。

许可已保存不代表所有动作都可执行：本人关系暂未核验不阻止保存其他动作许可，本人投递仍被拒绝；缺少应用权限或当前服务不支持发送时，返回部分可用状态。应用已开通但用户尚未授权所需权限时，先返回「尚未保存／需要补全用户授权」，补权后再启用。重新登录、查看状态和添加已有平台不会自动扩大旧只读绑定或重开已关闭工具。每次操作仍核对准确账号、目标和具体授权，依赖或账号失效时不借用另一平台。Workspace 不作为飞书收件和读取的前置条件。

## 4. 调整消息接收范围

也可以在对应助理会话中直接说「取消关注产品讨论群」「以后只接收研发群和产品群，私聊关掉」或「群消息只接收 @我，不接收 @所有人」。目标明确时直接修改，重名或范围不完整时先澄清；通知修改不改变工具和原接收起点。移除最后一个指定群会关闭群接收，没有其他接收类别时同时关闭总通知。

对话支持私聊启停和切换到全部人员私聊；重新开启会保留已有的指定私聊范围。新选指定私聊、修改指定人员及调整检查间隔仍通过完整设置完成。全部群聊不支持排除个别群；需要取消某群时，先明确要保留的指定群范围。

在成员详情的「平台」Tab点击对应平台「设置」，直接调整当前成员的通知内容和范围，接收者固定；修改后保存，检查间隔和接收起点放在「高级设置」。首次添加可先调整详情再回到添加面板确认，不必先开启采集。平台区的通知与工具开关各自立即保存，不提交详情草稿；已有关闭选择不会被添加操作重开。列表可折叠，异常提示直达对应设置；关闭或暂不可用的项仍保留。飞书仅投递到成员 Inbox，房间通知入口不提供飞书。

| 设置 | 使用方式 |
| --- | --- |
| 人员私聊 | 独立开关，默认全部可访问的人员私聊；可切换指定私聊并搜索多选 |
| 全部人员 | 位于人员私聊版块，默认勾选；后台继续发现新人员会话，不包括机器人私聊、本人自聊或类别未核实的会话 |
| 群聊 | 独立开关，新订阅默认启用全部可访问群聊；可取消「全部群聊」后搜索多选普通群或话题群 |
| 群聊消息 | 新订阅默认接收 @我 和 @所有人；可分别关闭，或接收范围内群聊的全部消息 |
| 已选会话 | 切换全部／指定、关闭／重开类别均保留选择；每类最多 32 个，无需手填 ID |
| 检查间隔 | 默认 10 秒，允许 3～3600 秒；发现与公平扫描意味着不保证每个会话均在一个间隔内送达 |
| 开始接收时间 | 从开启时刻、最近 1 小时、最近 24 小时或指定时间；按系统设置时区输入，不能选择未来 |

仅在已启用类别及选定范围内保留本人消息作为进展上下文，不能绕过关闭的群聊；系统消息、本人自聊和机器人私聊不进入人员私聊接收。总开关与类别偏好分别保存，关闭再开启沿用原范围、进度和积压。

会话列表只读取名称、类型和 ID，不读取消息，也不会自动开启订阅。读取失败时保留已选会话；切换飞书连接会清空会话选择，需要重新选择该账号下的会话。已有订阅的会话 ID 仍可直接显示和移除；目录加载后补充名称，已核验过的名称也会用于显示。会话只需从列表选择，无需手填 ID。

人员私聊和群聊分别展开设置，左侧勾选控制是否接收，标题及右侧区域控制展开／收起。取消「全部人员」后，使用私聊版块内的搜索多选框选择人员；取消「全部群聊」后，使用群聊自己的搜索多选框和消息筛选。可以在未开启时预先选择范围，勾选和展开互不联动。

会话搜索：两个选择器分别保留搜索词、分页和已选项。不输入关键词时分页浏览对应类型；输入群名或联系人姓名后，停止输入约 300 毫秒即远程搜索，不依赖已经加载的会话。群聊搜索包括普通群、话题群及外部群，排除未加入的公开群，支持继续加载搜索结果。人员私聊只搜索聊过的对象；结果较多时需输入更完整的名称。搜索结果仅用于选择，保存订阅后仍会独立核验会话访问权限。

群聊搜索使用已有的 `im:chat:read` 权限。人员私聊搜索另需用户身份权限 `contact:user:search`；先使用连接能力提示中的官方权限管理入口开通，按后台提示完成发布，再在同一连接点击「补全授权」。正常连接和「补全授权」会统一申请当前应用已开通的人员搜索权限。缺少某类搜索权限时，页面会说明原因并保留其他结果；也可清空关键词后继续从列表选择。

首次只测试新消息时，选择「从开启时刻」；想用已有消息验证时，可选择「最近 1 小时」或「指定时间」，无需等待新消息。指定时间保存为固定的绝对时间，重新打开页面仍按系统设置时区显示。**首次保存后，回填范围和起始时间锁定。** 同一成员增删会话、切换指定／全部范围、暂停后重新启用或重启服务，均沿用原接收起点及检查进度。另一成员须在自己的收件箱添加来源，独立选择首次起点，不继承原成员的进度和消费。需要追溯更早消息时，新建房间并在首次保存前选择更早的起始时间。新旧房间独立接收和处理，可能收到相同消息；追溯房间应以复盘为主，避免重复执行已有业务动作。追溯完成后关闭其通知源，否则仍会持续接收新消息。

## 5. 测试收件和助手处理

保存后，可在范围内自行发送新消息测试，或请另一位用户发送符合接收规则的新消息。要接收指定群里他人的普通消息，开启群聊、搜索并选中该群，再将群聊消息设为「全部消息」。配置变更保留原接收起点和检查进度，不重新回放已检查过的历史消息。仅处理已启用类别与选定范围内的消息；机器人私聊仍不接收，关闭的群聊不因本人发送而重新接收。订阅范围和接收起点保持有效。

本人消息是进展上下文（`context_only`），不会因读取而自动创建待办，也不能通过长期规则对本人消息自动回复；明确的真人指令仍可授权具体回复。Agent 应结合上下文更新已有跟进，提醒前重读相关会话；已回复不等于业务完成，覆盖不完整也不等于尚未回复。飞书来源本身不授予 Room 操作权限。

预览和 Agent 读取时会核对本 Room 当前成员的持久化动作回执，以账号、会话和完整原生消息 ID 匹配「Agent 代发」，不依赖正文或姓名。回执晚于消息时，后续读取可补充代发标记；发送结果未知且没有消息 ID 时只提示存在不确定代发，不推断该条是谁发送。无论回执是否已保存，本人消息都按进展上下文处理。其他 Room 或外部工具代发而本 Room 无回执的消息仍显示为本人消息，不据此宣称由真人手动发送。

在「成员详情 → 收件箱」查看通知。可以先保持成员暂停，确认收到后再点击「启用协作」；要直接自动处理，也可以从一开始就启用协作。成员暂停或预算耗尽时仍能收件，但不会启动模型。只在网页预览收件箱不会确认消费。配置平台并返回时，保留原 Tab、消息快照、分页、平台区展开状态和滚动位置；显式刷新消息才返回第一页。来源已配置但暂无消息时，查看其接收、暂停或异常状态，无需再次添加或登录。

新通知与 `lark read` 会将文本、富文本中的 @ 提及展开为姓名和飞书原生 ID；ID 匹配当前读取账号时标注「当前接收账号」，`@所有人` 单独显示。身份来自消息自身的提及信息，无需额外通讯录权限；信息不足时保留「身份未解析」，不会按同名猜测。升级前已保存的通知正文不会自动改写，可以在绑定读取能力后重读原消息。

富文本按飞书原始行组织，同一行中的提及、空格和文字保持行内排列，仅在原始行之间换行。已保存的旧通知没有保留原始行结构，不会按正文猜测并合并历史换行；绑定 `lark` 读取能力后重读原消息可使用新的解析方式。

通知正文及 `lark read` 保留简短的发送者说明：本人显示「姓名（我）」，姓名不可用时显示「我」；他人显示姓名和一份原生 ID，以区分同名用户。本人姓名复用同一连接已验证的账号信息，无需额外通讯录权限；他人姓名通过飞书的[获取用户姓名接口](https://open.feishu.cn/document/server-docs/contact-v3/user/basic_batch)查询，需要 `contact:user.basic_profile:readonly`。查询按原生 ID 去重、每批最多 10 人，每页最多 5 批，合计限时 3 秒；无法取得姓名时保留「飞书用户」和 ID。

为减少 Agent 上下文中的重复信息，正文不重复结构化来源已有的会话 ID、本人 ID，也不展开 `sender_type`、`tenant_key`；完整原始发送者结构仍保存在通知来源中。网页会将身份移至消息标题，完整来源放入默认折叠的「来源详情」；上一版已保存的冗长通知也适用网页精简展示。已有通知正文不会自动改写，Agent 重读原消息时使用精简后的内容。姓名和显示信息不代表 Room 成员身份或操作授权。

助手在有效回合中读取 Inbox，使用通知里已保存的原生身份建立引用和更新跟进；读取已收到的正文和开展跟进无需绑定成员 `lark` 工具，也不会再次查询原消息。来源的 `evidence_source=notification` 表示采集时快照，不代表当前远端状态已核实。需要补充前后文或重读最新内容时，再为成员绑定 `lark` 并使用 `lark read`；该读取仍独立核对当前连接与账号权限。旧的 `binding_unavailable` 来源可在有效回合通过 `matters resolve` 从原通知恢复，不重投递或改变消费状态。

需要决定时，助手在 Room 提问。原始飞书消息送入成员收件箱，不会自动复制到 Room。可以在「长期规则 → 跟进记录」查看处理进展，并在 Room 中回复助手的问题。

**检查间隔是调度周期，不是消息到达保证。** 系统按固定时间窗跨会话搜索，并读取命中消息、独立核验会话及成员关系；采集不等待完整目录发现。首次接收、积压及大范围全部消息可能需要较长时间；关闭浏览器页面不会停止后台处理。

采集主路径使用跨会话搜索。新订阅默认接收全部人员私聊，以及全部群聊的「@我／@所有人」和本人上下文；已有订阅保留原开关、所选会话和开始接收时间。全部群聊＋全部消息会直接提示模型用量与费用。搜索覆盖与到达延迟仍受账号权限、索引更新及实际消息量影响。

## 查看诊断与恢复

### 收件箱图片与助手识图

图片消息和富文本中的图片会在收件箱显示缩略图，点击在当前页面弹窗放大，可通过「关闭」、Esc 或点击遮罩退出。图片加载失败后点击重试也留在当前页面。升级前已保存的 `image_key:` 通知同样支持预览，无需重新投递。图片通过该通知原有的飞书连接读取，不需要给成员另行绑定 `lark` 工具；成员重读其他上下文仍需配置读取绑定。

助手使用支持图片的模型时，TeamX 会在回合开始前准备当前未消费通知中的图片，将文字与图片一起传给 DSH。模型配置需要 `input_modalities = ["text", "image"]`，且实际 ACP Session 支持图片。默认每回合合计扫描 25 条 Room／Inbox 记录，最多 4 张图，单图 2 MiB、合计 4 MiB、单图 16777216 像素，准备时间 30 秒；可通过 `[server.image_materials]` 收紧或在服务上限内调整。

页面预览与模型输入分别执行：打开图片不会消费 Inbox；已经消费的历史通知不会因打开预览而自动再次送给模型。纯文本 Session 不下载图片；权限不足、图片撤回、超限或超时均向模型明确说明未读，不阻止其他可用图片。单独的文件、视频、语音和卡片图片不在本次支持范围。

官方 CLI 下载会使用私有临时目录，请求结束后删除；TeamX 不新增持久图片缓存。成功传给 DSH 的图片仍由其私有 Session 附件机制管理。真实验证范围见下文[图片验证](#图片验证)。

在飞书消息页展开「同步记录与诊断」：

| 现象 | 含义与处理 |
| --- | --- |
| 分支时间窗或当前页仍在处理 | 搜索及补全按步骤推进；查看各分支完成上界和页内进度，不能把搜索末页当作远端完整性证明 |
| 完成上界落后、来源积压增加 | 仍有积压；结合分支窗口、错误、重试及 Inbox 容量判断，不能仅靠缩短周期推断已追平 |
| 读取受阻 | 查看对应会话错误和重试时间，确认账号仍可访问该会话 |
| 来源积压大于 0 | 消息尚未交付成员；检查投递错误、成员是否有效以及 Inbox 是否满载 |
| 登录失效或权限不足 | 在原 profile 完成用户重新授权并重新验证连接；原账号下仍开启的凭据暂停订阅会自动恢复 |
| 账号已变化 | 核对原连接及原账号，再验证和同步；不要把同名显示名视为同一账号 |
| 游标过期 | 系统会重搜原冻结时间窗，保留已接纳和去重证据 |
| 积压超过 24 小时 | 存在尚未追平的 gap，检查失败范围、容量和重试；系统不会直接跳过历史 |

「立即同步」使用已经保存的配置；有未保存修改时先保存。它不保证一次完成所有查询分支和积压，也不会越过有错误的当前页。

关闭「接收通知」立即暂停该成员的新查询和投递，保留进度、积压及已收消息。再次开启继续原进度。需要另一成员接收时，在其收件箱添加来源，独立创建订阅，不改写旧订阅目标；当前没有旧积压转交或清理入口。新增其他平台通知也不覆盖原成员的设置；原平台更换账号仍沿用账号变更与退役结清规则。

## 当前边界

- 普通私聊／群聊回复与指定单群发送已通过真实用户身份 Agent 验收，应用成员连接后可用；每次动作仍核验账号、目标与具体业务授权。不改变飞书客户端已读状态。
- 本人投递已提供，需成员单独启用并核验本人会话；本人自聊不回流到 Inbox。向其他用户主动私信仍未开放，不会回退为机器人发送。连接统一申请当前功能所需 OAuth 权限；授权本身不修改成员绑定。人员搜索缺权只影响该项功能，准确原生 ID 无需全通讯录授权。
- 图片消息与富文本图片支持收件箱预览及模型输入；其他附件保留资源引用和未读取说明，完整原生话题历史尚未交付。
- 全会话代码已实施，跨 Token 到期续期、实际后台身份／钥匙串访问，以及长期覆盖和到达时延仍有待现场验收。

通知、消费和跟进的通用语义见 [平台通知](notifications.zh.md)；实际验证范围及复验入口见下文[真实验收](#真实验收)。

### 连接验证

`node internal/room/testdata/lark_guided_connection_browser.cjs` 检查生产页面的引导状态及桌面／手机尺寸布局，API 使用隔离模拟数据；不能算作新应用、Lark 或实体手机的真实连接通过。

### 消息与动作验证

历史窗口闭环入口为 `TestRealLarkNotificationInbox`（`internal/room`，`-tags=e2e`），通过 `TEAMX_LARK_TEST_INPUT` 提供私有 JSON：明确的 `profile`、`brand`、两个 `chats` 和不超过 24 小时的 Unix 秒 `start/end`。真实模型另设 `TEAMX_LARK_DSH_REAL=1`、全新绝对 `TEAMX_DSH_OUTPUT` 及[DSH 安装／模型环境](agent-runtime.zh.md#真实验收)。

持续发现仅使用隔离来源状态，不创建生产订阅或更改登录：

```sh
TEAMX_LARK_ALL_REAL=1 TEAMX_LARK_TEST_PROFILE=EXPLICIT_PROFILE \
TEAMX_LARK_TEST_BIN=/absolute/lark-cli TEAMX_LARK_TEST_BRAND=feishu \
TEAMX_LARK_RUN_SECONDS=180 TEAMX_LARK_REPORT=/absolute/private/report.json \
go test -tags=e2e ./internal/platform/lark -run '^TestRealLarkAllChatsContinuous$' -count=1 -v
```

允许运行 30～1800 秒，报告只保存聚合数量；前台 CLI 持续运行不替代后台部署及跨到期验证。普通回复、群发送和本人投递的复跑分别使用 `platform_lark_reply_dsh_real_test.go`、`platform_lark_send_dsh_real_test.go` 和 `platform_lark_self_send_dsh_real_test.go` 的显式开关与输入合同。新发送须另行指定准确账号、目标、正文及次数；保留 `.local/lark-l4-c/*native-attempt*`、`.local/lark-self-send-s2/native-attempt*`、原消息 ID 和 unknown 回执，不删除防重记录来重试。`TestRealLarkSelfReadOnlyRecovery` 可通过 `TEAMX_LARK_SELF_RECOVERY_SOURCE` 指向成功投递的 rooms root 只读复验，不新增发送。

### 图片验证

真实下载和模型读图已有通过记录，实际浏览器图片视觉检查尚未通过；服务重启后的新消息闭环、已消费历史消息补图、恢复／轮换后识图及完整权限变化矩阵仍待验证。

复跑入口为 `TestRealLarkImageMaterials`（`internal/room`，`-tags=e2e`）：`TEAMX_LARK_IMAGE_INPUT` 指向包含 `profile`（`platform.CLIProfile`）、已保存通知 `item` 和可选 `model` 的私有 JSON，不含 OAuth 凭据；`TEAMX_DSH_OUTPUT` 使用全新绝对路径。模型验证另设 `TEAMX_LARK_IMAGE_MODEL=1` 及 `TEAMX_LARK_IMAGE_EXPECT`（像素中独有文字的 JSON 数组，不放入提示），安装与凭据沿用 DSH 配置。`TEAMX_LARK_IMAGE_BROWSER=1` 启动隔离页面，实际目视确认后才写输出目录的 `browser-done`。下载、模型结果与页面显示分别判定，不互相替代。
