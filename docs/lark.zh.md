# 飞书使用说明

将飞书私信和群里的明确提及送入指定助手的收件箱，由助手读取上下文、整理和跟进，需要你决定时在 Room 中提问。当前支持指定会话和全部可访问会话两种范围，飞书回复尚未开放。

## 1. 准备环境并启动 TeamX

在运行 TeamX 的机器上安装官方 [lark-cli 1.0.99](https://github.com/larksuite/cli/releases/tag/v1.0.99)，并完成用户身份授权。当前 TeamX 固定支持此版本；CLI 的安装和登录按该版本说明操作。

在启动 TeamX 的同一系统用户下检查：

```sh
command -v lark-cli
lark-cli --version
lark-cli whoami --as user
```

记下可执行文件的绝对路径和输出中的 `profile`。确认身份为 `user`、`available` 为 `true`；后续网页中的连接验证还会核实远端账号。TeamX 通过显式 profile 读取，OAuth 凭据由 CLI 管理，无需向 TeamX 填写 Token。

已有 TeamX 服务时，先按 `Ctrl-C` 等待旧进程退出，再在项目根目录编译、启动：

```sh
go build -o bin/teamx ./cmd/teamx
./bin/teamx serve --config .teamx/config.toml
```

打开启动日志中的地址，示例配置默认是 <http://127.0.0.1:8088/>。Web 界面随程序一起编译，无需单独启动前端。首次配置 DSH 和模型请先完成 [快速开始](../README.md#快速开始)。

## 2. 添加并验证飞书连接

点击左下角「设置 → 平台连接」，新增连接：

| 字段 | 填写方式 |
| --- | --- |
| 连接名称 | 自定，例如“我的飞书” |
| 平台 | 飞书 / Lark |
| 品牌 | 国内飞书选“飞书”，国际版选“Lark” |
| 实例地址 | 飞书为 `https://open.feishu.cn`；Lark 为 `https://open.larksuite.com` |
| CLI 可执行文件绝对路径 | 使用上一步查到的路径，例如 `/opt/homebrew/bin/lark-cli` |
| 已登录的 profile | 使用上一步查到的 `profile`，不是账号显示名或邮箱 |

`profile` 和 CLI 绝对路径为必填项。保存成功会返回连接列表，显示“连接已保存，尚未验证”；字段不完整时保留表单并提示具体原因。打开已保存的连接，点击「验证连接」，确认显示的用户账号正确。未验证或验证失败的连接不能用于新开启的通知或成员读取。

## 3. 按需为成员绑定补充读取能力

进入一个房间，也可以通过左侧「＋」选择「个人助手」创建新房间。

1. 点击要接收通知的助手成员，进入「工具设置」。
2. 找到 `lark`，在「连接账号与实例」中选择刚验证的连接。
3. 点击「应用」，等待成功提示。

仅接收、理解已投递通知和开展跟进可跳过本节。成员绑定用于重读最新原消息和读取额外的有界上下文；它与通知源连接分别配置，通常选择同一账号，开启通知不会自动替成员绑定工具。仅接收通知不需要克隆仓库或配置 Workspace。

## 4. 开启飞书消息通知

打开右侧「通知源 → 飞书消息」：

1. 勾选「接收飞书消息」。
2. 选择已验证连接，以及当前房间中的接收成员。
3. 选择会话范围和消息类型。
4. 设置检查周期与首次历史回填，点击「保存设置」。

| 设置 | 使用方式 |
| --- | --- |
| 指定会话 | 每行填写一个原生 `oc_…` 会话 ID，最多 32 个；不能填写姓名或群名 |
| 全部可访问私聊与已加入群聊 | 自动分页发现会话，无需填写 ID；目录约每 10 分钟刷新 |
| 对方发来的私信 | 默认开启；排除本人发送和系统消息 |
| 群里明确 @我 | 默认开启；无提及的普通群消息不触发通知 |
| 同时接收 @所有人 | 默认关闭，与明确 @本人分别控制 |
| 同时接收机器人私信 | 默认关闭 |
| 检查周期 | 默认 60 秒，允许 3～3600 秒 |
| 首次历史回填 | 可选从开启时刻、最近 1 小时或最近 24 小时接收 |

首次只测试新消息时，选择「从开启时刻接收」；想用已有消息验证时，选择「最近 1 小时」。**首次保存后，回填范围不能修改。** 后续增删会话、切换指定／全部范围或更换接收成员，仍沿用原订阅基线，不会从修改时刻重新计算。

指定模式需要查找会话 ID 时，可使用显式 profile 枚举已加入会话，将 `YOUR_PROFILE` 替换成实际值：

```sh
lark-cli --profile YOUR_PROFILE im +chat-list \
  --types p2p,group --page-size 50 --as user --format json
```

从 `data.chats` 中选取 `chat_id`。若 `has_more=true`，使用返回的 `page_token` 加上 `--page-token` 继续读取下一页。

## 5. 测试收件和助手处理

保存后，请另一位用户给你发送一条新私信，或在已加入的群里明确 `@你`。本人发送的消息会被排除；群里的 `@所有人` 只有打开对应开关才会接收。

在「成员详情 → 收件箱」查看通知。可以先保持成员暂停，确认收到后再点击「启用协作」；要直接自动处理，也可以从一开始就启用协作。成员暂停或预算耗尽时仍能收件，但不会启动模型。只在网页预览收件箱不会确认消费。

新通知与 `lark read` 会将文本、富文本中的 @ 提及展开为姓名和飞书原生 ID；ID 匹配当前读取账号时标注「当前接收账号」，`@所有人` 单独显示。身份来自消息自身的提及信息，无需额外通讯录权限；信息不足时保留「身份未解析」，不会按同名猜测。升级前已保存的通知正文不会自动改写，可以在绑定读取能力后重读原消息。

通知正文及 `lark read` 保留简短的发送者说明：本人显示「姓名（我）」，姓名不可用时显示「我」；他人显示姓名和一份原生 ID，以区分同名用户。本人姓名复用同一连接已验证的账号信息，无需额外通讯录权限；他人姓名通过飞书的[获取用户姓名接口](https://open.feishu.cn/document/server-docs/contact-v3/user/basic_batch)查询，需要 `contact:user.basic_profile:readonly`。查询按原生 ID 去重、每批最多 10 人，每页最多 5 批，合计限时 3 秒；无法取得姓名时保留「飞书用户」和 ID。

为减少 Agent 上下文中的重复信息，正文不重复结构化来源已有的会话 ID、本人 ID，也不展开 `sender_type`、`tenant_key`；完整原始发送者结构仍保存在通知来源中。网页会将身份移至消息标题，完整来源放入默认折叠的「来源详情」；上一版已保存的冗长通知也适用网页精简展示。已有通知正文不会自动改写，Agent 重读原消息时使用精简后的内容。姓名和显示信息不代表 Room 成员身份或操作授权。

助手在有效回合中读取 Inbox，使用通知里已保存的原生身份建立引用和更新跟进；读取已收到的正文和开展跟进无需绑定成员 `lark` 工具，也不会再次查询原消息。来源的 `evidence_source=notification` 表示采集时快照，不代表当前远端状态已核实。需要补充前后文或重读最新内容时，再为成员绑定 `lark` 并使用 `lark read`；该读取仍独立核对当前连接与账号权限。旧的 `binding_unavailable` 来源可在有效回合通过 `matters resolve` 从原通知恢复，不重投递或改变消费状态。

需要决定时，助手在 Room 提问。原始飞书消息送入成员收件箱，不会自动复制到 Room。可以在「偏好与规则 → 跟进记录」查看处理进展，并在 Room 中回复助手的问题。

**60 秒是调度周期，不是每个会话的到达保证。** 全部模式首次扫描可能需要数分钟或更久；新私聊、新加入群还需要等待目录发现。服务运行时会继续后台轮询，关闭浏览器页面不会停止处理。

## 查看诊断与恢复

### 收件箱图片与助手识图

图片消息和富文本中的图片会在收件箱显示缩略图，点击可打开原图。升级前已保存的 `image_key:` 通知也支持预览，无需重新投递。图片通过该通知原有的飞书连接读取，不需要给成员另行绑定 `lark` 工具；成员重读其他上下文仍需配置读取绑定。

助手使用支持图片的模型时，TeamX 会在回合开始前准备当前未消费通知中的图片，将文字与图片一起传给 DSH。模型配置需要 `input_modalities = ["text", "image"]`，且实际 ACP Session 支持图片。默认每回合合计扫描 25 条 Room／Inbox 记录，最多 4 张图，单图 2 MiB、合计 4 MiB、单图 16777216 像素，准备时间 30 秒；可通过 `[server.image_materials]` 收紧或在服务上限内调整。

页面预览与模型输入分别执行：打开图片不会消费 Inbox；已经消费的历史通知不会因打开预览而自动再次送给模型。纯文本 Session 不下载图片；权限不足、图片撤回、超限或超时均向模型明确说明未读，不阻止其他可用图片。单独的文件、视频、语音和卡片图片不在本次支持范围。

官方 CLI 下载会使用私有临时目录，请求结束后删除；TeamX 不新增持久图片缓存。成功传给 DSH 的图片仍由其私有 Session 附件机制管理。真实验证范围见 [图片验收记录](lark-image-acceptance.zh.md)。

在飞书消息页展开「同步记录与诊断」：

| 现象 | 含义与处理 |
| --- | --- |
| 目录未完成、分页页数增加 | 仍在发现会话；等待后续分页。目录完整只代表枚举结束，不代表全部消息窗口已扫完 |
| 待扫描较多、最久落后增加 | 仍有积压；结合逐会话窗口和错误判断，不能仅靠缩短周期推断已追平 |
| 读取受阻 | 查看对应会话错误和重试时间，确认账号仍可访问该会话 |
| 来源积压大于 0 | 消息尚未交付成员；检查投递错误、成员是否有效以及 Inbox 是否满载 |
| 登录失效或权限不足 | 在原 profile 完成用户重新授权，在平台连接中重新验证，然后回飞书通知页点击「立即同步」 |
| 账号已变化 | 核对原连接及原账号，再验证和同步；不要把同名显示名视为同一账号 |
| 游标过期 | 系统会重扫原目录或时间窗，保留消息检查点和去重记录 |
| 积压超过 24 小时 | 存在尚未追平的 gap，检查失败范围、容量和重试；系统不会直接跳过历史 |

「立即同步」使用已经保存的配置；有未保存修改时先保存。它不保证一次完成所有会话，也不强制提前刷新尚未到期的目录。

关闭「接收飞书消息」并保存会暂停查询和投递，保留进度与积压。再次开启会继续原进度。更换接收成员只影响之后首次接收的消息，旧积压保留原目标；当前没有旧积压转交或清理入口。改用不同连接或账号时，系统会新建订阅，保留并暂停旧订阅及其积压。

## 当前边界

- 当前为只读收件与处理，不支持向飞书自动回复，也不改变飞书客户端已读状态。
- 图片消息与富文本图片支持收件箱预览及模型输入；其他附件保留资源引用和未读取说明，完整原生话题历史尚未交付。
- 全会话代码已实施，跨 Token 到期续期、实际后台身份／钥匙串访问，以及长期覆盖和到达时延仍有待现场验收。

通知、消费和跟进的通用语义见 [平台通知](notifications.zh.md)；实际验证范围及复验入口见 [L2 验收记录](lark-l2-acceptance.zh.md)和 [L3 验收记录](lark-l3-acceptance.zh.md)。
