# 飞书使用指南

将飞书 / Lark 私聊和群消息送入指定助手的收件箱，让助手整理、跟进，需要你决定时在会话中提问。也支持用户身份的普通消息回复、指定单群发送及单独启用的本人投递；每次操作仍需准确的目标与业务授权。

## 1. 准备环境并启动 TeamX

先完成 [TeamX 安装与模型配置](installation.zh.md)。standard 包已包含官方 **lark-cli 1.0.99**，可直接接入，无需重新编译或停止服务。core 或源码运行时，在服务机器为运行 TeamX 的系统用户另行安装[固定版本 CLI](https://github.com/larksuite/cli/releases/tag/v1.0.99)，配置排查见[开发运行参考](../internal/room/README.zh.md#服务配置)。

CLI、应用配置和登录态属于服务机器及其运行账号，不属于浏览器设备。当前非 macOS 服务不支持发送，Linux 凭据保存及运行限制见[安装指南](installation.zh.md#模型与平台的后续设置)。

## 2. 为成员接入飞书

### 通过对话接入

在个人助理中直接说：

> 连接飞书，关注产品讨论群，以后需要我处理时在这里提醒我。

助理先复用已核验的账号；确需授权或选择账号、同名群时，按对话中的官方链接、二维码和选择组件完成。无需预先启用平台工具。

只说「连接飞书」时，只连接账号，不附带开启通知或工具。明确要求关注群时，为当前助理订阅所选群；新订阅从保存时刻接收该群全部消息，私聊关闭。持续提醒要求另存为长期规则；已有订阅保留无关设置。

连接保存、群订阅、规则保存和实际提醒分别确认。授权或选择完成后，操作可经收件箱自动接续；成员暂停、模型失败或其他执行阻塞时不会保证立即处理。可以继续在原会话询问进度，不必新建连接或重新授权。

### 通过平台界面接入

1. 打开「成员详情 → 平台 → 添加平台」，选择已有账号并「添加并启用」，或选择「连接新平台 → 飞书 / Lark」。
2. 按提示填写平台名称并连接。飞书缺少应用时，使用「配置并连接」进入官方页面创建或选择应用，再完成账号授权；已有配置可直接登录。正常飞书引导无需手填 App ID 或 Secret。
3. 核对实际账号，点击「连接并启用」。页面分别展示连接、通知和工具结果，保存成功才算接入完成。

Lark 可复用已有配置；缺少应用时，展开「修复连接 → 通过 CLI 配置应用」，在服务机器使用同一系统账号按提示操作，再重新检测。多个应用或账号时须选择准确目标。应用配置完成与账号授权成功是两个步骤。

首次默认启用工具，并接收**全部可访问人员私聊，以及全部可访问群聊中的 @我／@所有人**。添加前可以分别取消通知或工具，调整接收范围和首次起点。已有开关与范围保留，不会因再次添加而重开，也不会自动启用协作。

全局「设置 → 平台」可先连接账号，随后在成员详情添加；全局连接本身不订阅消息或启用成员工具。

## 3. 调整成员工具

在成员平台行开关「使用工具」，立即保存，关闭工具不停止收件。已保存通知的读取和跟进不要求远端工具可用；重读最新内容、补充上下文或发送消息时才需要对应工具和权限。无需配置 Workspace。

明确启用飞书工具时，会配置当前支持的回复、指定群发送和本人投递许可，并核验可取得的能力证据。许可保存不表示所有动作均可用：本人投递还需核验本人会话，应用或用户缺权时按页面「补全授权」处理，再启用工具；已有许可受阻时使用「修复能力」。只要求某种动作时可通过对话明确说明。

能力检查中的「图片上传权限」只表示资源权限状态，缺少它不影响原有文字发送。成员平台行的「图文范围」显示支持的目标；实际发送仍需成员工具许可、本人会话核验或指定群的直接指令，以及目标访问权限。

需要修复图片权限时，在原成员的平台行点击「查看图片权限」。应用缺权按官方应用权限入口开通用户 `im:resource`，用户缺权再使用「补全授权」；检查过期或失败先重新检查，固定账号不可用先核验原账号。已有连接直接复用，无需关闭文字工具或重复启用其他成员。重新授权后，本人投递证据可能需在对应成员重新核验。

重新登录或添加已有平台不会自动扩大旧只读绑定。账号、应用权限、成员许可和具体业务授权在实际操作时分别核验，不借用另一账号，也不回退为机器人发送。

## 4. 调整消息接收范围

可以直接对助理说「取消关注产品讨论群」「以后只接收研发群和产品群，私聊关掉」或「群消息只接收 @我，不接收 @所有人」。新选指定私聊、调整人员及检查间隔通过完整设置完成。

在「成员详情 → 平台 → 对应平台设置」调整并保存：

| 设置 | 使用方式 |
| --- | --- |
| 人员私聊 | 默认全部可访问人员；可取消「全部人员」，搜索选择聊过的对象 |
| 群聊 | 默认全部可访问群聊；可取消「全部群聊」，搜索选择普通群、话题群或已加入的外部群 |
| 群聊消息 | 默认 @我 和 @所有人；可分别关闭，或接收范围内群聊的全部消息 |
| 检查间隔 | 默认 10 秒，允许 3～3600 秒；不保证每个会话在一个间隔内送达 |
| 开始接收时间 | 从开启时刻、最近 1 小时、最近 24 小时或指定时间；首次保存后锁定 |

私聊和群聊独立开关，切换全部／指定或关闭／重开均保留所选会话，每类最多 32 个。搜索和分页不丢失已选项，无需手填 ID；更换连接时需重新选择新账号下的会话。全部群聊不支持排除个别群，需要缩小范围时明确选择要保留的群。全部群聊接收全部消息会提示模型用量与费用。

范围内的本人消息作为进展上下文保留；本人自聊、系统消息和机器人私聊不作为人员私聊接收，关闭的群聊不会因本人发送而绕过开关。

搜索缺权时按连接中的官方权限管理入口补齐应用权限，再点击「补全授权」。人员搜索需要 `contact:user:search`，群聊搜索使用 `im:chat:read`；也可清空搜索词继续从列表选择。

首次只测新消息时选「从开启时刻」，使用已有消息验证时选历史窗口。暂停、重启、增删会话或修改范围都沿用原起点和进度，不回放已检查过的历史。更早追溯需在新房间首次订阅前选择时间，避免重复执行既有业务动作。

## 5. 测试收件和助手处理

保存订阅后，在范围内发送符合筛选的新消息，或使用首次设置的历史窗口验证。若要接收群内普通消息，须选择该群并将消息模式设为「全部消息」。

在「成员详情 → 收件箱」查看通知，可以先保持成员暂停，确认收件后再启用协作。页面预览不确认 Agent 消费，关闭浏览器也不停止后台采集。

助手在有效回合读取通知并更新跟进，需要决定时在当前会话提问；原始通知不会自动复制到公共消息。可以在「长期规则 → 跟进记录」核对进度，直接在会话中回复。本人消息可作为进展上下文，但不会自动创建待办或触发长期规则回复。

**检查间隔是调度周期，不是到达保证。** 首次接收、积压、大范围搜索、账号权限和平台索引延迟都会影响收件时间。通知收到、模型已处理和实际提醒送达分别核对。

## 查看诊断与恢复

在平台通知设置展开「同步记录与诊断」，先看范围、完成进度、积压及错误，再决定是否立即同步。

| 现象 | 处理 |
| --- | --- |
| 时间窗仍在处理或积压增加 | 查看分支进度、错误及 Inbox 容量；缩短间隔不能保证追平 |
| 登录失效或权限不足 | 在原连接核对账号、补权或重新授权；仍为原账号且开启的凭据暂停订阅可恢复原进度 |
| 账号变化 | 核对准确账号后再验证，不能按同名显示名继续 |
| 接入部分失败或取消后返回 | 读取原接入进度、重新检测并继续，不重复配置应用或登录 |
| 消息发送结果未知 | 保留原回执，先只读核实目标、作者及正文，避免重复发送 |

「立即同步」使用已保存配置，不保证一次处理完全部积压。关闭通知暂停新查询和投递，保留范围及进度；重新开启继续原进度，不能把旧积压转交另一成员。

「重新授权」「退出登录」会影响共享同一应用配置的连接和其他 CLI 使用者，先核对页面展示的引用房间。退出会清除该配置下的用户登录，并由 CLI 尝试撤销令牌；彻底取消授权需在飞书 / Lark 授权管理页处理。取消操作不撤销已经完成的远端授权，返回后先重新检测。

### 将 Room 原图发送到飞书

在托管 Room 或默认助理会话上传并发送图片后，可以要求“把上面的两张图发到我的飞书”，或“把这段说明和两张图一起发到项目群”。助手复用当前成员已绑定的飞书用户账号，向本人自聊或准确的单个受支持群发送，无需手动下载或提供文件路径。支持普通内部群，账号须在群内且允许全员发言；重名群会先让你选择。

支持当前会话仍保留的人类 PNG、JPEG、WebP 图片，每条最多 4 张，单图 2 MiB、合计 4 MiB。单图、多图及说明加图片均合为一条消息；说明保留原文和空行，文字在前，图片按所选顺序在后。TeamX 上传保存的原图字节，不压缩或重绘。已经消费的图片仍可从保留历史选择，转发不要求模型能够识图。

成功回执表示已核实账号、目标、完整文字及全部图片，不表示对方已读。来源或上传失败时整条消息不发送；结果未知时保留原回执并只读查询，不换 ID 重发。普通消息回复仍仅支持文字，通知来源图片、任意外部图片链接和跨会话图片不在当前转发范围。

### 收件箱图片与助手识图

图片消息和富文本图片可在收件箱点击预览，失败可重试；通过原通知连接读取，无需另行启用成员工具。支持图片的模型与实际 Session 就绪时，TeamX 会另行准备当前未消费通知的图片。

模型需配置 `input_modalities = ["text", "image"]`。默认每轮合计扫描 25 条 Room／Inbox 记录，最多 4 张图，单图 2 MiB、合计 4 MiB、单图 16777216 像素，准备时间 30 秒；可通过 `[server.image_materials]` 调整。

页面预览不消费通知，也不会把已消费历史图片重新送给模型。纯文本、权限不足、撤回、超限或超时会说明未读；文件、视频、语音和卡片图片不在支持范围。TeamX 不新增持久图片缓存，提交后的图片仍由 DSH 私有会话附件机制管理。

## 当前边界

- 普通私聊／群聊回复、指定单群发送和单独启用的本人投递可用；不支持话题回复或向其他用户主动私信，也不改变飞书客户端已读状态。
- 本人投递须核验本人会话，本人自聊不回流 Inbox。当前非 macOS 服务不支持发送。
- 真实验证覆盖飞书已有应用；新应用创建、Lark 网页路径、实体手机、跨令牌到期续期及长期覆盖仍有待验项。

读取、跟进和规则的共同用法见[平台通知与跟进](notifications.zh.md)，完整真实验证范围与复跑命令见[测试说明](testing.zh.md#飞书真实验收)。消息结构及 Agent 读取合同见[通知技术参考](reference/notifications.zh.md#飞书消息读取与展示)。
