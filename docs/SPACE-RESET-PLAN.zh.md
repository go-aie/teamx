# Space 数据与设置重置方案

日期：2026-11-25。状态：**阶段 1／2 已实现并完成对应增量验证；阶段 3 的 Linux amd64 standard／SRT 开发组合交付验证通过**。实现和证据边界见[个人空间重置](implementation/space-reset-personal.zh.md)、[Linux 多用户空间重置](implementation/space-reset-hosted.zh.md)与[安装交付验证](implementation/space-reset-delivery.zh.md)。最终归档的新装、旧包升级及重置冒烟通过，修复了 root 维护时误判空间登记文件 owner 的问题；日常服务未变。其他安装组合未由本次声明，正式发行沿用已有前置。

## 1. 目标与边界

个人版与多用户版提供“重置此空间”：清空当前 Space 在 TeamX 内部的业务数据和设置，恢复为**当前运行版本的首次使用状态**。保留 SpaceID、名称、所属用户及登记根目录，继续使用原空间。

| 清理 | 保留 |
| --- | --- |
| 会话、消息、Agent 私有 Session、附件、输入流／Inbox、通知、日历与定时任务、规则、业务操作记录 | 其他 Space、用户身份、系统登录、部署配置 |
| 本空间模型定义、默认模型选择、模型密钥、平台连接及空间私有凭证 | 用户级网关凭据、部署级服务应用及其密钥 |
| TeamX 管理的默认工作目录、受管仓库副本、自定义模板及空间偏好 | 用户指定的已有目录文件；解除该空间的绑定 |
| 本空间临时文件、凭证副本、迁移备份与浏览器业务缓存 | macOS 个人版原生飞书 CLI／Keychain 登录 |
| — | Computer 的配置、凭证、状态、实例和卷；仍执行原有运行关闭协议 |

个人版清理后进入网页模型设置；多用户版使用保留的用户级网关凭据，沿用现有默认模型验证、初始化流程。凭据缺失或模型不可用时留在设置页，不恢复重置前的自选模型。模型就绪后由正常首次使用流程创建新默认助手，旧 Room／Membership／Session 不复用。

只处理 TeamX 内部数据，不调用 GitLab／飞书远端删除、登出或撤销授权。不包含账号注销、Space 永久删除、自动备份、回收站、外部项目清理和整套部署恢复出厂。已有部署备份、运维日志及系统快照不作历史擦除；本功能不新增旧业务备份，也不承诺磁盘底层安全擦除。

## 2. 设计收敛与现有接点

采用“**现有归档关闭 → 固定清单清理 → 初始业务配置 → 新实例**”。新增逻辑集中在 Space 控制面及存储边界，正常业务不感知重置。

| 现有代码 | 改动责任 |
| --- | --- |
| [space_lifecycle.go](../internal/room/space_lifecycle.go)、[runtime_shutdown.go](../internal/room/runtime_shutdown.go) | 复用撤销准入、停止及等待；不复制 Agent／Room／通知／OAuth 关闭协议 |
| [space_identity.go](../internal/room/space_identity.go)、[space_server.go](../internal/room/space_server.go) | SpaceRecord 保存一份操作记录，协调关闭、续跑和新实例装配 |
| [config_document.go](../internal/room/config_document.go)、[space_directory.go](../internal/room/space_directory.go)、[bundle.go](../internal/room/bundle.go) | 原子更新业务配置，提取已有初始化默认值和模板复制接点 |
| [server_setup.go](../internal/room/server_setup.go)、[model_defaults.go](../internal/room/model_defaults.go) | 复用个人网页设置、多用户默认模型初始化；补齐 setup 请求的运行实例校验 |
| [space_directory_claims.go](../internal/room/space_directory_claims.go) | 仅在结清后移除目标空间工作目录占用，保留 Computer 占用 |
| [space-context.mjs](../internal/web/assets/space-context.mjs)、[application.mjs](../internal/web/assets/application.mjs)、[access.mjs](../internal/web/assets/access.mjs) | 使用重置 request ID 识别缓存失效，复用现有请求取消及 epoch 校验 |

明确不增加：

- 独立 generation 计数、全量请求重置头、所有存储键的数据代次。
- 新的 Space 生命周期状态；继续使用 `active / archiving / suspended`。
- 动态可执行清理清单、逐文件回执、通用事务／迁移引擎。
- Agent、Session、Inbox、通知等组件各自的 reset 协议，或正常调度路径上的重置分支。
- macOS Keychain 归属识别、擦除和迁移系统。

保留必要的 owner 校验、持久阶段、停止后删除、失败重试和旧请求失效。当前空间管理 UI 开关仍关闭；重置从现有设置页提供，不以前置开放整个多空间管理界面为条件。

## 3. 清理规则

### 3.1 固定清单与保护路径

代码使用固定清单，按已登记 `Roots` 解析路径；客户端不能传入路径或删除项。实施时从当前持久 writer 核对清单，覆盖输入流存储及历史迁移副本。无需为每个文件登记进度。

| 位置 | 处理 |
| --- | --- |
| `Roots.Data` 的业务条目 | 清理 Room、默认工作目录、输入流、附件、通知、日历、索引、业务动作及操作回执；保留根和保护项 |
| Home 的 `model-credentials`、`model-validations`、`model-operations`、`model-setup.json` | 清理正式／候选密钥、验证与操作缓存 |
| 本空间模型／平台／通知迁移产生的前像、备份及临时产物 | 纳入清单清理；未结束 writer 先通过原流程结清 |
| `Roots.Teams` 的本空间模板和资源 | 清理后复制当前版本初始模板，不使用用户已修改的目录作默认种子 |
| Linux 空间私有 `platform-cli/lark` 及本空间临时目录 | 停止相关进程后完整清理，见第 3.3 节 |
| 外部指定工作目录 | 不删文件；完成关闭和清理后释放本空间引用及占用 |
| 浏览器草稿、会话位置、偏好和业务操作引用 | 按第 6 节清除 |

必须按实际解析位置保护：安装身份、个人／多用户登记、`users.json`、`spaces.json`、登录会话、管理员凭据、执行环境描述、服务应用、用户级网关凭据，以及 Computer 配置与文件。不能 `RemoveAll(Space.Home)`。

特别注意：[server_access.go](../internal/room/server_access.go) 的部分启动方式将 `installation-id` 放在 Data 根中；自定义 `access.admin_token_file` 也可能位于业务根内。保护对象的父目录不能整体删除，必要时清理兄弟条目。Home、Data、Teams 根和持锁文件保持原位；不得先删除锁 inode 再重建根。

预检检查规范路径、根与保护项的嵌套关系、其他空间及 Computer 保护路径。顶层路径被替换、符号链接、根重叠或未登记挂载导致无法安全清理时明确拒绝；嵌套链接只解除链接，不能跟随删除外部目标。Home 中无法确认归属的文件不猜测删除。

### 3.2 业务配置恢复

通过现有 `configDocument` 的串行写入、外部修改检查和持久确认，局部替换业务字段。重置目标由当前版本默认构造函数产生，不另建一套散落常量。

| 字段 | 处理 |
| --- | --- |
| `models`、旧 `runtime.model` | 空模型目录、无默认引用；移除旧模型，防止再次自动导入 |
| 时区、Session 回合阈值、合并窗口、模型回合超时、Inbox 保留／模式、图片材料设置 | 恢复当前版本首次使用默认值 |
| Data／Teams 位置、可选工作目录范围、监听、远程访问、代理、`access`、`deployment` | 保留，继续沿用原部署与资源边界 |
| `runtime.dsh` | 保留部署拥有的启动器、参数和产物约束 |
| `computer` | 原样保留 |
| `env` | 按现有消费位置固定分类；移除空间业务覆盖和旧模型密钥，保留已确认的部署／工具路径／Computer 依赖 |

无法分类的自定义 `env` 在删除前返回配置错误，由部署者先整理；不新增变量归属管理系统。宿主进程继承的环境不属于 Space 持久数据，重置不修改它。

模板来源复用发行包 `share/teamx/teams`；源码部署显式提供同等可信种子，缺失在删除前报错。成功候选仅保留上表中的部署／Computer 配置，不复制旧业务定义或秘密。

**重开时必须重新映射业务运行参数。** 当前 `assemble()` 从 `s.assembly.config` 复制 serviceConfig，不能仅重写 TOML：需在装配接点从重置后 startup 配置重新计算 `maxTurns`、超时、Inbox、图片等业务参数，同时保留部署装配值。复用现有参数转换，验证文件、内存及下次重启效果一致，不借此重构全部配置系统。

### 3.3 凭证：区分个人 macOS 与多用户 Linux

**macOS 个人版：** 清空 TeamX 的平台连接、绑定、验证证据、授权任务和空间私有文件；明确保留原生飞书 CLI profile／Keychain，不执行全局登出、不研究共享条目的归属，也不自动重绑。用户以后可显式使用已有账号。模型密钥、TeamX 本地 GitLab OAuth 等空间私有材料仍须清理。

**Linux 多用户版：** 必须清除目标 Space 持有的敏感材料，连接列表为空不等于完成。清理至少覆盖：

- GitLab access／refresh token、个人应用／导入候选、验证绑定及本地副本；当前连接快照位于 Data 下的 `platform-connections.json`。
- 飞书私有 config／data／profile 内的 Token、应用密钥、DPoP 材料、加密文件及主密钥，完整清理 `platform-cli/lark`，不只删 profile 引用。
- 空间模型 API Key、Session 内材料，以及迁移前像、候选、临时文件和备份中的敏感副本。
- 原关闭流程先等待 OAuth、refresh、工具及后代进程结束；删除后旧回调、旧进程不能重新写回。

当前 [storage.go](../internal/platform/lark/storage.go) 已按空间绑定 CLI 配置／数据；[原生 Linux 测试](../internal/platform/lark/storage_native_integration_test.go)检查独立主密钥和加密文件，但真实 OAuth／refresh／DPoP 的重置清理仍须另做验收。

临时目录也要覆盖。当前 [tool/process.go](../internal/platform/tool/process.go) 和飞书适配器使用系统临时目录，正常 defer 清理不足以覆盖崩溃。多用户路径中，将含业务／敏感材料的临时工作目录通过已有工厂或进程参数绑定到 Space 私有临时根，例如 `Home/platform-tmp`，一并清理；保留正常退出清理。不修改进程全局 TMPDIR，不扫描／删除所有用户的系统临时目录，也不建立通用临时文件管理服务。切换前的历史全局临时残留无法凭名称证明归属，应在上线前核对并作一次受控处置，未核实前不能声称完整清理已覆盖该旧环境。

保留系统登录、用户级网关凭据和部署级服务应用密钥，因其可能供其他 Space 使用；Space 重置不等于删除整名用户的服务器凭据。凭证处理只操作本地存储，不触发远端撤销。

## 4. 最小操作记录与可靠执行

### 4.1 记录与生命周期

只在 `SpaceRecord` 增加一个最新重置操作，由 `spaces.json` 与现有空间状态一起持久保存：

```text
reset: {
  format_version,
  request_id, expected_version,       // 原始请求；同 ID 重试不得改正文
  phase,                             // stopping | cleaning | initializing | completed
  code, message                      // 可选安全错误；失败保留原 phase
}
```

不新增 generation、独立 status 或逐文件 completed_steps。运行中的 busy 标识在内存中防重复 worker；重启依据持久 phase 续跑。最近的 `reset.request_id` 同时作为浏览器“空间曾被重置”的标识，受理后不清除。

空间状态仍表示业务是否可用，reset.phase 仅表示一次管理操作的进度：

| 时点 | Space 状态／操作阶段 |
| --- | --- |
| 活动空间受理重置 | 同一次持久提交 `archiving + stopping`，立即封闭业务 |
| 原已归档空间受理重置 | `suspended + stopping`，仍核验旧所有权结清 |
| 关闭与检查通过 | 同一次提交 `suspended + cleaning`，记录允许删除的事实 |
| 清理完成 | `suspended + initializing` |
| 初始化持久完成 | owner 可用且资源准入通过则 `active + completed` 并装配新实例；否则 `suspended + completed` 并说明原因 |

任何非 completed 操作阻止公共恢复、改名和再次重置。原归档后台任务与重置 worker 不能同时推进同一空间；复用内部关闭函数和唯一 owner，而非串接两个 HTTP 请求。状态查询优先展示 reset.phase 及错误，不把清理中的 suspended 显示成普通“可恢复归档”。

### 4.2 执行流程

1. **预检。** 校验真实 owner、空间版本、原操作状态、路径保护、模板种子、配置分类与操作格式。错误在停止和删除前返回。已有模型、OAuth 等受理任务不必全部预先空闲，后续统一关闭。
2. **持久受理并停止。** 原子保存上述状态和 request ID，撤销本空间准入、执行令牌及 SSE，取消原 entry。等待已准入 HTTP、setup、模型操作、通知、日历、OAuth／refresh、平台调用及 Agent／后代执行，复用 `settleSpace()`、`SpaceRuntime.Close()` 和 manager shutdown。超时留在 stopping，保留原 owner 及数据，重试继续等待。
3. **确认允许清理。** 结清后取得必要的 Home／Data 锁，核验路径和配置。已准入 writer 的正常最后提交纳入最终候选；外部修改按原冲突规则处理。准备并验证重置候选，持久进入 cleaning 后才可删除。
4. **固定清单清理。** 不存在视为已清理，失败留在 cleaning；重试从该阶段开头执行。删除及相关父目录同步确认后，持久进入 initializing。无需逐文件回执。
5. **初始化。** 局部发布候选配置、复制可信模板，复核清单内业务和敏感副本已清除，释放目标空间已结清的工作目录占用，保留 Computer 占用。操作幂等，不创建旧 Room，不联网重放业务。
6. **完成。** 清除敏感临时产物，在既有用户管理锁顺序下核验 owner，按现有资源准入检查决定能否重开，提交 completed 与相应空间状态，释放清理锁。可用 owner 且准入通过时创建全新的 runtime／manager／通知与模型对象及 epoch；用户停用或资源暂不可用时完成清理并保持挂起，显示原因，以后走原启用／恢复流程，不重复清理。完成不等待用户启用，避免与 `userSettled()` 相互等待。

候选配置若需暂存，放在删除目标外的私有操作目录，例如部署 Home 的 `space-reset/<space_id>/<request_id>/`，权限 0700／0600；它是受操作记录约束的产物，不是第二份状态权威。只保留重置后的候选，不复制原业务快照；完成前删除暂存秘密。持久记录不保存正文、Token 或完整配置。

磁盘操作、执行等待不持有 `spaceServer.mu`／部署身份锁。保留原锁 inode，清理期间保持必要的独占权限，重开前按原协议交接；不能通过改根目录绕过现有锁。部署关闭等待重置 worker 停在安全边界，再释放控制面所有权。

### 4.3 中断恢复与必要衔接

- **检查必须足够早。** [serve.go](../internal/room/serve.go) 当前先跑个人模型迁移；[space_server.go](../internal/room/space_server.go) 在启动普通 runtime 前恢复目录占用。须先识别未完成 reset，再决定是否运行迁移、旧索引扫描和业务初始化。清理中的空间不读取半清理业务重建占用；保留已有保守占用到初始化释放，其他空间正常装配。
- **stopping 重启不能跳过检查。** 没有旧 Go entry 不等于执行已结清，不能照搬归档的无 entry 快捷分支。利用既有后端／执行环境的 `CheckReset` 等检查确认持久 Session、进程、后代与 writer 已结束；证据不足保留 stopping 和数据并显示原因。本功能不新增孤儿进程修复或通用 Session 恢复系统。
- **cleaning／initializing 重启继续原阶段。** cleaning 已有允许删除的持久事实，不因部分 Session 文件已删除而重新要求它们存在。各阶段可重复，初始化不重新运行清理阶段。操作格式无法识别时保持封闭并报错，不增加跨版本清单迁移引擎。
- **持久结果不确定时先核对。** `ErrCommitUnknown` 不等于成功，封闭目标空间，按原 request 核对落盘状态后推进；不能换 ID、回滚成旧空间或猜测完成。初始化已完成但最终回执失败时，只确认并补完原操作。
- **用户停用优先阻止业务重开。** 内部停用流程可调用同一结清接点，但不能覆盖 reset.phase 或启动第二个关闭 worker。启动时的 disabled 空间归一化也不得抹掉未完成操作。completed 后停用空间保持 suspended，因而原用户启用检查可成立。
- **unknown 业务结果不等于未结清进程。** 本功能不联网核对已停止调用的远端结果；清理后不重放。仍有本地执行或写入所有权时始终禁止删除。
- **不自动回滚。** 受理后只重试同一次操作。正常升级／备份流程识别未完成重置，避免同根并发；不实现跨版本自动修复或单空间旧备份导入。

## 5. 页面与接口

在右侧设置面板底部提供“重置此空间”，确认框说明：

> 将清空此空间的聊天记录、Agent 上下文、附件、通知与待办、定时任务、规则、模型配置、平台连接和默认工作目录。指定的已有目录文件、Computer、系统登录及其他空间保留。此操作无法撤销。

macOS 个人版补一句“系统保存的飞书登录会保留”。无逐项勾选或清理强度选择。允许 owner 重置 active／suspended 空间，包括尚未设置模型或业务启动失败的空间；归档进行中先完成原操作。归档空间完成重置后会重新进入首次使用，确认时说明。

首次模型设置页、暂不可用页也可查询和重试重置，不依赖已清理的业务 manager。展示“正在停止任务 → 正在清理 → 正在初始化”；失败展示原因与重试。同一页面状态查询继续使用现有控制面，无需新增管理后台。

拟议接口：

```http
POST /v1/spaces/{space_id}/reset
Content-Type: application/json

{"request_id":"<opaque-id>","expected_version":12}
```

沿用真实 owner、same-origin 和控制面认证；Agent／执行凭据不能调用。首次接受返回 202 和操作投影；重复原请求查询／续跑同一操作，completed 返回 200。先匹配最新 request ID 与原 expected_version，再做首次受理版本检查，避免操作自己的版本递增使重试失败。同 ID 不同正文、未完成时不同 ID 均拒绝，不创建第二 worker。

`GET /v1/spaces` 返回 reset 投影及内存 busy。只保存最新操作回执；后续新重置覆盖它之后，旧请求因原 expected_version 过期被拒绝。Space version 不随业务清理归零，不新增历史幂等服务。

模型验证成功不是重置完成条件：清理、配置与 completed 已持久确认即可成功；接下来的模型初始化失败使用现有设置反馈。若新实例装配失败，显示“重置已完成，空间启动失败”，重试只重新装配，不能再次清理新状态。首版无需 CLI 重置命令。

## 6. 浏览器缓存与旧请求

复用持久 `reset.request_id`，不增加独立 generation。

- 页面配置、空间目录和 setup 状态返回 SpaceID／最近 reset ID。浏览器先读取身份与该标识，再恢复本地业务缓存；与本机上次标识不同，清除本空间草稿、位置、偏好、操作引用及内存状态后记录新标识。历史缓存没有标识而服务端有 reset ID 时，同样清除。
- 普通服务重启 reset ID 不变，继续保留原有草稿体验。默认 URL 与显式 `/s/<id>` 都按真实 SpaceID 定位，禁止 legacy fallback 把刚清掉的旧数据再次导入；setup 草稿也补齐 Space 作用域。无需给全部业务键附加代次。
- 更新集中在统一缓存恢复／清理入口；不清空整个 origin 的 storage，保留登录及其他空间。关闭或离线设备在下次访问时清理；重置成功不以所有设备在线为前提。
- 页面保留自己读取的 reset ID，不能只比较共享 storage 中的标识；其他标签更新共享标识后，旧页仍须丢弃自身内存和草稿。统一缓存写入口校验页面标识，已过期页面的 pagehide／迟到回调不再保存旧草稿；清理前先冻结旧页缓存写入，避免清完后又写回，也避免旧页清掉其他标签已初始化的新缓存。
- 原 ServiceEpoch／RuntimeEpoch／RoomIdentity 校验继续防止旧请求写新实例；审计现有写入口，仅补齐遗漏。特别是 `/v1/setup/model` 当前没有业务 epoch，应返回并校验已有 RuntimeEpoch，不能只依赖重置后可能重新从初始值开始的模型 version；覆盖普通管理写入、附件上传、迟到授权回调和 setup 提交。
- 前端复用请求取消、视图身份和读任务序号，发现 reset ID 变化后取消旧任务与 SSE，丢弃迟到结果并导航原 Space 初始化页；不将旧请求重新绑定到新 epoch 自动发送。不统一新增重置 HTTP 请求头，也不传播到 Agent 工具协议。
- 双标签通过现有重连／轮询发现变化即可，BroadcastChannel 不作为必要组件。未收到响应时保留原重置 request ID 和正文，只查询或重试同一次受理，不能自动生成新 ID。登录凭据保留，旧业务缓存失效。

## 7. 实施阶段与开发顺序

主要新增 `internal/room/space_reset*.go`，在上文接点作局部调整；固定清单与平台私有清理靠近对应存储 owner。不要先重构全部持久目录，不修改 turn 调度、输入流消费协议或正常 Session 自动恢复，不给这些正常路径增加重置分支。

按部署场景形成完整行为，不再按“后端 → 凭证 → 页面”分层交付。各阶段包含自身的入口、失败处理和验收；阶段 3 验证安装产物与真实组合，不能把凭证清理、旧请求隔离或关键恢复逻辑留到最后补做。

| 阶段 | 实施范围 | 完成出口 | 粗估 |
| --- | --- | --- | --- |
| **1. 个人版完整重置** | 操作记录、关闭与结清、固定清单、配置／模板初始化、启动前续跑及运行参数映射；页面确认／进度／重试、缓存清除和必要 epoch 校验；清理 TeamX 私有模型／平台凭证，保留原生 Keychain | 从页面发起，重置后重新配模型并真实对话；默认／新增／归档空间、重复提交、长任务、中断重启、旧页面及指定目录／Computer 保留通过。个人版形成完整可用行为，多用户入口尚不开放 | 4–6 人日 |
| **2. Linux 多用户完整重置** | 复用阶段 1，补齐 Linux 飞书私有存储、敏感临时根和副本清理；用户停用／启用、资源准入、共享应用和跨用户／空间隔离；接通多用户默认模型与对应页面反馈 | 两用户各两空间：目标敏感材料清除，其他空间继续运行；停用和重开失败无循环等待、无重复清理；必要真实 CLI／OAuth／refresh／DPoP 材料及默认模型路径通过，形成多用户闭环 | 2–4 人日 |
| **3. 安装交付验证** | 检查最终归档中的模板、CLI、运行依赖；验证所选组合的新装／升级、服务账号、权限和正式启动方式，运行一次重置冒烟并留存摘要与结果 | 同一最终产物的安装路径与重置冒烟通过；阶段 1／2 已验证功能不重复，所发现实现遗漏回补原阶段；正式发行沿用已有前置 | 0.5–1 人日 |

### 7.1 阶段 1 的内部任务顺序

阶段 1 工作量最大，内部按下列小任务连续实施，不再把它们列成可独立宣称交付的“底座阶段”：

1. 固定清单、保护路径、个人平台凭证边界、配置默认值及装配参数映射。
2. 最小操作记录、现有关闭流程衔接、阶段重试、启动前恢复与控制面 API。
3. 页面确认／进度／重试、reset ID 缓存清理、setup 等遗漏入口的 epoch 校验，以及个人版完整验收。

上述任务各做对应测试，阶段出口再验证完整链路。私有密钥清理、停止超时不删除、中断续跑和旧请求拒绝属于阶段 1 必须项，不能因为没有公开按钮而延后到阶段 2／3。阶段 1 仅对个人模式声明支持，多用户 API 在修改任何状态前拒绝；不能只隐藏前端按钮。

### 7.2 阶段边界与开放条件

- 阶段 1 完成后，个人版可在其已验收环境中完整使用，不依赖 Linux 多用户清理完成；发行安装组合仍须通过阶段 3 对应部分。
- 阶段 2 复用阶段 1 的同一控制面、操作记录与前端，只增加多用户部署特有行为。多用户入口在私有凭证、副本及隔离验证通过前保持关闭；现有多用户部署组合前置门槛继续生效。
- 各阶段自行覆盖其长任务、停止超时、清理失败、进程／服务重启和迟到请求。阶段 2 的真实凭证验证不能全部留给阶段 3；环境或授权材料不足时记录未完成出口，不用合成凭证测试替代。
- 阶段 3 只关闭最终包资源、新装／升级、正式启动与一次重置冒烟的交付证据缺口。阶段 1／2 已验证的凭证、模型、浏览器和恢复矩阵不重复执行；真实双账号 SSO／强制 refresh 竞态若属于重置必要证明，应列为原阶段缺口，不转成新的交付测试。发现实现遗漏需回补原阶段并重建产物；正式发行仍沿用既有前置。
- 各组合按自己的出口判断，个人版发布不必等待未选择的多用户组合；对外不开放只清理部分数据的按钮。新测试按行为命名，不按临时阶段编号。

收敛后功能实现复杂度中等，完整异常及跨部署验收中等偏高。三阶段工程粗估合计约为 **7–11 人日**，主要不确定性是旧存储副本与 Linux 历史临时目录核对；不计 macOS Keychain 擦除、通用 generation 或清理引擎。

## 8. 验收矩阵

仅在新建临时 Home／Space 和私有证据目录验证，不操作日常数据。源码核对、夹具、真实 CLI／DSH／模型及浏览器证据分别记录。

下表按部署范围归属：个人场景在阶段 1 完成，多用户增量在阶段 2 完成；通用的配置、关闭、故障、路径和浏览器要求随对应场景一起验证。阶段 3 在所选安装组合复核这些已完成行为，不承担第一次验证关键可靠性的职责。

| 场景 | 必须证明 |
| --- | --- |
| 个人默认空间／新增空间 | 业务、默认目录、私有密钥与模板按规则恢复；身份、登录、其他 Space、Computer、外部项目保留；重启后仍可进入模型设置 |
| 配置一致 | 时区、Session 阈值、超时、Inbox／图片等在配置文件、新运行对象及再次重启后一致；Data 内 installation-id、自定义管理员凭据位置受保护 |
| Linux 两用户各两空间 | 仅 owner 可重置；目标 Space Token、refresh、飞书主密钥／加密材料、模型密钥和临时／迁移副本清除；其他 grant、SSE、后台任务不受影响 |
| macOS 原生飞书 | TeamX 连接清空、不自动重绑；原生 profile／Keychain 未登出或误删；TeamX 私有模型／GitLab 凭证仍清除 |
| 长任务与旧回调 | Agent、工具、模型验证、OAuth／refresh、通知先结清；超时不删，原 owner 重试；迟到回调／进程不能写回 |
| 故障与中断 | 受理、关闭、清理中途、配置提交、模板复制和最终发布前后故障；按同 request／阶段重启恢复，无二次 worker、业务重放或半清理开放 |
| 用户停用与启用／资源准入 | 停用或资源暂不可用时可完成清理并挂起，之后能正常启用／恢复，无循环等待；重开失败不再次清理 |
| 路径与锁 | 自定义根、链接、替换路径、保护项嵌套、锁竞争；外部文件校验值不变，根和锁不被替换 |
| 浏览器与请求 | 默认／显式 URL、双标签、离线后访问、刷新、迟到响应；重置清缓存，普通重启保留草稿；旧 setup／上传／业务写入拒绝 |
| 再次使用 | 个人重新配模型及新默认助手真实对话；多用户默认模型初始化或明确失败；不恢复旧 Room／通知／规则，不创建第二 Space |

正常 Go／前端回归及定向 race 覆盖受影响接点，运行文档与代码差异检查；真实模型、浏览器和 Linux 凭证验收显式执行，不加入普通 CI。Linux 原生 CLI 的合成凭证存储测试不等于真实 OAuth／refresh／DPoP 清理通过。

**开放条件按部署组合判断：** 个人版要求阶段 1 的固定清单、私有凭证清理、结清、重试及旧请求拒绝通过；Linux 多用户版在此基础上还须通过阶段 2 的敏感材料清除、用户生命周期和隔离要求。正式发行另需阶段 3 对应安装组合通过，不要求所有可选组合同时完成。凭证或副本删除失败必须保留未完成操作和错误，不能只清连接记录就显示成功；已完成后仅重试业务装配。保留的用户级／部署级秘密和个人原生 Keychain 依照第 1 节边界验收。
