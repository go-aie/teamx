## 复跑

要求 Python 3.11+、Go、可用 Docker daemon，以及与宿主架构匹配的固定版本 DSH/Node。此次使用 macOS ARM64、Node 24.22.2 和仓库部署锁中的 DSH 0.2.2-rc.1。不能使用本工作区 `teamx-space` 中的 Linux 二进制或原生依赖。

准备运行时（目录仅供本次验收使用）：

```sh
mkdir -p .local/agent-sandbox/dsh-darwin
cp packaging/dsh/package.json packaging/dsh/package-lock.json .local/agent-sandbox/dsh-darwin/
# 使用 Node 24.22.2 自带的 npm；忽略生命周期脚本，保持仓库锁文件不变。
/path/to/node-24/bin/node /path/to/node-24/lib/node_modules/npm/bin/npm-cli.js ci \
  --prefix .local/agent-sandbox/dsh-darwin \
  --omit=dev --ignore-scripts --no-audit --no-fund
/path/to/node-24/bin/node scripts/check-dsh-native.mjs .local/agent-sandbox/dsh-darwin
```

拉取固定镜像后运行。`--model` 是现有模型目录中的显式条目 ID，配置及对应托管凭据只读；密钥只通过子进程环境和 MCP Header 传递，不写入验收配置或命令参数。

```sh
docker pull enterprise-public-cn-beijing.cr.volces.com/vefaas-public/all-in-one-sandbox@sha256:5ca2cd5619ee1e18c5479301e740c1e35307ce85d4142a145aec65d459655eee
docker pull nginx@sha256:901e593c95dc85f5a729f5765516321366ef4ac401821431d408897e95287d0a

python3 scripts/agent_sandbox_acceptance.py \
  --config .teamx/config.toml --model daily \
  --dsh-node /absolute/path/to/node-24/bin/node \
  --dsh-cli .local/agent-sandbox/dsh-darwin/node_modules/@deepseek-ai/dsh/lib/bin.js \
  --output .local/agent-sandbox/new-run \
  --seccomp-unconfined
```

输出目录必须不存在，禁止复用旧 Session。默认任务间隔 65 秒，为当前模型服务留出配额窗口；`--task-interval` 可显式调整，但失败请求不会自动重放。容器启动最多等待 120 秒，单回合最多 4 分钟，DSH 验收总上下文 25 分钟，外层测试还有硬期限。Ctrl-C/SIGTERM 通过取消标记通知 Go 入口，保留 ACP 取消和本地进程树结清；随后核验并删除测试容器及网络。强制杀死宿主程序或 Docker 失联时不能保证自动清理，必须根据报告中的容器 ID 核验，不能复用未结清环境。

## 实际部署边界

- AIO 限制为 2 CPU、3 GiB 内存（禁止额外 swap）、512 个 PID、512 MiB 共享内存，无宿主目录和 Docker socket 挂载。独立 internal 网络禁止浏览器直接外连；单独 nginx 代理仅将宿主 `127.0.0.1` 端口转给 AIO。代理只挂载生成的只读 nginx 配置，限制为 0.25 CPU、64 MiB 内存、64 个 PID。
- Docker Desktop 的 overlayfs 不提供本次可用的独立容器磁盘配额；脚本检查至少 8 GiB 可用空间，以专用容器和总期限约束测试。这不是生产磁盘隔离验收。
- 默认 seccomp 实测使 Chromium 报 `Failed to move to new namespace ... Operation not permitted`。本次显式使用上游示例中的 `seccomp=unconfined`，不能据此宣称适合不可信多租户执行。
- 镜像实际支持 `SANDBOX_API_KEY` 和 Bearer Header。本次核验 API、MCP、CDP、VNC、Jupyter 的无凭据拒绝，以及 CDP/VNC WebSocket 的无凭据拒绝、有凭据升级；未评估 JWT、ticket 或完整镜像安全性。
- Hub 原始列表含 32 个工具，`--filter-mcp-servers browser` 不会移除内置 Shell/代码/文件工具。因此仅在测试容器中，将已有 nginx `/mcp` 上游由 Hub `:8091` 改为镜像自带 browser MCP `:8100`，保留外层认证。最终实际发现 21 个 browser 工具，未转换 Schema 或结果，也未建设 TeamX Sandbox 适配层。

固定镜像对应上游 [1.11.0 启动说明](https://github.com/agent-infra/sandbox/blob/7f1afaf8d82bd30531a19caeb1a24dfebbc97d8c/README.md)；其文档示例工具名不足以替代实际发现。工具清单、Schema 字节数和摘要随机器证据归档。

## 证据判定

三个独立随机页面分别包含异步加载值、链接、输入框、服务端校验和跳转、固定下载内容，以及仅包含像素的八位数字 PNG。预期值保存在验收目录及容器内验证服务目录，不进入提示或 DSH Workspace。验证服务只提供受控路由。

每轮同时核对模型准确汇报动态值和最终回执、服务端收到正确输入及完成页请求、浏览器下载请求、AIO `/home/gem/Downloads` 中实际文件的名称/大小/SHA-256、ACP 工具轨迹及正常回合终态。仅模型自述、仅服务端下载请求或仅错误目录中的同名文件均不足以通过。

模型截图工具与验收程序的独立页面截图分别留证。视觉结论依赖实际 MCP 截图调用、DSH 图片附件及模型正确识别未出现在提示/DOM/工具文本中的随机像素数字；没有抓取模型供应商请求包。文本模型可以只通过文本/DOM 路线，不能标成视觉通过。

远端浏览器调用不使用宿主 DSH PID 证明停止。结束时必须通过 Docker 核验 AIO `Running=false`、`Pid=0`，再移除 AIO、代理及专用网络。浏览器工具没有为本次每个调用提供通用任务归属/停止账本；本阶段采用专属整容器停止，不开放日常远程 Shell 或后台任务。

最终结果、失败记录、资源数据和 S2 建议见同目录机器证据。原始 ACP 记录、容器日志、截图及下载留在 `.local/agent-sandbox/`，仅提交合成测试材料和脱敏摘要。
