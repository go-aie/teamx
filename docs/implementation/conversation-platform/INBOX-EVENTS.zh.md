# 对话式平台接入：Inbox 类型扩展实施记录

日期：2026-11-11。对应方案 C4。实现和证据限于本地服务、Inbox／成员 Actor、HTTP／CLI 与模拟 DOM；没有接入真实连接操作的事件生产者，也不代表飞书／模型 Agent 自动接续验收通过。后续 C5 的操作结果订阅、待投递恢复及 Skill 异步策略见[异步自动接续实施记录](ASYNC-CONTINUATION.zh.md)。

## 已交付

- Inbox 使用封闭的 `platform_notification`／`task_event` 两类信封。平台条目保留原 `notification.Item`；内部条目只携带事件 ID、操作 ID／结果版本、原请求序号、事件类型、结果引用和时间。载荷互斥，未知类型拒绝；历史无 `type` 字段的条目仍按原平台消息校验和读取，不迁移或清空队列，平台交付摘要算法不变。
- `inbox_payload.go` 集中提供类型、载荷校验、交付元数据和消费关联分派；准入、投影和回收使用相同的封闭类型边界。内部事件不创建外部来源、账号、订阅或普通跟进事项，不进入远端引用解析、消息来源归因或图片材料处理。
- Agent 和人类预览显式输出 `type`，内部事件不附带虚构的 `item`、`source` 或平台设置入口。UI 展示事件类别、操作／结果引用、原请求和时间，并说明消费不代表原需求完成。CLI 帮助和 Agent 指南说明按最新操作结果及用户意图接续，已处理步骤跳过。
- 新增私有服务入口 `receiveTaskEvent`，仅由服务内测试生产者调用。没有新增公开事件发布 HTTP／CLI 接口，也没有为连接操作启用订阅或自动发送事件。

## 持久化与恢复

Inbox 沿用原 `inboxes/<membership>/` 不可变条目、批次及 `consumption.json`。内部事件的最小记录位于 `agents/<membership>/task-events/`：

| 目录 | 保存的事实 |
| --- | --- |
| `events/` | 绑定完整 Room／Agent／Membership 的不可变事件及本地结果引用 |
| `deliveries/` | 稳定 DeliveryID、载荷摘要及原 Inbox 序号；正文回收后继续去重 |
| `links/` | Inbox 序号与事件／操作结果的消费关联及关联时间 |

服务先保存事件，Inbox 再保存正文、交付回执及序号检查点，全部完成后才返回成功。正文已经落盘而后续写入中断时，沿用 Store 的 `commit_unknown` 写入冻结；重开时由同一正文补齐交付回执，禁止生成新序号掩盖未知结果。相同成员、事件 ID 和载荷返回原回执；改变载荷冲突。actor 回调只读已加载的回执索引，文件读写保留在受管理任务及 Store 锁内。

读取固定批次后，平台条目保存原 followup 关联，内部条目保存本地事件关联，然后才允许确认同一页。确认失败或响应不确定时，原批次／页回执和关联可恢复，不重复创建跟进或完成业务。预览不创建关联或推进消费。重开时校验已消费条目和回收后的事件／交付／关联记录；缺失或错误身份的证据报错，不能重置游标。

容量检查仍只计算保留的 Inbox 条目。容量不足时，已保存的事件结果引用保留，测试生产者用同一事件重试；C4 不实现 C5 的自动待投递管理。必要的事件及去重／关联回执保留在队列之外，不复制凭据或授权会话。

## 准入、调度与回收

- 内部事件只接受已保存、完整成员身份匹配的本地记录；平台条目仍沿用现有来源核验和准入。外部通知核验受阻时，事件不能越过它确认页或推进共享游标；没有只放宽 `AutomaticBlocked`。
- 两类条目共享序号、固定快照、分页回执和前缀回收边界。沿用 Room／Inbox 两种回合输入、成员暂停、预算、公平调度和失败恢复；没有新增调度类型分支。
- 平台通知的过期跳过只适用于平台条目。未消费的内部事件始终保留；消费且关联持久化后，按独立的固定保留期回收 Inbox 正文：关联时间起 7 天。长期群关注或跟进是否结束不参与回收判断。
- 活跃回合及未结清批次仍阻止物理清理；前方尚未到期的条目会阻止后方正文回收，不新增独立游标。内部去重回执在正文回收及重开后仍有效，同名替换成员无法接收或继承旧事件。

## 验证

```sh
go test ./... -timeout=4m
go test -race ./internal/room \
  -run 'Test(AgentInbox|Inbox(MixedPayload|TaskEvent|PayloadLegacy|Consumption|Scheduling|Admission|Lifecycle))' \
  -count=1
go test -race -tags=integration ./internal/room \
  -run '^Test(AgentInbox|Inbox|AgentInboxReadProjection|ReferenceFollowups)' \
  -count=1 -timeout=4m
node --test --test-reporter=dot internal/web/tests/web_*test.mjs
git diff --check
```

覆盖：混合读取／分页和 Agent／人类投影；旧格式及错误类型；CLI 预览、完整输出确认和短输出不确认；交付正文／回执／检查点与消费关联／确认写入中断；缺失证据拒绝恢复；已消费正文回收及回收后的去重；内部事件不受平台过期跳过；共享前缀、准入阻塞、容量不足、成员替换；平台及混合队列的暂停／预算／公平调度回归。

结果：全仓普通 Go 测试、核心 Inbox race 回归、带 `integration` 标签的 Inbox／引用回归均通过；最后补充的三类事件 CLI 投影、回收中断恢复和容量释放后按原事件重试也通过定向 race。前端全部 375 项通过，`git diff --check` 及新增文件空白检查通过。新调度测试最初遇到 Room 提交时的正常 `ErrBusy`；测试生产者改为保留相同事件并有界重试后，race 回归通过，未修改调度或准入规则。

模拟 DOM 检查覆盖混合展示、未知类型不进入平台渲染、无平台控件、刷新保留节点和展开状态。它不能代替真实浏览器视觉验收；真实操作结果订阅及无新聊天时自动继续，按 C5 验收。
