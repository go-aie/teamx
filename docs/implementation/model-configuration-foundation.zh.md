# 模型配置与验证基础

2026-11-12 完成[模型配置方案](../MODEL-CONFIGURATION-AND-LIVE-APPLY-PLAN.zh.md)阶段 1。新能力通过内部调用、组件测试及隔离 home 验证，当时尚未开放管理写接口或网页入口；阶段 2 已接入全新 home 的网页设置与运行，见[首次使用闭环记录](model-first-use.zh.md)。

## 已实施

- `models.go` 定义模型列表、稳定条目 ID、列表 version、执行 revision、默认／固定引用，以及按完整成员身份计算的影响范围。改名、相同配置与相同 Key 不改变执行 revision；相同 Key 可复用不可变凭据引用。管理参数不包含 `api_key_env`。
- `model_credentials.go` 将 Key 保存到 home 下私有目录：目录 `0700`、文件 `0600`。已发布版本保守保留，失败候选清理。进程环境仅用于旧配置读取；新执行显式绑定 Key，宿主同名旧值或空值不覆盖绑定。
- `config_document.go` 提取时区设置已有的来源检查、文件锁、临时写入、原子替换、持久性复核与内存发布。模型保存和时区修改共用该实例；首次设置／认证的配置写入也复用底层机制并继续强制 `0600`。探测不持有配置锁，提交前重查版本。
- `models_config.go` 局部替换 TOML 的 `models` 表达式，保留其他字段及注释；支持普通表、数组表、引号键、点分键、内联表，以及其他字段中的多行字符串。`supports_developer_role` 的省略／false／true 经 TOML、JSON 与重载保持三态，其他协议拒绝该项。
- `managedMember` 与团队成员定义加入可选模型引用；旧记录的缺省值仍表示尚未迁移。内部初始化可保存模板显式引用；当前生产模板加载明确阻断该字段，避免提前接受引用后仍运行旧模型。未增加已有成员的在线改选入口。
- `model_session.go` 保存每个 generation 的不可变执行快照：完整成员身份、选择及版本、条目 revision、凭据引用、模型参数、Backend profile 和实际 DSH 身份。恢复读取原 generation，拒绝用最新列表覆盖；模型 Key 和执行 token 不进入快照。

关键实现路径：

1. `dsh.Probe` 使用生产模型适配器，在独立 home 和空工作目录中运行文本及固定工具探测。托管 DSH 的 Agent scope 禁止全部全局工具，仅注册无副作用的 `teamx_probe`；ACP Session 创建依赖隔离插件就绪。探测不继承业务凭据或管理认证，不注册业务工具、绑定 Room 或推进游标。工具返回随机回执，必须观察到完成及模型复述；仅有工具名称或文本应答不算成功。
2. 探测限制并发、请求步数、工具次数、输出和总时间，并预留清理预算。成功要求进程结清；清理未完成不发布候选。验证回执绑定执行配置、凭据版本及 DSH 身份，只作诊断，后续操作不能据此跳过新探测。图片能力只记录声明，未将文本通过写成图片实测通过。
3. 既有 rotation 增加内部模型目标，沿用 `prepared → old_closed → completed`。模型路径只冻结新 turn，当前执行结束后才启动平台结清，随后关闭旧 Session、保存固定目标并安装新 Backend。保留启用意图和期间新增的暂停；更新本身不额外调用模型。手动取消仍保留原语义。

模型目标只由内部调用构造，没有新增临时 HTTP／Agent 权限入口。正式在线发布、成员应用协调和完整故障恢复属于阶段 3，不能把本阶段原型当成已交付的在线管理功能。

## 迁移规则已确定

阶段 4 才执行一次有备份、固定目标、可重试进度的迁移，本阶段不写入现有部署数据：

- 旧全局模型成为默认条目；房间／模板按完整执行参数和实际有效 Key 比较，相同者转换为默认模式，不同者去重成为额外条目和固定引用。这是新规则，不推断旧系统曾保存跟随意图。
- 旧变量按“进程环境优先于 `[env]`”读取，包括显式空值；变量名不同不代表凭据不同。缺失 Key 不算有效凭据，不能据此合并或伪造验证成功。
- 兼容项保留三态，未指定不补 false；旧 Session 的变量名、参数、指纹及历史目录保持原样。后续新 Session 才使用内部变量名和托管凭据。
- 迁移完成后移除旧生效来源，不长期双重解析。当前启动入口拒绝直接运行新 `models` 配置；内部模型服务也拒绝已有旧模型或 Room 数据，防止提前开放未验收的写能力。
