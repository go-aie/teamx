# Lark 配置族编译 CLI 夹具

2026-11-24，实施测试改造方案 §11.4 的 F2 首族：`tools_lark_configuration_test.go` 与共用配置夹具的直接、间接调用方。只改测试夹具、测试和记录；生产 Client、环境白名单、账号 pinning、进程组取消、授权与持久化保持原路径。

## 路线与覆盖承接

先探测已有 Room 测试二进制 helper：20 次空调用的启动中位约 13.7 ms，Python `-S` 加载 JSON 约 24.4 ms，小型 Go 空程序预热后约 4.3 ms。小程序首次启动及构建仍有额外成本，不能只比较预热中位。这些只是路线筛选探测，不代表完整原生协议成本。本轮选择每套测试进程只构建一次的小型 Go CLI；没有同时维护该配置族的 Python／Go 两套协议。

可执行源文件位于 `internal/room/testdata/lark_configuration_cli/main.go`，不依赖 TeamX 业务包。构建由 `sync.Once` 共享，TestMain 在全部测试和子进程结清后清理。每个夹具拥有自己的启动包装、JSON、消息材料、门闩和调用日志；包装使用 `exec`，通过私有 argv 传递目录，正式 Client 仍负责 profile 参数、cwd、环境、输出上限和进程组。

| 原场景／注入方式 | 当前承接 | 保留的实际边界 |
| --- | --- | --- |
| 配置脚本中的 version／whoami／config／scope／renewal 响应 | 配置族首次注册核验即使用编译 CLI；原 application／missing scopes JSON 继续按每次调用读取 | HTTP、member、onboarding、原生 TeamX CLI 与真实配置回执原断言保留；auth check 缺权仍返回原生退出码 1 |
| self 证据测试通过替换成员和租户字符串改变响应 | 私有 `native-fixture.json` 的 `Self` 字段 | 生产原生目标验证、伪造证据拒绝、旧证明刷新与持久版本匹配 |
| 并发权限缺口测试插入 Python 阻塞循环 | `Gate=permission` 和原 `permission-ready`／`permission-release` 文件 | 在真实远程读取尚未结束时修改原目标／兄弟目标，仍复核 ABA、撤权与回执投影 |
| 原生协议与错误分类 | 新增 `TestLarkConfigurationNativeProtocolAndFailures` | 生产 Verify 的完整 argv/profile/cwd、版本／身份不匹配、畸形响应、非零退出、stdout／stderr 上限、错误文本隔离，以及拒绝原生写命令 |
| 已核验账号在下一次读取中发生变化 | 新增 `TestLarkConfigurationNativeIdentityChanges`；原生 user_info 返回后改变身份 | 最后一次真实 whoami 拒绝晚到身份变化；后续读取不能沿用缓存身份 |
| 阻塞调用与继承管道的子进程 | 新增 `TestLarkConfigurationNativeCancellation` | 生产 Client 取消真实 OS 进程组，父子 PID 均退出，读取返回且 profile 锁可再次使用 |
| 保存失败、未知提交、关闭重开、独立版本和并发目标 | 原有完整测试继续使用真实 Store／manager／Room | 未删恢复矩阵，未以返回值模拟持久成功，也未减少原生调用 |

被迁移的配置 Python 分支与两处字符串改写已移除。`larkFixtureScript` 仍只服务未迁移的通知／self-send／图片等族；它们的协议没有重写，仅复用原有账号注册和核验组件。独立重开测试仍读取原夹具私有目录中的同一 CLI／材料。真实平台、模型和浏览器未在本轮执行。

## 测量与验证

环境：macOS ARM64、Go 1.27.1，HEAD `479e79f35157cf15b8f60c793a7840b59d07647c` 加原有工作树。按当前 helper 引用关系提取 13 份文件、84 项原有顶层测试，包含共用调用方和 integration；改后另纳入上述 3 项检查。没有删除／移动原测试或调整四槽策略。

计时使用预先编译的测试二进制，从 `internal/room` 执行 `go tool test2json -t` 与 `-test.count=1 -test.timeout=6m`。Room 测试二进制编译不计入执行对照；整族墙钟包含一次小型 CLI 构建、首次启动、原生 TeamX CLI 构建、执行和清理。对照期间不并跑编译、race 或其他检查。原 Python 二进制只增加同格式的测试调用／分段观察，不改变原协议和断言；这部分临时计数没有留在未迁移的 Python 夹具中。

构建时间单独输出；每个配置夹具记录 setup、target、cleanup 与 CLI starts/exits。setup 从开始装配到夹具返回；target 到该夹具的收尾观察点，包含稍后注册的测试收尾；cleanup 是观察点后的组件关闭、日志统计及私有目录清理。测试体内的显式关闭／重开计入 target，多个夹具嵌套的跨度也可能重叠。native 时间只是程序入口后的处理跨度，排除解释器／Go runtime 启动，可能含受控门闩等待；它不等于原生进程完整墙钟。并行 fixture 的累计时间有重叠，不能相加作为整族执行时间。原有场景共 78 个配置夹具、2,083 次 CLI 启动，其中一次受控取消没有正常 exit 日志；新增协议检查另计，不能遗漏后冒充总数下降。

原有夹具的累计 setup／target／cleanup 为第一对 64.391／86.567／2.070 → 73.753／55.817／2.569 秒，第二对 69.474／106.932／2.135 → 75.250／46.298／2.524 秒。target 工作明显减少，但装配变重且有波动，不能把 target 累计差值当作墙钟提速，也没有证据将波动归因于某个宿主因素。分段保留在机器证据中，不据此继续扩大四槽或削减正式文件同步。

构建复用探测采用同一已编译 Room 二进制，显式选择 `^TestLarkToolConfiguration`、`-test.count=2`。两轮首个 run 到最后一个顶层 pass 的跨度为 8.942／7.112 秒，单次构建 0.816 秒，只出现在首轮。它给出完整配置文件在复用后的实际执行观察，排除包启动／最终退出，不是另一组 84 项整族计时，差值也不能全部归因于构建。
