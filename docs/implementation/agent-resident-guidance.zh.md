# Agent 常驻流程收敛

2026-11-21，实施 [Agent 上下文简化分析](../AGENT-CONTEXT-SIMPLIFICATION-ANALYSIS.zh.md) 的 **S1d**。本次只调整公共指南和已有按需资源，复用原 CLI、HTTP、动作账本、配置指纹与 Session 生命周期。

**状态：候选实现已落地，组件／集成验证通过；URL 真实模型的成本验收未闭合，尚未满足完整采用条件。**

## 交付边界

公共指南不再展开通知短命令、选择卡片创建与异步确认、飞书授权修复的操作步骤。按任务直接读取已有入口：

| 触发条件 | 入口 |
| --- | --- |
| 当前成员通知总开关 | `platforms skill --topic notifications` |
| 明确要求账号／群／项目卡片，或 selection 结果事件 | `platforms skill --topic selection` |
| 连接、授权、来源／工具定制、修复，或 connect 结果事件 | `platforms skill` |
| GitLab MR 文本／图文评论、准确讨论回复，需要发送指导 | `tools skill ENTRY --topic managed-send` |
| 开发、评审、合并等其他已声明工作流 | `tools skill ENTRY` |

以上命令均通过 `"$TEAMX_CLI"` 调用。已有指导直接复用，不先读目录／全文选 topic。已有目标和合同能恢复原账号时，不为重新加载指导发现 ENTRY；准确 ENTRY 未知时可按原合同省略 `--tool`。

常驻保留身份与成员作用域、人类意图和最新撤销、全部适用规则、正式 Inbox 与只读 History 的区别、准确账号／目标、完整内容、稳定 ID、unknown 原回执恢复、持久进展和消息格式。无账号／无 Skill 工具保持原入口，不增设平台、Workspace 或 Skill 前置。Calendar、输入消费、History 分页、DSH 内部协作及角色内容均未改动。

平台完整指南和两个 topic 的共用边界明确：操作结果不能复活已撤销的意图。GitLab 完整指南和发送 topic 同步明确：已有合同与指导不应引入 ENTRY 发现或 Skill 重读。通知短路径、卡片 handled/result_version、60 秒能力观察和各类修复、图文授权及 unknown 合同原已在对应资源中保留，不新增补读层。

## 大小与验证

度量、同输入模型对照和失败样本见[脱敏证据](agent-resident-guidance-evidence.json)。固定交付沿正常 `OpenSession → PrepareOpen → Launch.Instructions → 所选工厂` 验证，覆盖默认助理、保存的自定义角色及 legacy／CLI／HTTP 输入合同。

在两侧均保留同期新增的 Workspace 文件链接指导后，公共源指南从 15,896 降至 14,507 UTF-8 字节；默认助理的 HTTP 最终 Instructions 从 23,771 降至 22,382 字节（减少 1,389，约 5.8%）。初始模型基线采于该 137 字节的并行指导加入之前，实际 Instructions 和源文件大小分别保留在证据中；没有覆盖这条无关改动。按需资源补充的边界计入总量，不把下沉后的资源大小忽略；具体单任务及完整轨迹比较见证据。未采集模型实际 token／缓存费用，不据字节数推算统计可靠性、耗时或费用收益。

行为验证复用真实 DSH、当前模型和产品默认助理；平台 HTTP／CLI 为本地 fixture，选择卡片由真实 Chromium 提交，采集器不启动。GitLab 场景覆盖完整 URL、既有目标／合同、图文与文本、未知回执、重启、取消和最新人类撤销；后者将真实发送请求与其后撤销先保存，再恢复调度，要求读取后不 resolve／execute。已知合同的连续发送禁止新增 ENTRY 发现或 Skill 重读；unknown 后查询原 ID 属于允许的核实，不误算成发送前置。

定向 `integration -race` 中其他 63 个顶层用例通过；新增资源断言的 fixture 修正后，工厂交付和资源合同两项定向 race 检查通过；最终工作树上的四项工厂／资源／绑定检查也通过 race。轮换／帮助／恢复的 9 项定向检查、工具包和命令观察器检查也通过；不把这些结果表述为整仓全量通过。

## URL 验收未闭合与归因

改后 URL 采样分别出现报告 shell 引号错误、任务禁止的 `ls`、猜测不存在的 `comment_mr` 工具入口，以及先读全文再读 topic。首次托管发送在部分样本中已成功，但成本／约束检查失败，不能计为完整通过。GitLab 设置另一次模型 HTTP 429 已在结清和等待后复采通过。所有失败均保留在证据中。

审查猜入口样本时发现，S1d 首版确实将原先明确的“不要猜 ENTRY”弱化为“缺失时发现”和“不猜 provider 别名”。最终已恢复原来的明确约束，并加入最终工厂交付检查；复验仍出现先读全文再读 topic，因此没有把恢复一句话当作验收通过。

为判断归因，另外以当前代码和相同 Workspace 链接指导运行旧指南对照。旧指南也在已知目标上补做工具发现，未通过同一成本门槛；此前 B2 记录已有无关 `ls`，本轮改前还出现 JSON 参数修正。由此不能认定引号／目录查看等偏差是 S1d 新增，也不能排除上下文调整的间接影响。该缺口按实际结果保留，不通过删检查、改任务、扩大后端／工具改造或仅挑一次成功来闭合。

最终仍待证明：完整 URL 发送和后续已知目标复用，在当前模型下直接读取一次 topic、没有全文前置／猜入口／重复发现，并完成 unknown 原 ID 恢复。现有已通过的 URL CLI／服务合同和其他业务矩阵不能替代这项真实模型成本验收。
