## 代码与交付

成员外部 MCP 文件加载、服务器列表注入、裸 environment 代理及仅服务旧通道的浏览器夹具已移除。`server.agent_mcp_file` 暂留一个拒绝解析的迁移标记，存在即返回不含字段值的明确错误，空字符串也不例外。通用 Agent／DSH MCP 声明继续供内置 TeamX MCP 使用。观看与接管只通过受管成员 screen，接管事件、输入退出、身份和读取确认断言迁至正式路径。

[现行使用说明](../../agent-mcp.zh.md)、[会话帮助](../../conversations.zh.md#电脑)和 [AIO 部署说明](../../../packaging/computer/aio/README.zh.md)统一采用全局设置与成员开关；旧试验接入记录标记为历史版本，截图交付补丁移至历史记录目录，不再作为部署脚本提供，也不属于首版能力。

`scripts/package_computer.py` 独立生成静态 linux/amd64 Runtime 构建归档及 SHA-256，包含固定 AIO 依赖／工具锁、Dockerfile、二进制和源码摘要。不需要运行 Docker，不更改普通 TeamX 发布矩阵或增加启动依赖。实际归档的构建记录和打包清单检查保留；日常 Runtime 从该归档构建，不复制旧 Cookie 或宿主 Workspace。

## 综合验收

显式复跑命令：

```sh
python3 scripts/computer_view_acceptance.py --run --group \
  --agent-config /absolute/path/to/config.toml \
  --output .local/computer-combined-new
```

最终组合记录来自固定 AIO Runtime、真实 TeamX HTTP、两位真实 DSH 与 `deepseek-v4.1-flash-1017`，以及真实 Chromium。Room 使用显式 parallel 调度，并采样确认两个真实回合同时 active。A 人工接管期间 B 完成 3 次独立页面读取，累计 4 个真实模型回合。A 交还后模型通过原生工具读到 `authenticated`；停止重建后 Cookie 保留，B 不继承 A 的登录。原生调用仍走正式 MCP 与执行门，没有放开旧通道。

浏览器记录、桌面、390px 视口和成员选择覆盖实际像素、侧栏、草稿、两页面排他控制、鼠标／键盘、虚构账号登录与交还。移动视口是模拟，未宣称实际手机验收。新页面对测试模型目录的附带请求出现 403：这是受管模型目录夹具与测试用真实后端覆盖的边界，电脑链路及浏览器 JS 无错误；不把该请求当作模型设置页验收。

普通模式不传 `--agent-config`，仍使用受控 Agent；Runtime、原生工具与浏览器为真实实现。此前 C3a 的受控 Agent 证据、C2 的图像任务／实际请求工具体积与默认关闭验证保留原范围，不混同为双真实 Agent 证明。ARM 宿主运行 amd64 镜像属于模拟执行，不推导原生容量。运行报告记录固定 image、源码摘要和一次性容器／卷清理；失败与修正记录不计入通过项。

当前源码另行复跑 C2 的真实模型与连接流程：复核报告证明普通未启用回合、页面文本、截图像素任务、成员关闭和全局关闭后的实际 Schema 卸载、停容器后的原 generation 恢复均通过。未启用与离线普通恢复的 Provider 构造计数为零，测试 PATH 不提供 Docker／辅助程序。连接更换与关闭后的 无容器启动也通过。实际请求的工具名称与定义字节见请求记录，不记录凭据或业务正文。

## 日常实例采用

切换前审计覆盖 10 个 Room、18 个成员 Session 引用。7 个已创建真实 DSH 状态，其中 6 个保存旧输入桥，1 个为更早的无桥 Session；7 个均有本地结清记录，当前无活跃回合。其余 11 个引用尚未创建后端。4 个成员在升级前已被阻断；升级不为它们重放业务或自动恢复执行。

日常服务已正常启动当前二进制，全局 Computer 就绪，唯一「AIO 浏览器测试」成员按完整身份启用。该成员使用新的 `computer_status`、`browser_navigate` 和 `browser_get_text` 打开 example.com 并读到 Example Domain。现网 Chromium 通过实际公网登录入口验证观看、接管与交还；浏览器报告不使用替身。新 screen 来自新持久卷，没有复制旧 Cookie、私有配置或 Workspace。旧 `teamx-aio-dm-79c2234ae0` 容器仍保留运行，新容器为 `teamx-computer-shared`；清理由部署方决定。

采用回执、逐代结清检查和最终成员状态记录 7 个初始化 Session 的已完成轮换。其中既有自动恢复已完成的代次直接核对原回执，未重复轮换。最终 4 个原阻断成员保持暂停，其余 14 个成员 idle；全局已启用成员数为 1。未初始化的 11 个成员引用继续保留，不挂载 Computer 工具。

升级并非只影响测试成员。旧服务关闭记录中有两个 Room 的进程观察器超时；新服务按既有规则阻断自动打开。先用正式 `dsh.CheckReset` 对 7 个旧代次取得结清证明，再经正常显式 Room open／Session 轮换入口恢复，没有编辑指纹或清除恢复证据。切换脚本最初没有在重启前冻结所有受影响成员，导致一个原阻断成员自动恢复读取回合；随后暂停受影响成员并取消该回合。诊断只观察到 Inbox／宿主内容／事项读取，动作记录核验未发现外部动作账本新增或变化。此事件作为采用过程的偏差保留，不计作正常自动恢复保证。

历史核验从私有备份与当前 `room.json` 各自引用的持久段读取正文，逐条比较原有 587 条消息，10 个 Room 的实例身份及原正文全部保留。段文件会在追加时更换名称，因此核验消息内容而不要求旧段文件名继续存在。私有全量备份、旧二进制及配置位于 `.local/computer-release-adoption/`，未发布密钥、Session 正文或整个 Workspace。

日常模型曾生成一个不存在的截图链接，随后自行发出修正；一次占位文件 edit 被拒绝，未形成文件交付。原生网页读取与最终标题已核实，但不将模型这一轮描述为完全遵循所有行为约束。首版仍只提供截图图片结果；不把自然语言链接当作文件导出回执。
