# Computer 观看与人工接管

原始日志、截图和 JSON 回执仅在本地保存；本文保留验收结论、复跑入口及已知限制。

日期：2026-11-23。范围：共享 Computer 方案 C3a。右侧“电脑”已接入正式受管 screen，提供观看、成员选择、人工接管与交还。文件交付仍留 C3b；日常旧接入切换、清理和发布采用仍留 C4。

## 使用

先在全局“设置 → 电脑”连接并启用，再在成员详情打开“启用电脑”。会话工具栏和菜单统一显示“电脑”。私信默认显示该成员；多人 Room 可选择本 Room 中已开启的成员。未开启时说明设置位置，打开已开启成员的画面可按需创建 screen。只读取成员列表不创建 screen，也不探测 Provider。

画面显示容器内该成员的桌面和 Chromium；聊天、DSH、宿主 Bash 和 Workspace 仍在宿主运行。普通观看不暂停 Agent，关闭观看只断开画面。面板沿用右侧辅助栏、展开、手机覆盖布局和临时键盘；切换文件／日历或成员会释放原观看连接，聊天草稿保留。界面不显示 Runtime 地址、内部端口、screen 代次或管理密钥。

点击“接管操作”先暂停目标成员，等待当前回合结束。等待期间可取消；当前回合再次调用 Computer 时会收到 `human_control`，应结束回合而不重试。只有当前页面取得控制权、执行结清且画面已连接时才开放输入；其他页面继续只读观看，其他成员继续独立工作。

完成时点击“完成接管”。交还只恢复接管前原本运行、且期间没有新手动暂停的成员。原先暂停的成员继续暂停。页面关闭、画面断开、服务重启或租约失效均保留暂停；普通观看断开不改变调度。

先前网站动作结果未知时，必须先核验远端执行停止，才允许人工检查。面板明确提示仅供核验；交还后仍暂停，不自动恢复故障 Session，不把停止证明当作网站操作成功，也不补发原动作。

## 控制与输入围栏

成员 Actor 继续保存暂停意图和 `pauseRevision`；Runtime 保存当前 screen 的排他控制租约。宿主的短期准入提示只负责尽早拒绝新工具调用，不另建持久控制状态机。网络、进程和画面退出等待均在 Actor、Room／Store 和配置锁外执行。

1. Actor 持久暂停后续调度；宿主关闭新调用准入，Runtime `hold` 立即围住同一 screen 的原生工具入口。已接受的动作仍走 C2 的结清路径。
2. 当前回合退出后核验 C2 的外部执行事实。未结清则阻断；仅业务结果未知且已有停止证明时允许人工核验，并取消自动恢复意图。
3. Runtime `activate` 只接受当前服务租约、screen epoch、控制代次和页面身份；在途执行或未核验 unknown 不能获得输入。每个 Room 运行作用域内的新接管使用递增代次；Room 重开可从新的作用域开始，已退休的作用域不能再接管。旧 hold／renew／activate／release 不能影响新接管；先收到 release 的请求也不能被迟到 hold 复活。
4. 交还先把 Actor 置于 finishing，Runtime 关闭输入准入并撤销操作流。RFB 解析器在同一上游连接上提交带随机标记的 `Fence(Request|BlockBefore)`，等待 Xvnc 应答，再关闭连接并等待全部读写处理退出；宿主也等待 WebSocket handler 退出。此后才写固定、按接管 ID 去重的目标成员 Room 事件，再按原暂停意图恢复。
5. 缺失输入 Fence 应答时 screen 保持 blocked，不能交还并恢复。协调层复用 C2 的单屏停止核验；有了停止证明后可完成交还反馈，但故障成员仍暂停。另一 screen 不受影响。

租约为 20 秒，持有页面通过原控制查询续租。每个文档生成独立页面身份，复制标签页不会沿用同一个输入所有者。Runtime 监测服务／screen 失权、停用、断线和租约过期，撤销对应流；服务 CAS 交接清除旧控制代次，旧服务不能续租或重新输入。重启保留的是 Actor 的持久暂停，不恢复人类输入租约。

## 传输与只读保证

Provider 的可选 `DisplayScreen` 合同把 `Control`、原始 RFB 画面流和受限 noVNC 静态资源附着到同一个受管 Screen，原生 MCP 仍走 C2 的唯一调用路径。Room 不读取 AIO 端口或进程结构。AIO 通过认证私有管理协议承载控制与 RFB upgrade；管理凭据留在宿主和 Runtime，浏览器只访问 TeamX 同源路径。

沿用 `GET /v1/environments` 取得本 Room 的可选成员，以及 `/v1/environment/{opaque-id}/viewer`、`control`、`websockify` 和受限 `vnc/core/…js`／`vnc/vendor/…js`。这些内部路径名保持兼容；产品文案统一为“电脑”。写控制操作验证当前 Room／服务、人类 caller、成员和页面归属。已有登录失效、成员失效或配置变更会关闭长连接。

只读保证在 Runtime 实施，独立于 noVNC 的 `viewOnly`。RFB 3.8 握手后逐消息、有界解析；观看连接只允许像素格式、编码协商、画面请求和 Fence，键盘、鼠标、粘贴及未知扩展不能到达 Xvnc。操作连接另验唯一租约，只开放受限输入消息。WebSocket 分片不能绕过 RFB 解析。

画面协商限定为 32 位 raw／copyrect、游标、桌面尺寸、LastRect 和 Fence，便于准确解析 Fence 应答；不协商扩展剪贴板或未经支持的输入扩展。这只影响画面传输，不修改原生 MCP Schema、截图图片块、坐标或工具结果。单 screen 最多 8 个画面连接，宿主继续使用有界总连接数；握手、输入消息、静态资源和退出等待均有边界。

Agent 指导已说明人工接管、`human_control` 的结束回合行为，以及交还后重新观察且不扩大网站写入授权。`computer_status` 在接管期间报告不可用和人工控制提示；工具 Schema 集合没有因观看／接管增加。

## 验证与证据

检查记录列明普通回归、定向 race、e2e 编译和真实验收。受控测试覆盖等待／取消、当前回合再次调用拒绝且不留下变更记录、多页面互斥、成员选择及 Room 隔离、暂停意图恢复、新手动暂停优先、异常阻断、停止后的 unknown 人工检查、租约过期／服务失权、旧控制代次、输入 Fence 应答与缺失、输入退出后才能交还，以及固定事件幂等。

真实验收可显式复跑：

```sh
python3 scripts/computer_view_acceptance.py --run \
  --output .local/computer-view-acceptance-new
```

默认验证私信、文件／日历侧栏切换；增加 `--group` 验证多人 Room 的实际成员选择及空私信状态，两种模式均已通过。脚本构建固定 amd64 派生镜像，创建独立容器和卷，运行真实 Runtime、TeamX HTTP、两个受管成员 screen 和 Chromium。使用一次性站点及虚构账号，无真实平台写入；不修改日常成员、旧容器或 TeamX 配置。结束后核验容器停止、删除容器和临时卷。当前宿主为 ARM，amd64 通过模拟运行，不据此推断原生容量。

浏览器记录及桌面、390px 手机视口、多人 Room 成员选择证明实际像素、侧栏切换／展开、草稿、双页面排他控制、鼠标和桌面键盘、手机临时键盘清空、虚构登录、交还与成员画面切换。组合记录证明 A 接管时 B 的原生调用继续，A 登录在停止／重建 screen 后保留，B 不继承 A 登录。另有私信浏览器记录保留文件／日历切换证据。运行报告保留实际镜像和构建时源码摘要，以及容器／卷清理结果。

本阶段真实 Agent 调度使用受控后端，原生 MCP、Runtime、桌面、浏览器和输入均为真实实现；没有把这些证据当作双真实 DSH／模型并发验收。此前失败尝试见尝试说明，不计入通过；最终记录来自完整通过的一次运行。

C3a 不发布文件列表、导入／导出、独立 CLI 或 MCP search，不切换日常旧 environment 接入。新观看／接管需要更新可选 AIO Runtime 镜像；普通 TeamX 构建、启动和未开启成员仍不依赖 Docker 或辅助程序。
