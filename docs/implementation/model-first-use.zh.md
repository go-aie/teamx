# 模型首次使用闭环

2026-11-12 完成[模型配置方案](../MODEL-CONFIGURATION-AND-LIVE-APPLY-PLAN.zh.md)阶段 2。范围为全新 home 的首次设置、保存和真实对话；在线改选、全局传播、删除替换与已有业务数据迁移仍未开放。

## 已实施

- `start` 直接准备缺失文件和首次管理认证，不再以 `init`、`access init` 或终端模型问答为前置。可选 `init` 只准备文件与认证后退出，`--non-interactive` 保留兼容用途；macOS 下载隔离确认保持独立。支持 `start --listen` 避开已有服务端口。
- 首次身份先持久预留，再创建私有 token、提交配置；中断可续接相同身份与 token。已有身份缺失／损坏 token 时拒绝自动补发，并提示部署机修复入口。共享初始化代码由持有 home 锁的调用者调用，不递归获取锁。日志只显示地址与 token 文件路径。
- 原首次网页表单复用阶段 1 的生产适配器隔离探测。验证由服务异步持有，HTTP 返回操作 ID；刷新和双标签页可查询进度，同 ID 相同输入返回已有状态，不同输入拒绝。进入正常服务及重启后，同一提交仍可核对回执。未完成验证在重启后标记中断，要求显式重新验证，不重放请求。
- 一次验证必须完成文本、固定无副作用工具往返和进程清理。失败不发布模型；提交前复核列表版本与配置来源。网页不要求 `api_key_env`，Key 进入私有凭据存储；验证、实际执行和重启使用同一托管版本，宿主同名旧值／空值不覆盖它。
- 无业务数据的预填配置可复用地址、模型、高级参数与已有 Key。旧环境按原优先级读取，敏感的系统／TeamX 变量不能作为模型 Key 导入；保存时在同一次配置提交中移除该初始 `runtime.model` 和对应旧 `[env]` 项，保留其他配置及注释。已有房间或其他业务数据的实例仅能查看修复提示，新写入继续阻断，未执行阶段 4 的迁移。
- 高级表单包含输入类型、上下文窗口、输出上限、推理强度及三态 developer 兼容性。非 Completions 协议明确清除该兼容项，服务端继续拒绝携带不适用值的请求。Key 成功提交、失败、退出和离开页面后清空，不进浏览器存储。
- 保存成功后在同一监听地址启动正常管理服务，保留当前登录。默认助理复用原持久创建回执和重试机制，成员保存默认引用；新的 Room 配置只保存模型引用及启动器，完整模型与凭据引用保存在 generation 快照。设置保存和助理初始化是独立状态，失败重试不重复创建。
- 正常重启只读托管配置／验证回执并恢复原 Session，不在启动时发模型请求，不因断网回首次向导。启动校验兼容已完成房间从索引移除初始化快照的既有行为，并核对实际 `room-config.json` 身份。
- 更新启动帮助、README 和两份发行使用说明。正式归档 smoke、全部发行平台与只读包矩阵仍留在阶段 4。
