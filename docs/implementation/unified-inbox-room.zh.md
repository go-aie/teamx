# Room 共同存储内核实施记录

日期：2026-11-18。对应[统一方案 S6](../UNIFIED-INBOX-STORAGE-PLAN.zh.md#s6--room-接入共同存储内核与升级验收)。本阶段交付 Room 与私有／共享 Inbox 的共同段操作、发布校验及确认原语，保留 Room 原生候选、唯一游标及发布根。没有部署或操作生产 Room。

验收构建：Go 1.27.1 / darwin arm64，revision `4d334fc41547ba33806fb081aacd8aef44e9c4a6`，包含工作区改动。生产 CLI 构建 SHA-256 为 `db8e6c630b798c8a480cca4c0db30ea4a44d8c1e1bc1d80b57fc8386a1e5f93c`；相关源文件摘要、实际服务目录及测试二进制执行日志见本地 evidence。

## 实现与兼容

`internal/inputstream/segments.go` 提供发布范围校验、只读已提交前缀、记录字节边界检查、同步写入及尾部截断。私有和共享 Repository 的加载、追加、回收边界重写及升级导入使用这些原语；Room 通过原生段元数据适配同一内核。共同代码不解释 provider、Room 事件或成员权限。

Room Actor 构造原生候选，Store 准备段并以 `room.json` 原子发布。保留原分段格式、消息和事件序号、回复、成员身份、事件去重回执、清空边界、游标和原生同页证明；纯成员确认写入正文段数为零。Room、私有及共享分区保留各自唯一 owner 和发布根，没有额外的 Room 分区账本。

`confirmation.go` 提供物理页顺序、分区、快照范围及检查点比较。Room 适配器继续核验执行、成员可见性和精确扫描结果，原生游标与证明仍一起提交。补齐反向扫描检查，避免异常确认范围触发切片越界。

Room 扫描与成员 reserved 页落盘之间，在既有 Store 锁内重新核验原生已提交边界及游标，与清空的保护检查串行。清空先提交时拒绝旧扫描，不保存失效正式页，下一请求可读保留后缀；正式页先保存时清空被保护阻止。已持久页跨重启仍受保护，恢复、确认及回合封存后才能清空。

分段格式不变，因此不新增升级格式或重复迁移已分段 Room。旧内联历史和旧输入继续使用已有独占自动升级框架，备份／转换／围栏／发布／清理各边界均沿原进度恢复。已分段且包含原生证明与事件回执的数据重开时不生成新升级日志。

## 真实服务、浏览器与模型

Chromium 使用隔离管理目录、真实 HTTP、Room Actor 和实际生产页面；仅 DSH 子进程由现有 controlled component 替换。页面实际发送两条消息并引用第一条，清空经正常 `POST /v1/messages/clear` 指定快照。服务完整关闭，再从同一数据目录重建 manager 和 runtime；页面显示保留回复及「已清空」引用，继续发送取得序号 3。1440px 桌面及 390px 移动视口没有横向溢出或 pageerror，截图已人工检查。清空通过 HTTP 执行，不将它描述为页面完整「重新开始讨论」验收。

真实 DSH 使用已有默认模型 `deepseek-v4.1-flash-1017`、实际 ACP 进程和 HTTP MCP，通过匹配的持久 Session 工具结果证明确认。隔离 Room 中一条普通消息、一条含保存图片的历史集成消息、一条回复及一个定向事件，共四条；模型正确返回全部标记、`reply_to: 1` 和像素中红色。成员甲原生游标推进至 4，成员乙仍为 0；关闭 DSH、重开 Room 后正文及原生同页证明完全相等。

图片下载使用隔离 fixture，平台链接也是 fixture；本轮没有真实 provider 验收或外部业务写入。模型和浏览器均有独立日志、报告及保留数据目录，最终路径和完整 RoomIdentity 记入本地 evidence 文件。证据为私密本地材料，不纳入 git。

## 操作测量与边界

1000 条、每条文字 192 字节的同一原生 Room 样本，对追加一条、确认 20 条、清空 500 条、重开分别测量耗时及正文段写入次数。追加和清空各写一个段，确认写零个段；清空后保留 501 条。实际毫秒值见 `.local/unified-inbox-room-operations.json`。这些是本机文件同步与 Actor 调度下的单次样本，不声称吞吐、最坏延迟或相对旧实现的性能提升。

最终权威清楚分离：Room Actor 写原生时间线、成员游标和证明，成员 owner 写执行页及 Session 交付协调，通知 owner 写来源事实，Inbox owner 写共享正文与保护。Room 操作在根发布后完成；回收由原生页、持久成员页及定向事件事实核验；重启只按已提交根和同页证明恢复。正常存储与升级合同已同步到 [Room 架构](../room-architecture.zh.md)、[存储架构](../storage-architecture.zh.md)及[安装与运行](../installation.zh.md#room-输入自动升级)。
