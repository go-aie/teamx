# Web 更新通知与读取

活跃会话页面使用一条 SSE 接收资源变化通知，再通过原 HTTP 接口读取权威状态。消息、配置、Activity 和历史正文继续由各自接口返回；命令仍通过原接口提交。使用和部署要求见 [Server 说明](../server.zh.md#页面更新与连接)，复跑入口见 [测试指南](../testing.zh.md#web-更新通知与自动读取)。

## 通道与业务边界

`GET /v1/updates` 接受现有浏览器会话或本机免登录身份，订阅全局资源及可选的当前 Room。托管模式共享一个进程内通知中心，单 Room 模式独立持有中心。Room 订阅须匹配 `room_id`、`room_instance`、`room_service_epoch`；订阅不会启动已关闭的 runtime。

流发送 `hello`、`invalidate`、`resync`、`heartbeat`，仅包含连接、主题和必要资源身份。没有正文、凭据、业务成功回执、SSE id 或持久重放日志。注册先于 hello；每次 hello/resync 后由页面隔离旧读取并核对现态，旧连接与旧资源身份的事件直接丢弃。

业务层只提供可选、无错误返回的观察回调；通知在状态安装或需要核对的门禁变化后发布，不反查生产者、不在业务锁下读取 HTTP 正文或写网络。通知不作为写成功证明，也不改变保存结果、commit-unknown、原业务恢复与授权判断。没有匹配订阅时跳过通知投影、详情读取和目录扫描。

| 来源 | 通知范围 |
| --- | --- |
| 消息、共享阅读 | 消息实际新增/清空、阅读安装及错误门禁变化，按需通知 messages、human_read、catalog |
| 成员、Inbox | 可见执行状态、成员增删、实际入箱/消费/清理及写错误，按对应资源和明确目录触发点发布 |
| 通知源 | 持久安装后的状态变化，分类为 notifications/summary 或 diagnostics |
| Workspace、目录 | 操作记录、索引、runtime 生命周期及忙状态安装 |
| 模型、设置、平台、工具 | 配置发布、原操作进度/终态、连接与绑定安装；普通消息不刷新模型配置 |
| 交互、授权、Policy | 原操作记录、规则保存及到期核对；按 operator、Room、成员身份隔离 |
| Activity | 诊断追加、运行状态及最终诊断变化；锁释放后发信号，正文通过 HTTP 读取 |

Policy、平台能力、授权与 selection 的到期反馈使用订阅内的一次性唤醒；读取后更新截止时间，断流时清理。它只要求核对，不启动登录、刷新 token 或其他业务命令。后台平台采集、Agent 执行和已受理操作继续由 Server 持有。

## 通知分类与扩散控制

共用 notification Store 的 `Changed` 回调提供安装前后只读状态，来源字段的解释留在 Room 适配层。摘要提取只比较固定业务字段，不构建完整 HTTP 投影或比较整个状态。

- `summary`：目标、配置版本、启停/退役、积压、运行状态、采集/投递错误、Events 缺口及 Lark 搜索分支错误；可刷新侧栏和来源摘要。
- `diagnostics`：检查时间、扫描进度、观察数、内部水位、调用/耗时/字节等指标；仅诊断详情可见时读取，重新打开时核对现态。

缺省 kind 按 summary 处理。两类共用 notifications 资源键、在途读取与限频；合并时 summary 优先，即使它在诊断读取期间到达，也保留一次后续核对。

源进度保存不代发 inbox、members 或 catalog。实际入箱、消费、清理和成员变化由各自拥有者通知；通用 members 失效也不自动扩散到 catalog。目录仍由消息、共享阅读、名字/索引、成员增删、runtime 和忙状态等明确变化触发。这样持续空查询不会变成持续全页补读，实际错误与业务变化仍可及时显示。

## 前端调度与恢复

每个资源只有一个在途逻辑读取、一个 dirty 代次及至多一个唤醒定时器。连续通知合并，读取期间变化保留一次后续核对，新通知不推迟已安排的唤醒。追平后停止定时器；失败按 1～30 秒退避，并与最小读取间隔取更晚时间。

| 普通失效对应资源 | 最小读取开始间隔 |
| --- | ---: |
| messages | 500ms |
| members、human_read、models、workspace、interactions、authorization、settings、platforms、tools、policy | 1000ms |
| catalog、activity、inbox | 1500ms |
| notifications | 2000ms |

首次进入、恢复和显式操作核对可越过普通失效限频，但共用同一个串行读取入口。权威写回执可直接安装并隔离写入前的读取；未知写入只核对原 operation/session，断线和重复通知不重新发送消息、应用模型或启动授权。身份/权限错误停止对应资源的普通重试，待显式重入或上下文变化恢复。

消息、成员、配置和 Activity 分别调度，慢详情不会成为聊天读取的前置依赖。Workspace 与平台设置共享 platforms 的在途读取。历史补载仍按固定快照分页，一轮逻辑读取可能产生多个 HTTP 请求；Inbox 历史、Policy 草稿/版本冲突、阅读进入边界和原操作 ID 保留原保护。

隐藏、离线或 pagehide 关闭流并暂停调度；恢复后重新订阅并核对。正常连接错误优先使用 EventSource 重连；45 秒无有效帧或连接终止时关闭旧连接，按有抖动的 1～30 秒退避替换。只有 session 核对确认为 401 才返回登录，hello 本身不解除聊天发送门禁。

会话页面已移除主显示循环、模型设置和平台授权状态轮询。保留搜索防抖、共享已读合批/重试、dirty 读取限频/重试、心跳检测和到期唤醒。首次模型初始化的 `/access` 受限入口尚无 Room 业务服务，原操作仍查询 `/v1/setup`，不属于会话页面的空闲零读取范围。

## 多端与有界资源

每个活跃页面独立建立连接，拥有自己的队列、dirty、缓存和定时器；同一操作者的变化会扇出到所有匹配订阅。一端读取不会消费另一端的更新，隐藏、退出或慢连接不阻止其他端接收。不同 Room 各自订阅详情，并通过全局 catalog 更新目录。

共享已读沿用服务端合并规则；各端草稿、滚动位置和阅读进入边界留在各自页面。恢复只读现态，不复制另一端的页面位置或转移原授权绑定。跨端阅读行为见 [会话说明](../conversations.zh.md)，固定 Inbox 历史行为见 [Inbox 说明](../inbox.zh.md)。

| 边界 | 当前值/处理 |
| --- | --- |
| 单帧 | 最多 4KiB |
| 每连接积压 | 最多 64 个资源键、64KiB 编码预算；同键合并，超限清空并发 resync |
| 每连接到期登记 | 最多 64 个；超限要求 resync，断流清理 |
| 连接数 | 每中心 64 条，每浏览器会话 8 条；本机免登录共用匿名配额，超限返回 busy |
| 心跳与写入 | 15 秒心跳，每次 Write/Flush 期限 5 秒，成功后清除期限 |

writer 每次领取一个键，普通通知合并 100ms；网络发送在中心锁外进行，流不占普通 HTTP 请求槽位。登出、会话到期/撤销、访问设置变化、runtime 替换及服务关闭会取消对应流，阻塞写入也可被打断。

## 验证与后续边界

回归覆盖资源限频、来源安装、通知分类、慢读取/慢 writer、积压与连接上限、撤销、重建恢复及未知写入防重放。隔离服务的真实 Chromium 验收覆盖单 Room/托管空闲零显示读取、活动采集、多页面和独立认证上下文，以及阅读、Inbox、Policy 与授权组合；模型和外部 CLI 使用受控 fixture。

同机同数据配对表明空闲及无业务变化的采集可消除显示补读，连续更新和历史组合可减少请求与字节。它不保证每个场景的 CPU、内存或消息延迟都下降：完整目录和 Activity 仍由 HTTP 计算/传输，大历史补载仍可能造成主线程长任务；分页请求、业务写入和后台采集也继续存在。

已有负载检查覆盖 101 Room 和三页面/两个浏览器上下文，不外推为更大规模容量或实体设备证明。390px 视口、触摸和模拟隐藏不替代真实手机的软键盘、系统冻结、网络切换与前后台恢复；实际 HTTPS/反向代理逐帧刷新及现场部署后的活动采集与多端观察仍须独立验收。原始测量输出按测试指南在本地生成，不作为源码依赖。
