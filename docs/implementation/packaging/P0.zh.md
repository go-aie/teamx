# P0：发行依赖与平台核查

> 实施记录：本文保留记录时的范围、结果与缺项，不作为当前操作指南。当前用法见[打包指南](../../../packaging/README.zh.md)及[正式发行操作指南](../../../packaging/releasing.zh.md)。

核查日期：2026-11-08。对应[打包与发行计划 P0](../../PACKAGING-AND-DISTRIBUTION-PLAN.zh.md#102-p0依赖与平台核查)。

P0 已交付依赖清单、精确 npm 解析、平台矩阵、资产允许清单和首批许可证材料。P1 公共入口与 core 开发归档验证见 [P1 实施记录](P1.zh.md)；后续组装、验证和新增阻塞见 [P2 实施记录](P2.zh.md)。本文件其余内容保留 P0 核查快照，没有正式发行包。

按本次用户要求，**Scion 暂缓**：`scn` 不进入任一 profile 的必需依赖，也不阻塞 full。已有 `teamx-scion` 封装仍列在自有构建入口中，但包的能力说明必须标明暂不支持 Scion；不下载其私有资产、不复制登录资料。

## 交付文件与检查

| 文件 | 用途 |
| --- | --- |
| [dependencies.lock.json](../../../packaging/dependencies.lock.json) | 精确版本、来源、平台产物、摘要、布局、系统环境、验收状态和阻塞项 |
| [dsh/package.json](../../../packaging/dsh/package.json)、[dsh/package-lock.json](../../../packaging/dsh/package-lock.json) | DSH 的独立生产依赖解析输入；724 个条目固定版本、URL 和 SHA-512 integrity |
| [bundle-files.json](../../../packaging/bundle-files.json) | 三个自有构建入口及逐文件资产清单，不递归复制工作区目录 |
| [licenses/](../../../packaging/licenses) | DSH、Node、glab、lark-cli、dugite-native 及当前四个 Go 模块的许可证 |
| [glab.lock.json](../../../tools/gitlab/glab.lock.json) | 补齐四目标官方归档摘要与完整源码 commit；统一 lock 引用它，避免重复维护归档摘要 |
| [check-packaging.mjs](../../../scripts/check-packaging.mjs) | 无网络、无安装、无业务平台请求的清单一致性检查 |

在仓库任意 cwd 通过脚本的绝对路径运行也可以。以下命令在仓库根目录执行：

```sh
node scripts/check-packaging.mjs
node scripts/check-packaging.mjs --require-ready --target darwin-arm64 --profile full
```

第一条校验版本契约、来源 URL、摘要、npm 解析、四目标原生依赖、模板覆盖、资产路径和许可证材料。退出码 `0` 仅表示清单有效。第二条还检查组装/发行门槛；当前应退出 `2` 并列出缺项。清单错误或未知参数退出 `1`。`--target` 可选，省略时检查全部目标；`--profile` 支持 `core`/`full`，默认 `full`。

升级依赖时显式更新版本、来源、摘要和相关版本契约，再重新核查。更改 npm 输入时还须更新统一 lock 中的输入摘要；普通打包不得重新解析 semver 范围。脚本不下载依赖，不把待验收项改为通过。

四目标的 Node、glab、lark-cli、Git 均有精确归档和摘要；DSH 原生依赖有对应目标条目。暂缓 Scion 后，没有发现需要为额外两目标另建流程的缺项，因此四目标共用本期流程，不设延后目标。这是 P0 的交付范围决定，实际部署若暴露专项问题，须显式更新范围和证据。

runner 标签与架构来自 [GitHub 官方列表](https://github.com/actions/runner-images#available-images)，本次未调度远端 runner。macOS 14 runner 已于 2026-11-02 退役，不能使用旧标签替代 Intel 环境。runner 访问权限、配额和真实原生执行仍在 P4 验证。

上表是本期准备验证的最低系统范围，**尚未形成已经通过的系统兼容承诺**。Node 24.22.2 自身要求 macOS ≥13.5；Linux 要求 kernel ≥4.18、glibc ≥2.28、libstdc++ 的 `GLIBCXX_3.4.25`。这些下限不能直接推广为完整包的下限，见[精确 Node 版本的构建说明](https://github.com/nodejs/node/blob/v24.22.2/BUILDING.md)。Go 1.27 要求 macOS ≥13，见 [Go 发布说明](https://go.dev/doc/go1.27#ports)；当前选择 macOS 15 验证全依赖，不提前承诺 13/14。Linux 原生模块及 Git helper 的最终动态库下限留到各原生环境检查。

系统保留 POSIX shell、基础命令、`/bin/ps`、正常进程观察权限和证书。macOS 还使用系统 libSystem、Security/Keychain 与 libcurl；DSH 的 workspace-write 命令工具需要系统 `/usr/bin/sandbox-exec`，该前提由 P3 真实回合确认。Linux 的 Node 需要相应 C/C++ 运行库，其沙箱后端仍待目标原生环境真实验收。lark-cli 的 Linux 凭据存储涉及 D-Bus/Secret Service，服务器无桌面环境的支持方式需要真实登录验收。Windows、Alpine/musl 不在范围内。

### DSH

选用[官方 RC Release](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1) 的版本，保留 `prerelease: true`，不等待稳定版、不回退开发机安装。Release 仅列源码资产；已有精确[官方 npm 发布](https://registry.npmjs.org/@deepseek-ai%2Fdsh/0.2.2-rc.1)，因此主路径采用 npm，不在 P0 构建整个上游仓库。npm 元数据没有 `gitHead`；这里分别记录已核查的源码标签 commit 与同版本官方 npm integrity，不虚构 npm 到源码的构建证明。

本次核对顶层 tarball 的 SHA-256 与 registry SHA-512 integrity。先在隔离临时目录、不读取用户 npm 配置、禁用生命周期脚本的条件下解析依赖，再用固定 Node 24.22.2 / npm 11.19.1 离线复核 lock。lock 包含全部目标的 optional dependencies；这些条目不是跨平台可共用的已安装 `node_modules`。后续按目标使用固定输入运行 `npm ci`，不能在打包时执行会更新解析的 `npm install`。

原生依赖核查包括 `@deepseek-ai/node-addon-system` 0.1.2、sharp 0.35.5 / libvips 1.3.4、ripgrep 1.18.0、Koffi 3.1.1 的四目标包，以及 node-pty 1.2.0-beta.15 tarball 内的四目标 prebuild。node-pty 的官方 tarball 已核对 integrity 并检查 prebuild 文件；**预构建文件存在不证明 Node ABI、最低系统和加载行为已经通过**。

源码备用路径也固定同一 commit、pnpm 11.28.5 与上游 `pnpm-lock.yaml` 摘要；该摘要不是 npm 部署 lock。任何切换来源都须更新 manifest 并重新验收，不可用本机 pnpm store 链接替代部署。

对 integrity 已验证的 `@deepseek-ai/dsh-acp@0.2.2-rc.1` 做静态检查，预期身份是 `deepseek-harness-acp` / `0.0.1`，与 CLI `0.2.2-rc.1` 分别记录。未进行 ACP 握手或模型调用。包内真实初始化能力、图片输入、最小回合、工具调用、取消/关闭及恢复都需 P3 验证。

### lark-cli 与 Git

lark-cli 的[官方构建配置](https://github.com/larksuite/cli/blob/v1.0.99/.goreleaser.yml)提供 `CGO_ENABLED=0` 的四目标 Go 程序及许可证材料；本轮选择[原生发行资产](https://github.com/larksuite/cli/releases/expanded_assets/v1.0.99)，不携带用于安装的 npm 包，也不在用户启动时在线下载。不会复制打包机的 profile/Keychain。

Git 选用 [desktop/dugite-native 的固定 Release](https://github.com/desktop/dugite-native/releases/tag/v2.56.0-2)，四目标的归档及 SHA-256 均已核查。`ubuntu-arm` 是另一个架构，Linux arm64 必须使用 **`ubuntu-arm64`**。其 Git 子模块固定为 `a018953688f1b10bddf91bff8747068f5f4746a4`。该发行物为应用嵌入场景准备完整布局，不能只抽取 `bin/git`。

macOS 的[构建脚本](https://github.com/desktop/dugite-native/blob/v2.56.0-2/script/build-macos.sh)显式使用系统 curl；不能将“可搬移”解释为没有系统库。Linux 的[构建与打包脚本](https://github.com/desktop/dugite-native/blob/v2.56.0-2/script/build-ubuntu.sh)组装 helper 和证书等资源。P1/P2 须按原布局保留它们，以相对 bundle root 设置 exec-path、模板及 Linux 证书位置，检查符号链接和动态库；TLS、clone、commit 在 P3 验证。本次 Git 归档下载遇到 HTTP 502，只采用公开发布摘要和构建布局证据，未将其标为本地归档已验证。

## core/full 与资产边界

| 能力 | core | 当前范围的 full |
| --- | --- | --- |
| 三个自有 Go 程序、公开团队模板、DSH + Node | 包含 | 包含 |
| glab / lark-cli 原生运行程序 | 操作者自备 | 包含 |
| Git Workspace 原生依赖 | 操作者自备 Git | 包含可搬移 Git 与完整必需资源 |
| Scion | 暂缓；封装存在不表示原生能力可用 | 同左，不作为 full 缺项 |
| 模型、GitLab/飞书账号、登录资料、通知订阅 | 用户自行配置 | 用户自行配置 |

允许清单覆盖四个团队、20 个受版本控制的团队文件，另列配置样例、TeamX/嵌入 marked/依赖许可证。模板按逐文件清单复制；新增受控模板但未更新清单会失败。新增未受控文件不会被自动纳入。

禁止递归复制 `.teamx`、直接复制工作区 `bin`，或打包本机配置、data、profile、缓存、`.env`。Web 与平台 skill/askpass 保持现有嵌入方式，不额外复制源码树。`start`、manifest、README、摘要、完整第三方通知及 Git 源码材料由后续阶段生成；本轮允许清单不把尚不存在的入口伪装为已交付。

## 再分发材料与阶段出口

首批许可证已保存并在统一 lock 中记录来源/摘要：DSH、glab、lark-cli 的 MIT 文本，Node 完整 LICENSE（含内嵌第三方通知），dugite-native 的 GPL v2 文本，及当前 TeamX 四个 Go 模块的许可证。`go.mod`/`go.sum` 仍是自有 Go 依赖版本与校验的依据，不另建版本解析机制。

这批文件**尚不是完整发行许可材料**。P1/P2 必须从实际部署结果收集 DSH 全部生产依赖、原生库及平台 CLI 的第三方通知，并保留运行时自带材料。Git 还须准备与固定 Git/dugite-native 构建及捆绑组件相匹配的完整对应源码、构建材料和许可证；不能以一个源码仓库首页链接替代这项交付。此项已作为 `git_redistribution_materials` 阻塞正式分发；本轮不创建或发布任何远端资产。

P0 出口已达到：四目标已核查并固定范围，依赖/来源/布局可追溯，差异和剩余缺项已记录，可以继续 P1。以下门槛保持未完成：

- `native_runtime_acceptance`：最终归档、干净环境 smoke、真实 DSH/平台/浏览器与系统基线验收。
