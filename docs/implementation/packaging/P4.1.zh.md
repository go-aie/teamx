## 触发与矩阵

- `pull_request`：使用无业务凭据的 core 检查和四平台快照构建。
- `workflow_dispatch`：默认 core，可选 full。每次使用完整交付矩阵，不提供绕过失败目标的选项。
- 从 `packaging/dependencies.lock.json` 的 `delivery=included` 条目生成矩阵，读取固定 Go/Node 版本，不复制另一份组装流程。
- 当前对应 `darwin-arm64` / `macos-15`、`linux-amd64` / `ubuntu-24.04`、`linux-arm64` / `ubuntu-24.04-arm`、`darwin-amd64` / `macos-15-intel`。已按 [GitHub 官方 runner 表](https://github.com/actions/runner-images#available-images)核对标签和架构；实际账号的可用性与运行结果须以 Actions 为准。
- Linux full 继续由 `git_tls_runtime` 明确阻塞，手动选 full 将使相应 job 失败，不降级为 core；其他平台保留各自构建和下载复验结果，不能据此宣称全矩阵通过。

## 执行流程

`checks` 先执行 lock/资产检查、打包脚本测试、`make test`、`go vet ./...` 与 Web Node 测试，成功后运行构建矩阵。

每个构建 job 核对 Node 的 OS/arch 与内核架构，要求干净源码，调用同一个 `scripts/package.sh --channel dev`。依赖归档和 npm 内容缓存按 runner OS/arch、target、profile、Node 版本及 lock 摘要隔离，无跨目标恢复前缀；缓存命中仍由已有打包逻辑核对 SHA-256/npm integrity。Go 缓存使用 setup-go 的平台、架构、Go 版本及 go.sum 分隔。缓存不包含已部署的 node_modules、staging、用户 home 或业务数据。

通过构建及最终归档 smoke 后，生成 `snapshot.json`：记录同一归档 SHA-256、原构建报告摘要和完整 manifest，明确标为 `development_snapshot`、`release_ready=false`。只上传 `.tar.gz`、`.tar.gz.sha256`、构建报告和该说明，不直接上传目录形式的运行时。artifact 名含 target/profile/run attempt，保留 7 天；重跑不会读取上一次 attempt 的产物。

下载复验在新的匹配架构 job 中执行，不恢复构建缓存、不重建归档。核对文件集、归档摘要、构建报告、commit、target/profile/channel、版本、lock、源码输入及 smoke/原生检查/fixture 指纹后，再执行原有隔离 smoke。运行能力检查使用包内 Node/DSH/CLI；外部 Node 只运行验证器。复验后再次核对资产未变，另行上传 `snapshot-verification-...` 报告，保留原始构建报告。任一目标失败仍使整个 Workflow 失败，缺失 artifact 不从旧运行补取。

所有 job 只授予 `contents: read`，checkout 不保留 Git 凭据，无业务 secrets、模型 prompt、平台登录或业务平台写入；没有 `release.yml` 或 Release 发布动作。第三方 Actions 固定为完整 commit SHA，核对来源为各仓库该 SHA 的 `action.yml`：[checkout](https://github.com/actions/checkout/blob/d23441a48e516b6c34aea4fa41551a30e30af803/action.yml)、[setup-node](https://github.com/actions/setup-node/blob/249970729cb0ef3589644e2896645e5dc5ba9c38/action.yml)、[setup-go](https://github.com/actions/setup-go/blob/924ae3a1cded613372ab5595356fb5720e22ba16/action.yml)、[cache](https://github.com/actions/cache/blob/caa296126883cff596d87d8935842f9db880ef25/action.yml)、[upload-artifact](https://github.com/actions/upload-artifact/blob/b7c566a772e6b6bfb58ed0dc250532a479d7789f/action.yml)、[download-artifact](https://github.com/actions/download-artifact/blob/37930b1c2abaa49bbe596cd826c3c89aef350131/action.yml)。

## 本地复现

```sh
node scripts/package-ci.mjs plan core
node scripts/package-ci.mjs host darwin-arm64

# DIR 只放同一次打包生成的归档、摘要和构建 smoke 报告。
node scripts/package-ci.mjs record DIR darwin-arm64 core FULL_COMMIT
# 将 DIR 的四个文件复制/下载到 NEW_DIR，再执行：
node scripts/package-ci.mjs verify NEW_DIR darwin-arm64 core FULL_COMMIT NEW_REPORT.json
```

`FULL_COMMIT` 是与归档一致的 40 位 commit；本地 dev 归档可以有 dirty 指纹，但所有归档记录的构建输入必须与当前验证源码一致。CI 在构建前另行要求工作树干净。输出报告路径必须不存在，失败不复用旧的成功报告。
