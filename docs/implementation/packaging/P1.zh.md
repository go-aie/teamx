日期：2026-11-08。范围对应打包计划 P1；多平台组装、full、真实模型/平台/浏览器和 CI 仍属 P2–P4。

## 使用

构建机需要 Go 1.27.1、Node（执行编排脚本）、curl 与 tar；脚本下载并验证固定
Node 24.22.2，以其自带的 npm 11.19.1 部署 DSH。使用者无需这些构建工具。

```sh
./scripts/package.sh --channel dev --profile core --target darwin-arm64
# 缓存齐全后，禁止下载：
./scripts/package.sh --channel dev --profile core --offline
# 对已有归档单独复验：
./scripts/package-smoke.sh dist/teamx-dev-<commit>-dirty-darwin-arm64-core.tar.gz --report /tmp/teamx-report.json
```

`--target` 默认当前原生 OS/架构；所有四个纳入目标共用入口，拒绝跨目标部署。
`--channel` 支持 dev/release，`--profile` 支持 core/full（默认 full）。
P1 显式使用 core。full 因 Git 对应源码/构建/通知材料未齐而失败，组装适配留到 P2；
release 另要求干净源码、精确 tag 和 lock 的完整验收门槛，因此当前不产出正式发行包。
`--cache-dir`、`--output-dir` 可指定绝对路径；默认 `.packaging/cache/`、`dist/`。
参数错误、依赖缺失、缓存损坏、任一验证失败均非零退出；只在最终 tar.gz smoke 通过后
才发布本地归档、归档 SHA-256 和成功报告，不创建远端资产。同名输出使用排他构建锁；smoke 失败的候选仅保存在 `.packaging/last-failed.tar.gz` 供诊断，不进入成功产物。

使用者解压后执行：

```sh
./start init
# 编辑 .teamx/config.toml 中 runtime.model.base_url、runtime.model.model_id
export OPENAI_API_KEY='自己的密钥'
./start doctor
./start
```

不进行编码、也不使用 Git Workspace 时无需 Git。core 中缺少 Git/glab/lark-cli
仅显示为可选能力缺项；Scion 标为暂缓。平台登录、连接和通知订阅均由用户显式配置。

`start` 可从任意 cwd 调用并支持空格路径，前置包内 bin/Node 后 exec TeamX。
Go 的内部 bundle 入口负责初始化、诊断、持有 home 锁并运行现有 serve；shell 不拼接命令。
`teamx init`、`teamx doctor` 也可直接使用 `--bundle-root`、`--home`；doctor 另支持 `--config`。
默认 home 为包内 `.teamx`，显式 `--home` 使用独立私有目录，允许包本体只读。
便携配置的 DSH 路径相对配置目录；外部 home 使用这次 bundle 的绝对 DSH 路径。

配置由 TOML 序列化生成，模型地址/名称留空；未配置时显示配置位置和具体缺项并退出。
初始化用 home 锁和完整临时文件的原子发布，只补缺失文件，保留用户配置、模板和私有数据。
默认启动期间持续持有同一 home 的 `.bundle.lock`，退出后释放，服务数据锁沿用既有合同；两个锁独立，允许显式配置 data_dir 为 home 本身。

## 产物与检查

- 三个自有 Go 程序、公开模板、配置样例和许可证仅从明确清单构建/复制，不读取工作区 bin/config/data。
- Node 完整归档按预审 SHA-256 校验；DSH 用固定 package-lock 执行生产 `npm ci`，禁用安装脚本，保留依赖、profile 和运行资源。
- 原生模块使用 integrity 锁定的 optional 包/prebuild；仅补 node-pty spawn-helper 的可执行权限，不下载或编译备用二进制。
- 保留运行时原有许可材料，另列实际安装包的版本、license 声明及许可/NOTICE 文件路径和摘要。
- manifest 记录 commit/dirty、已跟踪源码差异摘要、参与编译的本仓库 Go/嵌入文件摘要、允许资产摘要、依赖来源/版本/运行时摘要、团队和待验证系统基线。TeamX 支持 `--version`。
- checksums.txt 为 JSON 清单，记录每个不可变文件的摘要/模式和符号链接目标；不包含自身和启动后生成的 home。
- 从最终归档解压到新空格路径，校验摘要、权限、内部链接；在独立 HOME 与不含 Go/Node/Git/平台 CLI 的 PATH 下检查入口。
- 随包 Node/DSH 的版本和帮助可用；GitLab 扩展的独立帮助可用；缺少 glab/scn 时，封装的原生帮助按契约返回依赖缺失，core 不伪装原生能力已齐。
- 实际执行 flock、sharp 单像素编码、node-pty shell 和随包 ripgrep；真实 DSH 仅检查版本/帮助，不发送模型请求。
- 服务 smoke 覆盖所有模板、首页/管理 HTTP、建 Room、SIGINT/SIGTERM、端口释放、同 home 排他、数据重启与初始化保留；独立 home 用固定 ACP fixture 检查 prompt/close 和子进程退出。

报告将 fixture、真实 DSH、平台和浏览器分别标记。fixture 不进入发行归档，也不替换包内真实 DSH；
它仅用于单独 home 的接线检查。已有 Room/平台连接的绝对路径限制与升级规则保持原计划。
