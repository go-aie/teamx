## 本地入口

构建机依赖沿用 P1。原生目标环境中执行：

```sh
./scripts/package.sh --channel dev --profile core --target darwin-arm64
./scripts/package.sh --channel dev --profile full --target darwin-arm64 --offline
./scripts/package.sh --channel dev --profile core --target linux-arm64 --offline
./scripts/package-smoke.sh dist/<包名>.tar.gz --report /tmp/teamx-report.json
```

`--offline` 只消费已校验的固定归档、当前目标 npm 缓存及 Go 模块缓存；首次部署其他目标须准备该目标缓存。失败不发布候选归档或成功报告。release 仍要求干净精确 tag 和完整验收，不因 dev full 成功而放开。

## 新确认的 Linux full 阻塞

实际下载并核对 Linux arm64 Git tar.gz 的 SHA-256，检查 ELF 和运行依赖：Git 主程序需要 zlib/glibc；HTTPS helper 需要 libcurl.so.4，并间接依赖 SSL/crypto、HTTP/压缩、LDAP/Kerberos 等库。固定 dugite 归档不含这组库。在已经装有 curl 的构建机上通过 `--version` 不代表这些库随包提供。

统一 lock 为两个 Linux 目标增加 `git_tls_runtime`，full 在创建 staging 或下载之前即拒绝。core 不受此项阻塞。后续需收集并锁定可搬移库及对应再分发材料，配置包内库搜索路径，再用干净基线执行 HTTPS helper/TLS 验证；不能复制开发机 `/usr/lib` 或以宿主库可用消除门槛。macOS 使用已声明的系统库，保持方案允许的系统依赖边界。
