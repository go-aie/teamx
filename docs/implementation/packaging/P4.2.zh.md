## 构建与资格边界

`.github/workflows/release.yml` 在推送 `v*` tag 时触发；脚本进一步限定版本为 `vX.Y.Z`。必须存在 `refs/tags/<版本>`，解引用后指向当前 HEAD，工作树干净，包括没有未跟踪源码。轻量及附注 tag 均支持，同名分支不能代替 tag；构建和下载 job 固定检出 checks 输出的完整 commit。

从统一 lock 生成四目标 × core/full 的 8 项矩阵，复用 `package.sh`、原生 runner 检查及现有 smoke。所有目标保留，`fail-fast=false`；Linux full 的 `git_tls_runtime` 继续阻塞，不回退 core，也不缩减交付矩阵。依赖缓存按候选渠道、OS/arch、target/profile、Node 版本和 lock 摘要隔离，恢复后仍校验依赖。

新增入口：

```sh
./scripts/package.sh --channel release --candidate --version vX.Y.Z \
  --profile core --target darwin-arm64 --macos-signing unsigned \
  --output-dir /absolute/new-candidate-directory
```

`--candidate` 仅用于 release 渠道，允许先组装尚待归档级真实验收的候选；仍执行依赖、full 完整性、干净 tag、目标、固定构建工具、`-trimpath`、源码稳定性及最终归档 smoke 检查。普通 `--channel release` 仍执行原有 `--require-ready`，没有开启正式发行。候选 manifest 标记 `distribution.kind=release_candidate`、`release_ready=false`，不覆盖已有版本产物；后续重建必须使用新的输出目录并重新验收。

Workflow 只授予 `contents: read`，不创建 Release、不上传 Release assets、不发模型 prompt、不登录 GitLab／飞书。原生 runner、Actions 完整 SHA 和快照能力复用 [P4.1](P4.1.zh.md)。tag 触发规则见 [GitHub 官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)。改动须先进入 GitHub 仓库；本机 GitHub remote 为 `upstream`，`origin` 是 GitLab。本次没有提交／推送或触发远端任务。

## macOS 签名与公证

默认 `unsigned` 表示没有完成 TeamX Developer ID 签名／公证；不删除下载隔离标记，不将上游已有签名或 Go 的 ad-hoc 签名视为本发行物已验收。该模式可以构建待验候选，但资格报告保留签名、公证和下载后系统安全缺项。

仓库变量 `TEAMX_MACOS_SIGNING=developer-id` 可启用完整签名路径：

- 变量 `TEAMX_SIGN_IDENTITY`：完整 `Developer ID Application: 名称 (TEAMID)`。
- secrets `TEAMX_MACOS_P12_BASE64`、`TEAMX_MACOS_P12_PASSWORD`：Developer ID Application 证书及私钥的 PKCS#12 导出和密码。
- secrets `TEAMX_APPLE_API_KEY_BASE64`、`TEAMX_APPLE_API_KEY_ID`、`TEAMX_APPLE_API_ISSUER`：App Store Connect API 私钥及对应 ID／Issuer。证书在 Apple Developer 账号的 Certificates 中创建；API key 在 App Store Connect 的 Users and Access / Integrations 中创建。仅写入 GitHub Actions secrets，不贴到聊天或仓库。

Workflow 在 runner 临时目录创建独立 keychain，以私有文件短暂解码凭据，导入后立即删除 P12/P8，最后无条件删除 keychain。凭据命令屏蔽 argv／输出，公开材料不包含私钥、密码或 notary profile。准备、签名或公证失败均直接失败，不重试为 unsigned。Linux 不读取 Apple secrets。

本地可预先准备独立 keychain 和 notary profile，再设置 `TEAMX_SIGN_IDENTITY`、`TEAMX_SIGN_KEYCHAIN`、`TEAMX_NOTARY_PROFILE`，使用 `--macos-signing developer-id`。本地密钥管理由操作者负责；`package-signing.mjs prepare` 是 Workflow 使用的临时凭据入口。

签名在最终 manifest、运行时摘要、checksums 和 tar.gz 之前执行：扫描实际 Mach-O，包括 Node、三个 Go 程序、原生 addon、动态库和 helper，保留脚本及链接；启用 hardened runtime 和安全时间戳，逐文件严格核验。仅 Node 使用 `node-entitlements.plist`，保留 V8 JIT／可执行内存及 DSH 动态 addon 缓存所需的例外；没有复制 Node 上游的调试授权。参考[固定版本 Node 的 entitlements](https://github.com/nodejs/node/blob/v24.22.2/tools/osx-entitlements.plist)。签名改变的运行时以新摘要进入 manifest，不能沿用 unsigned 包的结论。

完整目录封装为临时 ZIP，经 `notarytool submit --wait` 返回 `Accepted` 才生成最终 tar.gz；外部 security 报告将 submission ID、ZIP 摘要、签名文件摘要绑定最终归档 SHA-256。根据 [Apple 公证说明](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)，ZIP 及裸 CLI 不能像 app/DMG 一样直接 staple；此路径明确记录在线票据，不伪造 stapled 状态。下载后干净机器的 Gatekeeper／quarantine 验收仍须单独执行。

当前未提供 Apple 签名凭据，Developer ID／真实公证路径尚未执行。代码、负向检查与 unsigned 归档验证不能替代该项真实验收。

## 最终资产与下载复验

每项候选包含五个文件：最终 `.tar.gz`、`.tar.gz.sha256`、`-report.json`、`-security.json` 和 `candidate.json`。receipt 记录 tag 版本、完整 commit、target/profile、完整 manifest、依赖和源码输入、归档及原始报告摘要，不改变原 smoke／安全报告。归档包含现有许可证材料和首次使用说明。

上传的是已封装归档，artifact 名包含版本、target/profile、run attempt，保留 30 天。新的原生 verify job 只下载同次 attempt 的 artifact，不恢复构建缓存、不重建包。核对文件集、归档摘要、不可变内容／权限／链接、干净 tag、程序／运行时／配置输入、当前 lock、smoke 验证器及签名材料后，重新执行隔离 smoke；执行后再次确认资产和 receipt 未变。

重跑需连同候选构建和复验整次重跑；只重跑失败 job 时，前次成功构建的 artifact 不属于新 attempt，会明确报缺失。

```sh
node scripts/package-release.mjs plan vX.Y.Z
node scripts/package-release.mjs record DIR TARGET PROFILE FULL_COMMIT vX.Y.Z
node scripts/package-release.mjs verify DOWNLOADED_DIR TARGET PROFILE FULL_COMMIT vX.Y.Z NEW_REPORT.json
```

输出报告必须不存在。下载复验只证明传递身份和 smoke，报告仍为 `release_ready=false`；原报告保留。GitHub 下载方法见[官方说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)。

## 真实验收证据

正式候选的程序、构建选项、版本元数据和归档与 P3 开发包不同，不能复制旧包的“通过”。对下载的同一候选，重新执行现有 `package-acceptance.sh`，使用独立私有输出目录和显式模型配置。然后核对证据：

```sh
node scripts/package-release.mjs assess DOWNLOADED_DIR TARGET PROFILE FULL_COMMIT vX.Y.Z \
  NEW_ASSESSMENT.json /absolute/private-acceptance-directory
```

省略最后的私有目录时只列出缺项。提供后会校验顶层报告的归档、manifest、依赖、源码、原生 OS/arch 和全部验证器摘要，以及 smoke、真实 DSH、实际浏览器子报告摘要。真实 DSH 必须包含前台工具取消、进程退出、原 Session 新输入恢复和结清证据；fixture／跳过／部分成功、不同归档或验证器已变均拒绝。公开 assessment 仅保存摘要和状态，不复制模型回答、Session、账号、日志或截图。

目前证据导入覆盖 P3 已有的收窄本地范围。干净机器、下载后系统安全，以及 full 的 Git/TLS/clone 和平台登录／只读／绑定仍列为缺项；没有通用“手填 passed”入口。`assess` 对当前未完成资格返回 2，格式或身份错误返回 1；`release_ready` 始终为 false。后续补齐这些专门验收和正式资格汇总属于剩余出口工作。

Workflow 的下载 smoke 与资格步骤分开记录；当前资格步骤会因缺少上述验收返回失败，并继续上传 download-report 和 candidate-assessment。缺失候选 artifact 不读取旧运行补齐，单目标成功不使矩阵通过。即使所有候选已能构建，也不能把 Workflow 的 smoke 结果当作 P3 或正式发行资格。
