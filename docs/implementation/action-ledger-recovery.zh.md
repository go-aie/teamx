# 动作 ledger 的存储恢复与进程恢复分工

2026-11-24，实施测试改造方案 §11.5 的 F3，选定 Lark 文本自发消息恢复族。F2 没有迁移该族的 Python 原生夹具；本轮也不迁移 CLI、不扩大四槽、不修改生产授权或持久化实现。

## 风险与覆盖承接

| 原昂贵分支 | 当前承接 | 保留的独有边界 |
| --- | --- | --- |
| `TestLarkSelfSendLedgerFailures/intent` 的恢复子进程 | 关闭旧 manager、service 和 Store，在原目录重新创建真实组件；查询实际 actions list | 第一次 intent 写失败不能留下记录，也不能发送 |
| 同组 `attempt` | 同样关闭重开，跨 turn 两次回放原 ID，读取真实 ledger | attempt 未持久化不能发送；恢复为 `not_applied`、Attempts 为 0 |
| 同组 `result` | 同样关闭重开，读取原请求与结果 | 已发送但 result 未落盘，恢复为 `unknown`、Attempts 为 1；不能补发或捏造结果 ID |
| 同组 `result_commit_unknown` | 保留 rename 后目录同步失败的实际文件故障，关闭重开 | 原结果已可重读时恢复 `succeeded`，消息 ID 仍为 `om_receipt`，不能重发 |
| 文本 `settled`／`before_dispatch`／`after_dispatch` | `TestLarkSelfSendIndependentProcessRecovery` 原三项 OS 进程矩阵 | 成员恢复、进程 epoch、真实死亡、未结清 HTTP、孤儿原生 CLI、原 ID 回放和 unknown 换 ID 禁止补发 |
| Lark 图片两种格式、self／group、上传中／POST 后／验证前中断 | 原 10 项独立进程恢复全部保留 | 原图顺序、已知消息 ID、存储格式、目标种类、object/native pin 释放和禁止继续上传／发送 |
| GitLab 图片 comment／thread、上传中／POST 后／验证前中断 | 原 8 项独立进程恢复全部保留 | provider HTTP 与准确讨论分支、完整原意图、回执重读不进入 preparer、pin 释放 |
| 内容、身份、目标与拒绝规则 | 既有 `TestActionDispatchFrozenContentAndExactRecord`、`TestActionsLedgerFailureNeverReplays`、Lark provider self/send/reply 测试；原上层配置与撤权检查保留 | 不将通用 ledger 当作不同 provider／目标／格式等价的证明 |

源码依据：`service.executeReferenceAction` 在准备原生会话之前调用 `Store.existingReferenceAction`；该路径从真实 records 文件恢复，并由 `validateStoredAction` 检查成员、目标、账号、请求、提交次数和结果的一致性。四类故障的原请求均已返回，其后旧 manager 的正式 shutdown 结清组件并释放文件锁。新 manager 和 service 使用新的 Store 与 epoch，沿用独立进程 helper 的 `newService(...persistentScheduling: true)`，没有换成内存回执或跳过成员恢复。因此这里只去掉已结清场景外围的 OS 进程；死亡、未结清调用和跨进程风险仍由原进程矩阵证明。

本轮补强文本两组恢复断言：读取原 ID 的完整 ledger，核对原正文、operation、target ref、成员、账号、自聊目标和 capability basis；成功结果必须保留原消息 ID，unknown 不得出现虚构结果；相同 ID 改正文必须拒绝。原生 fixture 的实际消息还核对正文、chat、作者与 ID。intent 失败明确查询空 ledger，四个故障点明确断言注入发生。

## 健康修复与测量口径

首次运行发现 GitLab 图片恢复的 8 个分支在附件准备时就返回 403 identity，未进入恢复断言。相关图片共用 HTTP 夹具和恢复子进程改用既有 `fixtureHTTPHandler`，显式提供组件主体；文本族的 HTTP 入口也统一使用它。正式入口的主体、Space 和成员检查没有放宽。共用图片夹具的全部直接测试调用方另作回归；失败提前退出的原样本不参与提速对照。

这些主体接线修复针对当时并行开发的 Space 迁移，随该迁移保留在工作区；本次 F1–F4 独立提交沿用 HEAD 已有的 HTTP 夹具接线。下列计时和哈希仍按原完整工作树保留，不当作独立提交快照的性能对照。

计时对照在身份修复和新增回执断言之后建立：改前继续使用四个恢复子进程，改后改为真实组件重开。选择由当前七份测试文件枚举，包含文本恢复与配置、通用 ledger／dispatch、恢复期读取，以及两家 provider 的图片进程恢复，共 14 项顶层测试。两边均执行同一选择、包含关闭清理和一次生产 CLI 构建；预编译的 Room 测试二进制构建单列，不混入执行墙钟。没有移出测试、改变标签或退休额外验收。

本轮少启动 **4 个恢复服务 OS 子进程**；完整选择中的恢复服务子进程从 64 个降到 60 个。这里不包含原生 CLI 子进程，未减少原生调用来取得收益。先前已收缩的 14 项图片发送、10 项 Lark 图片恢复不再次计入新收益。

| 普通对照 | 改前 → 改后 | 结果 |
| --- | --- | --- |
| 同范围 14 项顶层／含子项 58 项 | 墙钟 130.573 → 161.787 秒；包执行 130.340 → 161.603 秒 | 两边全部通过，零失败／跳过；整组变慢，不能称为提速 |
| 仅四种 ledger 故障，顺序各执行一次 | 墙钟 21.048 → 20.393 秒；包执行 20.805 → 20.039 秒 | 两边 1 项顶层／含子项 5 项全部通过；只少约 0.65 秒，尚不足证明稳定收益 |
| Room integration 测试二进制构建 | 20.23 → 39.33 秒 | 均通过；构建单列，不算作执行改善 |

完整选择的未修改项也存在明显变化：GitLab 图片进程恢复 17.03 → 29.88 秒、通用 dispatch 4.92 → 7.58 秒。ledger 组顶层 Elapsed 为 26.54 → 30.83 秒，但四槽日志记录的持槽跨度为 26.542 → 23.534 秒，改后另等待准入约 7.301 秒；不能把等待差异归为恢复算法变化。补充的单组顺序对照排除这一等待后仍只有亚秒差异。没有证据确定波动来源，也不再重跑整组寻找更好数字。

**本轮交付的是恢复职责收敛和断言补强，没有证明稳定的整族净提速。** 不将四次服务进程减少外推为分钟级收益，不继续扩散，也没有冗余测试退役或额外验收移层的收益。若后续继续处理该族，应重新定位反复配置、身份读取和原生目标流程的成本，不继续机械削减真实恢复边界。

### 同范围复跑与保留决定

为核对运行时间波动并评估是否撤回，复跑复用上轮保存的两个测试二进制和同一选择，不同时运行其他构建或检查；完整选择与 ledger 单组均按「改后 → 改前」执行，与首轮顺序相反。当前源码只比上轮对照版本多了前述同值 `ImageRef` 命名字段修正；全部四次运行前后记录的相关源码摘要均未变化。

| 范围 | 首轮：改前 → 改后 | 复跑：改前 → 改后 |
| --- | --- | --- |
| 14 项顶层／含子项 58 项完整选择 | 130.573 → 161.787 秒 | 128.934 → 120.867 秒 |
| 四种 ledger 故障，1 项顶层／含子项 5 项 | 21.048 → 20.393 秒 | 22.655 → 22.115 秒 |

四次复跑全部通过，零失败／跳过。同一个改后二进制的完整选择从 161.787 降至 120.867 秒，变化约 40.920 秒；改前从 130.573 变为 128.934 秒。首轮的约 31 秒退化没有复现，说明不能把那一轮整组差值直接归因于 F3；也不能用本次约 8 秒改善承诺稳定的整组收益。两组 ledger 单独对照方向一致，分别少约 0.655／0.540 秒，符合只移除少量外围进程开销、主要装配与原生流程成本仍保留的判断。样本只有两组，不确定波动来源，不作统计显著性或零回退保证。

**决定保留 F3 的恢复方式替换，不撤回；继续停止扩散。** 已有覆盖与 race 证据仍适用，复跑没有修改测试实现。此前仅凭一轮整组变慢就建议撤回，证据不足；同样不能把职责调整描述为已通过整组提速验收。额外检查发现恢复组件显式关闭后还会由 `testManager` cleanup 再次关闭，这是真实的冗余路径，但尚未量化其成本，不能用它解释首轮约 31 秒差值。

### 实现验证与剩余门槛

改后实现的定向 integration race 已通过：Room 24 项顶层（上述完整选择与 GitLab 图片共用夹具的全部 10 项直接测试调用方）、Lark provider 10 项顶层，合计 34 项顶层／含子项 200 项，零失败／跳过、无竞态报告。命令含构建墙钟 239.709 秒，Room 包执行 210.221 秒，Lark 包执行 2.820 秒；这是验收成本，不是普通对照的提速数字。

随后 Room 范围 integration vet 发现同一图片测试文件的既有 `ImageRef` 使用位置字段字面量。已改为相同数值的 `MessageSeq`／`AttachmentID` 命名字段，该 bad-id 分支的定向 race 与最终 integration vet 均通过；这项语法修正不计提速。默认及最终 e2e 编译也通过，只证明标签接线，不代表浏览器或平台验收。

验证结果与源码摘要见[机器证据](action-ledger-recovery-evidence.json)。本轮仅交付这一恢复切片，不自动扩展其他 ledger／provider 族；F4、F5、完整核心／integration／全仓 race 及真实平台、模型、浏览器仍待各自验收。
