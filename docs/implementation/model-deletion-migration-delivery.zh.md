# 模型删除、迁移与交付

实施范围：模型方案阶段 4。删除替换、一次迁移、旧 Session 恢复及发行流程已实现；验收按组件、真实模型、浏览器和发行包分别记录。未修改原部署数据，未提交或推送。

## 行为

- 删除复用模型变更记录与 rotation：验证替代条目，持久标记待删除，原子改变默认，再按完整成员身份和选择版本替换固定引用。默认模式保留，独立成员分别完成；失败只保留自身门禁，重试沿用固定 generation，已完成者不再轮换。全部引用及待应用成员结清后移除定义，保留历史快照与凭据。
- 列表提供删除影响预览、替代选择、待删除及重试进度。未打开房间也参与引用核对；模板固定引用明确阻止删除。待删除条目不能被新增引用、编辑或设为默认。相同执行配置只替换引用，不立即轮换；其后自然轮换按当前成员引用生成快照，不继续产生引用已删除条目的新 Session。已受理模型操作仍使用原固定目标。
- 当前旧结构在恢复 Room 前一次迁移。全局导入默认，旧房间／模板按实际参数与有效密钥去重；不同者固定引用额外条目。兼容设置保留未指定／false／true；原变量名只留在旧 Session 运行快照中。
- `model-migration.json` 保存固定目标、输入摘要与本地进度；原字节放在私有 `model-migration-backup/`，目录 0700、文件 0600。文件按原摘要或已完成目标幂等核对，配置发布最后完成，外部改动不能被覆盖。中断先续接本地事实；冲突时只提供认证后的进度与显式重试，业务恢复保持阻断。
- 导入不联网、不伪造验证；缺失密钥保留可修复状态，只阻断依赖执行。原 Session 用原配置及原指纹恢复，通过不可变凭据绑定注入原变量名，原 DSH 的二进制、配置及 ACP 身份校验仍生效。首次验证后的新代际使用服务内部变量名。尚未启动的旧代际须获得已验证目标，不套用旧恢复权限。
- Workspace 历史回执不重写。迁移保存原 runtime 摘要，只允许与该精确来源对应的比较归一化；身份、工具、Workspace 等其他字段继续完整校验。
- 模型保存、时区与删除继续共用配置来源检查、锁和局部 TOML patch。缺失验证回执可用原条目重新验证修复；不会因此停掉其他模型或把修复误记为执行 revision 变化。
