# GitLab 使用指南

让 Agent 接收个人待办或项目活动、核实上下文并处理事务，也可以在「软件开发」房间中分工开发和评审代码。

## 准备环境

先完成 [TeamX 安装和模型配置](installation.zh.md)。standard 包已包含 GitLab 工具；core 或源码运行时，在服务机器安装 **glab 1.127.0** 与 TeamX GitLab 工具，方法见[工具手册](../tools/gitlab/README.zh.md)。需要克隆或修改仓库时，还须安装 Git。

接收通知不依赖工具二进制，也无需先克隆仓库；Agent 补读平台上下文及执行操作需要为该成员启用相应能力。

## 连接账号并为成员启用

1. 进入个人助理或任务房间，打开成员详情的「平台」Tab，点击「添加平台」。已有账号时直接选择并「添加并启用」；否则选择「连接新平台 → GitLab」。
2. 填写平台名称和 GitLab 实例地址，点击「连接并启用」。按页面提示完成 OAuth 授权；同一实例有唯一兼容应用时可直接登录，没有应用时填写 Application ID、Secret 和页面给出的回调地址。多个兼容应用需明确选择。
3. 核对实际账号及接入结果。首次默认接收「我的待办」到当前成员收件箱，并启用平台工具；项目互动默认关闭。账号、通知和工具分别显示结果。

添加前可以分别取消通知或工具，并调整首次接收时间。已有的开关和范围保留，添加操作不会重开关闭项。接入不改变成员的协作开关；需要助手处理时，在成员详情启用协作。

也可从全局「设置 → 平台」先连接账号，再回到成员详情添加已有平台。全局连接本身不订阅通知或启用成员工具。

### 选择 OAuth 权限

| 权限 | 用途 |
| --- | --- |
| `api` | GitLab API 读写，必需 |
| `write_repository` | HTTPS 仓库拉取和推送，新配置默认勾选；不需要时可取消 |

GitLab 应用需开通所选权限，页面回调地址也须匹配当前访问入口。修改权限后重新授权；已有仅 API 授权不会自动扩权。权限或回调不匹配时按页面原因修正。

## 接收待办与项目活动

在「成员详情 → 平台 → 对应平台设置」调整接收内容：

- **我的待办**：所选账号在所有可访问项目中的待办，不受 Workspace 项目限制。
- **项目互动**：搜索并选择一个项目，接收 MR、评论和 push 等活动，无需手填项目路径。
- **开始接收时间**：首次开启前选择从开启时刻、最近 1 小时、最近 24 小时或指定时间；保存后起点锁定，暂停或重启沿用进度。

在「收件箱」查看已保存通知，启用协作后由助手读取和跟进。只预览不会确认消费；收到、读取、处理完成和远端 Todo 完成是不同状态。时间范围只筛选要接收的通知，不代表接收账号全部历史未完成待办。

同一账号可供多个成员独立订阅，各自的开关、范围和进度互不覆盖。在房间和私信中，项目活动和待办都进入接收成员的收件箱。通用处理方式见[平台通知与跟进](notifications.zh.md)。

## 发送图文评论

在会话中发布图片后，可以要求助手“把这段说明和上面的两张图一起评论到这个 MR”，或“只把第二张图回复到这条讨论”。明确目标和图片选择后，助手使用当前成员已启用的 GitLab 账号，一次发布完整评论，并返回评论链接和核实结果。

可以直接提供完整 MR 链接，或带 `#note_评论ID`／`#discussion_完整讨论ID` 的链接，助手核实当前账号和目标后发布普通评论或回复准确讨论；无需先订阅通知、建立事项或配置 Workspace。文字评论也使用这一入口。不支持的锚点、不可访问的目标或独立普通评论会说明原因，不会自动改发到 MR。

每条最多 4 张当前会话保留的人类原图，支持 PNG、JPEG、WebP，单张不超过 2 MiB、合计不超过 4 MiB；保持原始字节和选择顺序。纯图片无需说明文字。

图片外发须由会话中的人类直接明确要求；长期规则、持久指令和问答授权仍只适用于原有文字能力。链接须为所选账号同一实例的完整 HTTPS MR／讨论地址；不支持查询参数、短链或模糊 IID。Issue、通知图片和磁盘文件不在这项能力范围内。

失败时不会改发文字或部分图片；上传后未发布的附件可能保留。结果未知时先查询原动作回执，避免补发。本人账号的评论通知只作为进度上下文，不产生新的自动回复或待办。

## 开发与评审代码

1. 新建「软件开发」房间，为需要读写 GitLab 的成员添加平台并启用工具。
2. 打开输入框下方的 Workspace，填写 HTTPS 仓库地址，选择连接并应用；等待各成员的独立工作副本准备完成。
3. 在房间描述需求和交付条件，让成员设计、实现并独立评审。需要你决定时，成员在房间中 @ 你。

成员通过 `teamx workspace-git fetch/push/ls-remote` 执行网络 Git，本地 diff／commit 使用 Git。Workspace 认证与成员平台工具分别配置，互不自动启用。目录保护、应用进度和失败重试见 [Workspace 指南](workspace.zh.md)。

## 管理账号与排查

已有平台提供「重新授权」「退出登录」「修改应用配置」。共享连接变更会展示引用房间，先核对影响范围。更换应用或 Secret 时，填写后点击「更新并授权」，核验成功才更新原配置；Secret 不回显，重新填写时以页面表单为准。

原账号重新授权成功后，因凭据问题暂停的项目活动和个人待办会自动恢复，沿用原接收起点、历史进度和积压。服务启动也会核对并恢复连接已正常、但仍保留本地凭据暂停状态的订阅；GitLab 明确拒绝凭据或授权结果尚未确认时，仍需先完成原账号授权。主动关闭、已退役或原接收成员已移除的订阅保持原状态。

授权结果会分别说明账号连接、原有通知恢复和接入设置是否完成。若账号已保存，但部分通知或接入设置尚未完成，在对应会话同步通知或继续原接入操作即可，无需重复登录。授权返回页只提供返回入口，最终以 TeamX 中的结果为准。

授权过程中刷新页面会查询原会话；服务重启后会重新读取连接列表，并提示原授权会话已结束，不自动重放授权。取消或保存结果未确认时，先核对连接状态，再决定是否重试。

| 现象 | 处理 |
| --- | --- |
| 账号已连接，但没有收件或工具不可用 | 核对准确成员的通知、工具开关和账号权限；连接成功与成员启用分别判断 |
| 接入部分失败 | 查看原接入进度并继续，保留已成功步骤，无需重新登录 |
| 收到通知但助手未处理 | 核对协作是否启用，以及成员的模型错误或暂停原因 |
| 工具缺失或版本不符 | 在服务机器按工具手册准备固定版本，调整服务环境后重启 |
| 操作超时或结果未知 | 先核对原回执和远端结果，避免重复评论或推送 |

GitLab 仅支持 OAuth。旧数据须先停服、备份，再按[平台格式升级](platform-architecture.zh.md#停服升级)处理；旧 PAT 连接保留引用但需重新登录，升级不撤销远端 PAT。

当前 OAuth 简化后的真实账号和 Git 网络链路仍有待复验，已有组件结果不替代这些验证。范围见[当前待验项](../internal/room/README.zh.md#当前待验项)、[Workspace 验收](reference/workspace.zh.md#真实验收)和[GitLab 工具验收](../tools/gitlab/README.zh.md#真实验收)。
