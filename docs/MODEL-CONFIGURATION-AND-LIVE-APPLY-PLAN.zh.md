# 模型列表、首次引导与 Agent 在线切换方案

状态：阶段 1–4 已实施，阶段 4 已通过本机 darwin-arm64 standard 的 smoke、生产浏览器及真实首次使用验收；其他发行环境和实测边界见阶段 4 记录。根据 2026-11-12 的多轮讨论与代码检查统一修订；本文继续作为后续开发依据。阶段 1 的实现、隔离验证及未开放边界见[配置与验证基础记录](implementation/model-configuration-foundation.zh.md)；阶段 2 的首启、浏览器和真实对话证据见[首次使用闭环记录](implementation/model-first-use.zh.md)；阶段 3 的在线管理、成员切换与验证证据见[在线模型管理记录](implementation/model-live-apply.zh.md)；阶段 4 的删除替换、一次迁移及交付证据见[删除、迁移与交付记录](implementation/model-deletion-migration-delivery.zh.md)。

## 1. 目标与取舍

设置页面集中维护模型列表，并选定一个默认模型。每个 Agent 实例选择“使用默认”或固定引用一个模型条目。配置与凭据验证通过后保存；实际模型变化时，相关 Agent 各自在当前执行结束后轮换 Session，无需重启服务、重建 Agent 或逐个房间修改。

本方案推荐实施，完整功能的复杂度为中高。模型列表和引用较简单，主要成本在安全切换、凭据隔离和重启恢复。先验证关键路径，再按小闭环实施，不同时重构整个配置、调度或权限系统。

确定以下边界：

- `config.toml` 保存唯一的模型列表与默认引用；不新增独立的全局模型文件，不提供房间共享模型配置。
- Agent 只保存选择方式和条目 ID；Session 保存自己的实际运行快照。它们分别是定义、引用和执行事实，不是三套模型配置。
- 模型选择按 RoomIdentity／AgentID／MembershipID 区分实例，同名角色或同房间成员互不等同。
- 首次与后续维护复用验证、凭据、保存机制；首启直接运行 `./start`，模型问答统一放在网页。
- 保留现有 Room、Inbox、业务动作和 turn 调度职责；扩展既有 Backend／rotation，不建立第二套 Session 状态机。
- 不包含模型自动路由、成员自填 URL／Key、提示词编辑、自动摘要迁移、通用配置事务框架或完整多版本 DSH 兼容平台。

本方案替代此前的“全局只初始化新房间”“房间保存完整模型”和“人工批量下发房间配置”设计。[Agent 提示词方案](ROOM-AGENT-CONFIGURATION-PLAN.zh.md) 的模型说明以本文为准，提示词编辑不作为前置任务。

## 2. 用户规则

### 2.1 集中模型列表与 Agent 选择

全局设置中的模型列表不依赖选中房间，展示名称、实际模型 ID、默认标识、验证概况及使用者数量，提供新增、编辑、设默认、查看使用者和删除。条目使用稳定内部 ID，区别于上游 `model_id`；改名不改变引用，首版不支持修改内部 ID。

模型表单维护协议、Base URL、模型 ID、API Key；高级设置覆盖 `input_modalities`、`context_window`、`max_tokens`、`reasoning_effort` 与 `compat`。协议默认 `openai-completions`，保留 `deepseek-messages`；省略值继续采用适配器默认，不猜测模型能力。`api_key_env` 不进入基础或高级表单，用户无需理解变量名、执行 `export` 或编辑文件。

普通配置流程为“填地址和模型 ID → 粘贴 API Key → 验证并保存”。系统负责私有保存与内部注入；后续默认显示“密钥已配置”，可复用或显式更换，界面不提供“填写环境变量名”或“先配置环境变量”的前置步骤。

“高级设置 → 接口兼容性”明确提供 `compat.supports_developer_role`，用于控制相关系统指令能否以 `developer` 消息角色发给上游。部分网关仅接受 `system`，此时显式设为 `false`；它不控制 Agent 身份、工具权限或是否开启推理。

| UI 选项 | 持久值与行为 |
| --- | --- |
| 使用适配器默认值（默认选项） | 不设置该字段，保留当前适配器判断，不等同于显式 `false` |
| 不支持 developer | 显式 `false`，相关指令使用 `system` 角色 |
| 支持 developer | 显式 `true`，允许适配器在适用条件下使用 `developer`，不保证所有请求都采用它 |

使用三态选择器，不用只能表达 true／false 的普通开关。该字段仅适用于 `openai-completions`；切换其他协议时提示清除不适用值，服务端拒绝仍携带该配置的提交，不能隐藏后静默保留。修改属于执行配置变化，纳入 revision、候选验证、Session 快照和受影响 Agent 的正常轮换；验证使用所选值，不自动改成其他模式后宣布通过。

成员详情的选择器只有两类选项：“使用默认（当前：A）”和具体条目“固定使用 A／B”。同一房间可以有不同模型。页面同时展示选择方式、目标模型和当前 Session 实际模型；未切换完成不能标为已经生效。

| 操作 | 影响 |
| --- | --- |
| 默认从 A 改为 B | 全部“使用默认”的已有 Agent 自动转向 B，显式选择者不跟随 |
| 修改 A 的 URL、Key、上游模型 ID 或执行参数 | 所有实际使用 A 的 Agent 更新，包括显式选择者 |
| 某个 Agent 从默认改为固定 B | 仅改变该成员实例 |
| 默认为 A 时，某 Agent 显式选择 A | 保存固定引用；以后默认改 B，它仍使用 A |
| A 改名、重复保存，或仅改变选择方式而实际参数／凭据相同 | 更新必要的引用／来源记录，不轮换 Session |

固定引用是固定条目，不是锁定旧 revision。想长期保留另一套参数，应新增条目。选择器保留“使用默认”和“具体 A”两个选项，即使 A 当前就是默认，也不能自动折叠两种选择。

新增／修改执行参数使用“验证并保存”；首次为“验证并开始使用”。纯名称变更不请求模型。保存前说明影响数量和私有上下文重置代价；保存后自动应用，展示已完成、等待和失败数量，不要求逐个房间勾选。

### 2.2 删除与替换

未被引用且不是默认的模型可直接删除；被引用的模型提供“删除并替换引用”，一次选择替代条目 B。没有合法替代时先新增模型，不能直接删除唯一默认模型。

删除 A 时预览所有引用，包括未打开房间的成员和未完成操作；处理规则为：

| 原状态 | 删除 A、替代为 B 后 |
| --- | --- |
| 默认为 A | 默认改为 B |
| Agent 使用默认 | 保持默认模式，随默认指向 B |
| Agent 显式选择 A | 改为显式选择 B |
| Agent 使用其他模型 | 不变 |

先确认 B 的当前执行配置已通过验证，再将 A 标记为“待删除”，禁止新选择和引用；如 A 是默认，在同一次列表提交中把默认改为 B。保存替换目标与进度，逐成员按版本更新显式引用并应用 B，始终保留 A 的定义，直到没有有效引用及待切换成员后才从列表移除。模板的显式引用也须检查；首版可列为删除阻断项，要求先修正模板，不额外开发模板编辑器或偷偷改写模板。

成员等待或失败时 A 显示删除进度，允许重试；已完成成员继续工作。某成员删除／改选造成引用变化时重新核对身份和版本，不覆盖后来设置。重试不重复轮换已完成成员，不把“暂未打开”当作没有引用。删除过程不允许新的操作把 A 再设为默认。

从列表删除不等于销毁旧 Session 的历史快照或凭据；这些按仍有引用的规则保留，不要求先删除诊断历史。删除与替换复用下面的配置提交和成员轮换机制，不另建批量下发引擎。

## 3. 最小数据结构与职责

### 3.1 模型定义与引用

模型列表写回服务实际使用的 `config.toml`，建议结构：

```toml
[models]
schema_version = 1
version = 1
default = "daily"

[[models.entries]]
id = "daily"
name = "日常模型"
revision = 1
protocol = "openai-completions"
base_url = "https://api.example.com/v1"
model_id = "example-model"
credential_ref = "cred-opaque-id"
input_modalities = ["text"]
context_window = 1048576
max_tokens = 32768
reasoning_effort = "low"

# 可选兼容设置；省略此小节表示使用适配器默认值。
[models.entries.compat]
supports_developer_role = false
```

列表 `version` 用于并发保存校验，条目 `revision` 只随实际执行配置／凭据变化；改名不增加执行 revision。完成初始化的非空列表恰有一个有效且非待删除的默认条目。空列表是首次设置状态。删除进度等运行信息保存在操作记录，必要的条目待删除标识必须可持久恢复。

新列表只保存 `credential_ref`，不要求填写或保存用户可编辑的 `api_key_env`。管理表单／请求与内部 DSH Options 按职责映射，不把底层 ModelConfig 的所有字段原样暴露给用户；内部变量名由服务组装运行配置时补齐。

沿用 `room-config.json` 的成员记录保存模型选择及成员选择版本：

```json
{"model_selection":{"mode":"default"},"model_selection_version":1}
```

```json
{"model_selection":{"mode":"explicit","entry_id":"vision"},"model_selection_version":2}
```

新 Agent 默认使用默认模型；团队模板可显式声明成员的条目引用，不再内嵌完整模型定义。模板只初始化新成员的选择方式，后续不会覆盖已有成员自己的选择。DSH 安装、提示词、工具绑定和 Workspace 保持现有归属。

原 `[runtime.model]` 和房间共享模型在明确迁移后退出生效路径，不能与新结构长期逐字段合并或互相回退。Session 中的完整生成快照不接受 UI 编辑，也不反向覆盖列表。

### 3.2 管理层与执行层

| 职责 | 应放位置 | 约束 |
| --- | --- | --- |
| 模型列表、引用解析、验证、影响计算、删除替换 | 管理层的小型模型服务 | 复用现有管理认证；不把模型业务塞进 Room／Inbox |
| TOML 原子保存与内存发布 | 现有配置写入机制提取共享部分 | 与时区、首次设置共用锁、来源检查和局部 patch，保留其他字段及注释 |
| 接收目标配置、等待执行结束、替换 Backend | 成员生命周期边界 | 扩展现有 rotation，保留原暂停／启用意图 |
| Session 实际模型、凭据版本、DSH 身份 | Session 生成快照 | 恢复使用原生成配置，不能用最新列表参数恢复旧 Session |
| turn 排序、Room 消息、Inbox 游标和业务动作 | 现有对应组件 | 不增加模型 ID、默认指针或凭据管理职责 |

列表保存只在短临界区串行；成员等待和模型网络请求均不持有全局锁。成员应用失败不占住部署级配置写槽，允许不重叠的模型维护。首版不排队覆盖同一成员的未完成目标，对重叠变更明确提示先处理原操作；不引入复杂的多 revision 合并／自动回滚。

已有 Workspace 操作按完整配置 `DeepEqual` 校验，成员选择变为可变字段后须按职责调整比较边界，继续保护 Workspace、身份和工具等不变量；不要为了改模型而批量重写历史 Workspace 回执，更不能整体关闭快照校验。

UI 保存成功后更新服务内存快照，不需要重启。首版不监听文件变化；外部手改导致来源冲突时明确报告，按既有方式重载，不能覆盖其他写入或无声退回旧模型。

## 4. 凭据与保存前验证

### 4.1 凭据

Key 存入服务私有目录，目录 `0700`、文件 `0600`；模型只存不可变凭据引用。这是凭据存储，不是另一套模型配置。更换 Key 新建版本，旧 Session 结清前使用原绑定，新 Session 使用新绑定；首版保守保留仍被 Session／操作引用的历史版本，不开发自动清理服务。

增加显式凭据输入，由验证器与真实 Backend 共用解析及子进程注入。当前 `dsh.Options` 校验、Session 脱敏取值和环境构造均读取进程环境，必须一起改造；不靠在线 `os.Setenv`，不把 Key 放入 ModelConfig、ToolEnv、prompt、命令行或操作日志。

DSH 底层仍可通过环境变量接收 Key，但 `api_key_env` 仅是内部传输细节。新运行配置由服务统一指定内部名称（例如 `OPENAI_API_KEY`），并在每个 DSH 子进程中注入该模型绑定的凭据；不同子进程使用相同变量名不会共享可变 Key。验证与执行均不要求宿主环境预先存在这个变量，启动环境中的同名旧值也不能覆盖已绑定的托管 Key。管理 API 不要求客户端传变量名，托管凭据异常时引导重新输入／修复 Key，而不是要求用户 export。

旧环境导入遵循当前“进程环境优先于 `[env]`”规则，包括显式空值；迁移器按旧 `api_key_env` 自动解析现有 Key 并转为托管凭据，不要求用户重复填写变量名。缺失时网页提示补填 API Key。旧 Session 继续保留其生成快照中的变量名与指纹，不能仅为规范内部名称改写历史配置；后续正常轮换的新 Session 使用服务约定名称。验证用什么 Key，实际执行就必须用同一凭据版本。

网页默认复用已有 Key，选择更换才输入；空输入不清空。预填配置展示“密钥已配置”，不要求重填或回显。Key 仅短暂留在表单内存／私有候选文件，不进浏览器存储，失败不发布，成功／退出清除表单值，候选失效后清理。

### 4.2 验证范围与复用

新增或修改执行配置必须先在服务端真实调用成功，失败不提交有效配置、不暂停原本正常的 Agent。只检查 URL、Key 非空或模型列表不足以通过。使用生产适配器与相同物化参数、凭据路径，在独立探测 Session 中验证：

1. 结构、本地 DSH、ACP 握手及模型选择。
2. 简短文本请求，确认 URL、鉴权、模型访问、参数接受和响应解析。
3. 一个固定无副作用的测试工具调用、结果回传及正常结束。
4. 关闭 Session 并确认所拥有的进程结清。

探测不绑定真实 Room，不注入业务工具、管理认证、平台凭据或 Workspace，不发布消息／推进游标。固定测试工具的注册与隔离在阶段 1 开始时验证，当前 ACP 入口没有现成的测试工具接入；不能假设换个提示词就能安全使用任意内置工具。若无法满足，先修订探测实现再继续，不静默跳过工具验证或放开业务工具。

限制提示词、轮次、输出采集、并发与总时间，建议总预算 90 秒并包含清理；不无限自动重试，不通过换模型／协议或删参数后宣布成功。小型调用不能证明百万上下文和完整输出容量；图片输入按适配器声明检查，可用固定小图另记实测结果，不把文本通过写成所有能力通过。

验证结果绑定完整条目执行配置、凭据版本和实际 DSH 身份。首版不单独建设验证票据服务／TTL 状态机：一次“验证并保存”持有不可变候选，保存前再次核对版本。改默认、Agent 改选和删除替换若改变实际执行目标，也在本次操作中确认目标可用；一次探测供本次相同目标的所有成员复用，不逐 Agent 重测。仅改变绑定方式而实际配置未变时无需另发探测。历史验证用于展示，不替代新操作的可用性确认，也不保证下一次服务持续健康；迁移来的未验证条目不能伪造回执。

发行验收以当前托管 DSH 为基线；显式安装复用同一隔离探测确认兼容性，不以 CLI 版本号精确相等作为准入条件。未覆盖的安装不宣称已经验证，不兼容者明确阻断自身切换。完整多版本远端探测矩阵延后，不因一个旧安装失败回滚其他已完成成员，也不偷偷继续开启旧配置 turn。

错误至少区分字段、DNS／连接／TLS／超时、鉴权、路由／模型访问、限流／配额、上游 5xx、参数／角色不兼容、工具／ACP 和清理失败。只返回脱敏诊断，不把上游原始响应或认证头直接展示；超时不等于 Key 错误，单一 404 不证明模型不存在。

## 5. 配置发布与成员安全切换

### 5.1 一次提交、分别完成

每次写操作带稳定请求 ID 和预期列表／成员版本。相同 ID 加相同输入返回原状态，不同输入拒绝。服务持有任务，浏览器关闭或 HTTP 超时不取消已受理操作。

保存一份配置变更记录，记录候选目标、版本、验证概况、受影响成员身份及其目标快照引用；逐成员 Session 结清与 generation 进度继续以现有 rotation 记录为准。管理界面从这些事实汇总状态，不再保存另一套独立的 Session 完成标志。

流程：验证候选 → 核对引用／版本 → 登记受影响成员的新 turn 门禁并持久保存目标 → 原子提交配置并发布内存快照 → 驱动各成员应用。实际参数／凭据不变时只更新引用来源，不轮换。

配置发布与 turn 接纳须协调，防止提交后再接纳旧配置 turn；保存前已经接纳的 turn 允许正常结束。新建成员从已发布列表解析，持久预留中的创建也要核对版本，不能遗漏并发创建窗口。配置结果不确定时保留阻断并核对磁盘，未确认提交前不得破坏旧 Session。

TOML、成员引用和日志不是一个跨文件原子事务：先保存稳定目标与进度，按版本幂等推进，重启核对事实后续接，删除过程保留待删除条目以避免悬空引用。不要为此开发通用事务引擎。

### 5.2 复用 rotation，但补齐两个缺口

当前 `switchSession` 仅换 Session 引用，仍返回旧模型的 Backend；当前 `prepareRotation` 会提前启动平台变更租约，`beginPlatformMemberChange` 又会撤销进行中的平台请求。因此，不能直接调用现有手动轮换接口来实现本方案。

模型切换采用明确的顺序：

1. **停止新 turn**：复用成员接纳／rotation 等待条件，保留用户启用意图，当前 turn 的工具与平台请求继续有效。
2. **等待当前 turn 结束**：此时不启动会撤销平台请求的租约，不提前停止当前执行依赖的工作。只有原执行确已结束，才进入平台结清和 Session 关闭。
3. **关闭旧 Session**：复用既有资源所有权、结清检查与 `prepared → old_closed → completed` 持久步骤；保留旧目录。
4. **安装新运行配置**：扩展轮换过程，使目标 Backend 携带已验证的模型／凭据快照，在固定目标 generation 上完成切换；重试用同一个目标。
5. **解除该成员门禁**：保留期间新增的暂停意图。下一次正常工作才打开新 Session，设置更新本身不发起回合。

具体用受控内部消息或 Backend 扩展接入，在阶段 1 的关键路径验证中确定可行方式，阶段 3 完成正式实现与恢复处理；不新增面向所有业务的配置事件协议。手动取消、删除成员等现有撤销语义保持原有职责，不统一改成等待模式。

空闲成员立即处理，未启动过的成员只更新未来目标；未打开房间用持久状态与结清证据处理，不为改配置而自动启用。每个成员完成即可继续，不等其他房间或同房间成员；生命周期操作可短暂串行，不能用全房间暂停实现模型切换。

### 5.3 上下文、失败与恢复

轮换会丢失私有上下文，包括未公开的进展、临时判断和工具结果；保留公共消息、Workspace、身份、工具绑定、游标和累计使用记录不等于完整记忆恢复。新 Session 明确收到重置提示，按需 `read --latest`／`read --all`，不自动灌入全部历史、摘要或补发模型回合；每 Session 计数沿用现有轮换契约，累计用量不归零。

图片材料已经通过当前 Session 的 `SupportsImages()` 准备，直接保留这条路径。保证新 Backend／Session 使用新能力即可，不另建房间级或成员级能力系统；不支持图片时按现有明确反馈处理，不静默丢弃输入。

验证／提交前失败维持原配置。提交后某成员结清或切换失败，只阻断该成员新 turn；其他成员继续完成，不整体回滚或重放。旧模型下线也不授权自动重试原失败 turn 或结果不确定的外部动作。

重启先核对变更记录与 rotation 再恢复执行。旧 Session 恢复必须用原生成快照，不能用最新列表参数绕过恢复指纹。已完成成员不重复轮换，已替换／删除成员不按同名 Agent 接管。未完成执行步骤由管理页面显式重试同一目标，不自动重放验证／业务任务；纯本地事实核对可自动进行。

取消仅允许提交前；提交后通过查询、修复与重试完成操作。若要回到旧模型，作为新的已验证配置变更处理，不能复活旧 Session。保留必要的固定目标和进度即可，首版不实现自动回滚、失败目标合并或跨操作补偿。

## 6. 首次使用与发行入口

目标主流程：

```text
运行官方 install.sh
→ 内部部署 standard、准备基础文件与首次管理认证、启动常驻服务
→ 浏览器登录 → 配置／复用预填模型 → 验证并保存为默认
→ 幂等初始化默认 Agent（使用默认）→ 自动进入对话
```

设置页不能依赖默认 Agent 或业务 worker 已启动；无模型时服务提供认证后的 `setup_required`，不因启动前模型检查失败直接退出。首次完成用持久状态判断，模型保存成功和默认 Agent 初始化成功分别报告；初始化失败复用已有创建回执重试，不重复创建。

基础文件、模板和现有模型不覆盖。自动认证仅用于确认全新且无历史身份／业务数据的实例，或有持久初始化进度可续接的首启；并发和中断后保留同一个 operator 与 token。已有实例 token 丢失／损坏不能当新实例自动补发，报告部署机修复入口。提取共享初始化逻辑，避免 home 锁递归获取；日志只输出访问地址与私有 token 文件路径，不打印 token 值。

删除终端模型问答及仅为其服务的回显／信号处理代码。`start init` 保留为可选“仅准备基础文件与首次认证后退出”，不启动服务、不调用模型；`--non-interactive` 可保留兼容，但正常模型配置不再依赖它。现有 `access init` 保留显式部署／修复用途，`doctor` 是可选诊断，不发模型请求。

普通安装不再要求用户执行 `start init`；安装器内部调用 `teamx service install`，之后统一用 `teamx service` 管理。保留的开发用 `start` 仍负责其下载隔离确认，带隔离标记的非交互拒绝保持现有行为。当前安装入口、CLI 和网页设置说明以 `docs/installation.zh.md` 为准。

已有实例正常打开／重启不强制联网重验，不因临时断网或回执时间变旧回首次向导。模型／凭据故障在原页面反馈并提供修复；只阻断依赖者，不关停其他独立有效的成员。

## 7. 迁移与管理接口

迁移规则在阶段 1 确定，阶段 4 完成实际迁移与专项验收。前期用隔离的新 home 验证新结构，未通过迁移验收前不向已有数据实例开放新写入。

进行一次有备份、固定目标和可重试进度的迁移：旧 `[runtime.model]` 导入默认条目；旧房间／模板参数和有效凭据与旧全局相同者转换为默认模式，不同者去重导入额外条目并改为显式引用。报告转换结果，这是新规则，不声称旧系统曾保存跟随意图。完成后移除旧生效来源，不长期维护双重解析。

旧 `[runtime.model.compat]` 及房间／模板中的兼容项一并导入。`supports_developer_role` 保留未指定、显式 `false`、显式 `true` 三态，沿用现有 `*bool` 表达；不能因布尔零值、序列化省略或表单默认值而丢失 `false`，也不能把未指定补成 `false`。Session 历史快照中的原值保持不变。

旧自定义 `api_key_env` 仅由迁移／旧 Session 恢复路径解释，不转换为新的用户配置项或网页字段。完成凭据导入后，新模型选择与运行不再依赖用户持续 export 旧变量；重启从私有凭据存储读取。

缺失凭据、未验证条目如实标记并允许管理修复，不伪造成功或为迁移强制全量联网验证；不能恢复者仅阻断依赖者。旧 Session 快照与恢复指纹保留，不能只因重组引用就轮换。迁移未完成时先阻止受影响的数据恢复／写入，管理入口仍可查询进度。不要同时承担旧数据通用修复或任意旧版本迁移。

最少管理能力为：查询列表／默认／使用者、查询成员选择与实际版本、提交变更、查询操作、重试及提交前取消。可沿用 `/v1/setup`，增加 `/v1/models`、成员模型和模型操作路由；具体路径随现有规范确定，不为每一步持久阶段增加专用 API。

写请求带稳定请求 ID、完整目标身份和预期版本；认证主体来自管理会话，沿用 Origin／CSRF 检查。模型管理不进入 Agent 执行 token 权限。耗时验证／切换异步受理返回操作 ID；前端刷新、切成员、双标签页或迟到响应不重复写入、不覆盖其他草稿。设置模式仅放行必要的精确管理路由。

## 8. 实施阶段与验收门槛

采用四个实施阶段。每阶段只验证本次改动直接涉及的行为；基础阶段通过内部调用和测试检查即可，不为“可检查”额外开发管理 API、临时页面或完整进度 UI。用户流程形成后再做浏览器验收；故障测试随对应逻辑加入，完整端到端和发行包验收集中在交付阶段。

| 阶段 | 交付边界 | 验证重点与完成门槛 |
| --- | --- | --- |
| 1：配置与验证基础 | 开始时验证隔离探测和等待 turn 后换 Backend 两条关键路径；完成模型列表、引用、凭据、TOML 保存及 Session 快照，确定迁移规则 | 组件／集成测试及必要的真实 DSH 探测；Key 不串用、不依赖宿主变量；配置保存与重启正确；关键路径可行。无需 UI，暂不迁移已有数据 |
| 2：首次使用闭环 | 复用首次网页表单，完成验证保存、默认 Agent、直接启动的文件／认证准备；移除终端模型问答，保留可选 init | 一次完整首启浏览器验收：新 home 不先 init／access init、不 export Key 即可完成首条真实对话；预填复用、失败不提交、重复启动不改认证 |
| 3：在线模型管理 | 先完成单 Agent Backend／rotation／恢复，再扩展改默认、条目更新、全局传播与汇总进度；复用设置页及成员详情 | 针对切换新增集成／竞态及故障测试，必要的真实模型切换与新 UI 流程检查；等待不提前取消动作、默认／显式语义正确、失败隔离、重试和重启不重复执行 |
| 4：删除、迁移与交付 | 复用传播机制实现删除替换；完成一次旧配置迁移、打包说明、smoke 和完整交付检查 | 删除／迁移专项测试；最终完整端到端及发行包验收。无悬空引用、旧差异与指纹保留；通过迁移验收后才对已有数据实例开放 |

阶段内按依赖小步开发、提交和检查，不把每个内部步骤都提升为独立交付。阶段 1 的两个关键原型在开始时完成，不另设阶段或临时用户入口；阶段 3 内“单 Agent → 全局传播”保留先后顺序，但共用同一套轮换、表单和进度实现。阶段 4 的删除、迁移和发行检查仍是分别可核对的工作项，不要求合成一个大提交。

控制实施时间的约定：

- 优先扩展已有首次引导、设置页和成员详情，不为每阶段重复建设 UI。
- 测试按配置、凭据、生命周期等行为归属；有新变更、失败或未解决风险时才重跑相关检查，已通过的检查不因进入下一阶段就全部重复。
- 真实模型调用只验证适配器、工具往返及实际切换；超时、并发、写入不确定和部分失败组合主要用可控 fixture，不反复消耗远端调用。
- 凭据隔离、当前执行结清和重启恢复属于必要正确性验证，不能为了压缩阶段而省略。
- 未完成的写能力不提前开放；代码／测试按行为命名，不用临时阶段编号作为长期概念。

阶段用于组织依赖和检查点，不是额外的审批流程。授权实施整个方案时可连续推进；明确指定只实施某一阶段时遵守该范围。尚未授权实施前，本文仍只是方案。

以下是全方案累计覆盖清单，按相关改动补齐，不是每阶段都重新跑一遍的验收套餐。组件、真实模型、浏览器及发行包证据分别报告，模拟结果不能代替真实结果：

- **组件／集成／竞态**：引用解析、相同执行配置不轮换、凭据不串用、版本冲突、原子保存结果不确定、并发创建／删除、自动轮换和 Workspace 冲突、等待／暂停、部分完成、重启恢复、删除替换及迁移中断。
- **真实 DSH／模型**：文本和固定工具往返；运行中从 A 切到 B；更换 Key 且重启仍可用；同房间成员异模型；核对实际后续请求，不只检查配置或 generation 文件。不同 DSH 身份的未测能力单列。
- **浏览器**：首次引导、集中列表、成员默认／固定选择、等待与失败进度、删除替换、刷新／双标签页、预填凭据复用，临时断网不回首次向导。
- **发行包**：全新 home 不先运行 init／access init；可选 init 后退出；重复／并发首启及中断续接；已有 token 丢失不自动补发；外部 home、只读包、必要程序缺失与 macOS 下载隔离。更新 `scripts/package-smoke.mjs` 及现有打包浏览器验证。

凭据体验单独验收：基础／高级表单与管理请求均不要求 `api_key_env`；全新且没有 Key 环境变量的服务，网页输入后可验证、执行并在重启后继续使用；宿主同名变量为旧值／空值时不覆盖托管 Key；多个模型共用内部变量名不串用凭据；旧自定义变量自动导入、缺失时只需补填 Key，旧 Session 指纹保持不变。

接口兼容性单独验收：三态经 TOML、API、表单、迁移和重启往返后不失真；非 Completions 协议拒绝该项；显式 `false` 的实际请求不含 `developer` 指令角色，`true` 按适配器条件使用，未指定保留原行为；修改不关闭独立的推理设置、不覆盖 DeepSeek `thinkingFormat`；变更后按引用范围验证并切换 Session，其他模型条目不受影响。

必须单独验证两个场景：

1. 默认 A；甲选默认、乙显式 A。默认改 B 后甲用 B、乙仍用 A；编辑 A 后只有乙应用新版本，不能仅比较显示名称。
2. 删除默认 A 并替换为 B；甲保持默认、乙改为显式 B；乙切换失败时甲可继续工作，A 保持待删除且禁止新增引用；重试后完成删除，旧 Session 快照仍可诊断。

完成标准是配置已保存、引用正确、相关 Agent 已按边界切换且真实后续调用符合目标。仅表单可保存、模型能列出或目录已生成，不算端到端完成。
