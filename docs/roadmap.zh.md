# 后续方向

以下均未交付，按实际需求单独确定范围，不是使用当前功能的前置步骤。已实现功能见[核心概念](concepts.zh.md)，现有链路的验收缺口见 [运行手册](../internal/room/README.zh.md#当前待验项)。

## 协作节奏

当前已有房间级单执行名额和成员回合预算，执行中用户追加输入只合并通知，不自动打断回合。可按需增加：

| 方向 | 目标 | 必须保留的约束 |
| --- | --- | --- |
| 发送新鲜度检查 | 未读他人消息时返回 `context_stale` | 与消息追加共用串行提交边界；既有发送 ID 先返回原回执，拒绝不消耗新 ID，不自动重放工具 |
| 每轮讨论预算 | 限制一轮任务的公开发言并允许结束讨论 | 明确轮次归属与新用户输入边界，区分成员执行预算和公开消息预算 |
| 用户新输入优先 | 取消旧回合，结清后处理最新输入 | 只响应同 Room 的新 human 消息；合并连续输入，取消限定实际回合，不影响后续回合 |

用户输入打断必须记录独立原因；收到取消不代表结清，旧回合仍占名额。仅在协议、工具、worker 均停止且成员健康、启用、预算充足时才能续跑；手动暂停、移除、轮换和退出优先。取消失败或结果不确定继续阻断。已发生的消息与远端副作用不撤回，不重放旧调用。

角色提示词可提高发言门槛、区分已确认与待核实事项、允许沉默，但不承担调度授权或强制收敛。业务统筹角色不因此拥有调度器权限。

## Agent 运行时

- 崩溃接管：核实宿主异常退出后的进程归属、旧工具及清理证据；不得按裸 PID 清理，也不能用正常关闭测试代替。
- 独立交互 CLI：有调试需求时复用 Session 组件提供独立对话、Ctrl-C/EOF 和恢复提示，不成为 Room 运行依赖。
- 诊断体验：按需增加完整事件归档、日志轮转和排障展示，不让诊断写入阻塞协议或结清。
- 产物与系统兼容：升级 DSH 安装产物或增加支持平台时，重新核验配置、协议能力、进程观察和故障恢复。

## 平台扩展

[GitHub 活动方案](GITHUB-EVENTS-PLAN.zh.md)仍是提案。连接、通知和独立工具按需分别接入，复用当前公共生命周期，不要求先增加 Workspace 绑定。多项目通知、多仓库 Workspace、全局执行配额、空闲实例卸载、跨房间协作、Webhook 和自动事务处理不属于当前交付。
