# 使用 Scion 开发与评审

在「软件开发」团队中使用 Scion，可以让 developer 开发并创建 Review、reviewer 独立测试和评论，再由 developer 修正并更新同一个 Review，交 reviewer 复审。复杂需求由 architect 先交付设计。GitLab 与 Scion 共用这套团队，根据 Workspace 和成员工具绑定选择对应流程。

## 首次配置

### 1. 准备程序并启动服务

先完成 [TeamX 安装与模型配置](installation.zh.md)。Scion CLI 暂不随 standard 包提供，须在服务机器另装固定 **scn 0.1.13**，下载与校验见[工具手册](../tools/scion/README.zh.md#安装)；当前已核实的平台为 macOS arm64。

TeamX 支持原生 `scn` 或配套 `teamx-scion`，无需重新编译 TeamX。已安装个人服务由服务选择程序：默认使用本 release 的封装及同目录 `scn`，管理员可在服务启动环境中设置 `TEAMX_SCION_BIN`、`TEAMX_SCN_BIN` 的规范化绝对路径，修改后重启。完整安装缺失依赖不会回退到 PATH。独立个人／源码运行继续保留每个 profile 的外部程序选择。Linux 多用户仍不开放 Scion。薄封装构建及服务环境配置见[工具手册](../tools/scion/README.zh.md)；从源码启动见[开发运行参考](../internal/room/README.zh.md#从源码运行)。

个人版的默认空间和新建空间均可接入 Scion。连接、登录凭据和操作回执由当前空间独立保存；新空间不会继承默认空间的账号，退出一个空间的登录不会退出其他空间。同一服务中的空间复用服务选择的 CLI 程序，各自使用私有凭据文件。

### 2. 在页面配置 Scion 连接

从「成员详情 → 平台 → 添加平台 → 连接新平台」选择 **Scion**，也可先在全局「设置 → 平台」连接账号：

1. 填写连接名称；实例地址默认是 `https://scion.opencsg.com`，也可在地址下拉输入框中填写其他实例。对话中的登录卡片同样默认使用此地址；指定实例或重新登录已有连接时沿用对应地址。
2. 程序由服务自动检测。已安装服务不在页面选择程序；独立个人／源码运行可在「高级设置」填写服务机器上 `scn` 或 `teamx-scion` 的绝对路径。
3. 页面自动检测当前服务已有的登录：单个账号自动选中；多个账号由你选择。
4. 没有可用登录时点击「登录」，已有账号时点击「重新登录」，再输入该实例的 PAT 并点击输入区内的「登录」。登录成功后显示实际账号，再点击「保存连接」。

**不需要手工创建目录或填写 profile ID。** 后台调用 Scion CLI 登录并管理独立 profile，PAT 输入框提交后立即清空。登录响应丢失时只查询状态，不会自动重发 PAT。可以取消正在进行的登录。

同协议版本的服务升级后，旧连接使用当前控制面程序，核验、成员工具、无凭据帮助与 Workspace 共用选择规则；无需改写旧 profile、凭据指纹或成员授权。已受理调用保持原程序和本次凭据副本直到结清。旧 Session 的 DSH、Agent CLI 与执行描述保持原有生命周期。

连接保存后会再次验证账号。PAT 及账号须具备目标仓库所需的读取、任务分支发布和 Review 写入权限。

已登录时，可在账号旁点击「退出登录」。确认后会停止正在使用该账号的操作，清除当前 TeamX 受管账号的本地凭据，并使共享此账号的连接失效；连接配置和房间绑定保留。重新登录后需保存连接并重新验证。退出不影响其他独立登录，也不会撤销 Scion 平台上的 PAT；撤销令牌请通过「查看或创建 PAT」进入令牌管理页面。

### 3. 新建软件开发 Room

新建「软件开发」Room，先完成下面的工具和 Workspace 配置，再发送需求。新模板只影响新建 Room；已有 Room 保留旧角色快照。使用 `~/.teamx/teams/` 或自定义团队目录时，先将更新后的软件开发团队模板同步到实际加载目录。

### 4. 为成员启用工具

进入各成员详情的「平台 → 添加平台」，选择刚保存连接的「添加并启用」以启用工具；之后可在平台行直接开关工具。通知与工具独立，可按下节单独配置 Issue 新建通知。developer、reviewer 分别绑定；architect 需要提交设计时也须绑定。可以共用一个平台账号，也可以分别选择各自的已验证连接。

### 5. 初始化 Scion Workspace

打开输入框下方的 **Workspace**，选择 Scion 类型，填写仓库和分支，选择已验证连接并应用。例如：

| 字段 | 示例 |
| --- | --- |
| 仓库类型 | Scion |
| 仓库 URL | `https://scion.opencsg.com/OpenCSG/teamx-demo` |
| 初始分支 | `main`；留空则核实并使用仓库默认分支 |
| 连接 | 刚验证的 Scion 连接 |

等待初始化完成，每个成员会拥有独立的 `.scion` 工作副本。**Workspace 连接与成员工具绑定分别配置**，初始化不会自动启用工具。已有非空目录不会被清空覆盖；目录保护与恢复说明见 [Workspace](workspace.zh.md)。

## 接收 open Issue 新建通知

在成员详情的「平台」中，打开已有 Scion 行的设置；尚未添加时，在「添加平台」选择该连接的「设置」。填写仓库规范名称或同实例仓库链接，验证后选择从现在、最近一天或自定义时间开始接收，再保存。连接和接收成员来自当前平台行，无需重复登录、绑定工具或初始化 Workspace。

当前只接收**查询时仍为 open 的 Issue 新建通知**，不含 Review、评论、关闭或评审动态。一个连接／成员对应一个仓库；仓库、Issue 类型和接收起点保存后固定。可暂停／恢复、在高级设置调整 30—3600 秒的检查间隔，或立即同步。暂停和服务重启保留进度；同账号重新验证可恢复凭据暂停，不将原进度转交给不同账号。

内容进入所选成员的私有 Inbox，由现有输入工具正式读取确认。不同成员分别配置和消费，通知不会启用成员工具。过期策略沿用全局设置，页面显示当前有效接收下界、过期跳过、待投递和范围不完整诊断；列表未读全时不会声称完成同步。两轮查询之间新建后即关闭的 Issue 不在覆盖保证内。

也可以直接在对话中说：“给你开启 Scion 工具，并关注 OpenCSG/scion 从今天开始的新 Issue”。Agent 复用已有已验证连接；有多个候选时显示账号选择卡片。首次通知必须明确仓库，不会自动取 Workspace；以后可一句话暂停／恢复工具和通知，或单独修改其中一项。工具和通知各自保存并反馈结果。

没有可用账号时，可直接在消息卡片的密码框填写 PAT，也可点击「查看／创建 PAT」打开当前实例的令牌管理页。点击一次「登录并继续」后，页面自动登录、保存并核验连接，再把账号选择返回原会话，由 Agent 继续原请求；无需打开平台设置或另点保存。重新登录会更新所选的原连接；只有实例不明确时才需补填地址，多个旧连接需要明确选择。

PAT 仅由密码框直接提交登录接口，不写入聊天记录、选择草稿或模型上下文，提交及离开页面时清空。登录／核验失败不会提交选择，登录或保存应答丢失时只核对原结果，不重复发起。也可通过「完整设置」管理连接；浏览器中途刷新时，可在原卡片刷新账号并提交已经保存的连接。

仓库、类型和开始时间首次保存后固定，只支持修改通知开关和轮询间隔；Review 和评论动态尚未开放。实现与验收记录见 [Issue 通知首批交付](implementation/scion-issue-notifications.zh.md) 和 [Scion 对话配置](implementation/scion-conversation-configuration.zh.md)。

## 日常使用

配置完成后，直接发送业务需求，例如：

> 帮我做个命令行 Todo 看板，能添加、查看和完成任务，关掉再打开数据还在。

无需在消息里列 Scion 命令或评审步骤。developer 完成开发、测试并交接 Review 链接和完整版本；reviewer 在自己的副本检出准确版本、独立测试并发表评论。你可以继续提出修改，成员会更新原 Review 并复审新 revision。简单需求不要求 architect 额外发言。

查看 Room 中的 `[待评审]`、`[待复审]` 和评审结果，或点击 Review 链接查看平台版本和评论。成员暂停时，在详情查看原因，处理后通过「启用协作」继续。

当前流程使用普通版本化评论，**不自动 approve、合入或关闭 Review**。Scion 的任务分支 `land` 是发布，`review land` 才是合入目标分支；评审通过不代表已经合入。成员使用原生 Scion 命令，不在 `.scion` 副本执行 Git 开发流程。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 程序找不到或版本不符，退出 127 | 检查服务端的封装、scn 路径和固定版本；路径配置改变后重启服务。成员 shell 中修改 PATH 不会传给服务端。 |
| 连接验证失败或 `credential_unavailable` | 点击「刷新账号」核对当前服务的登录，必要时使用 PAT 重新登录。命令行配置的诊断见工具手册。 |
| `identity_mismatch` | 实际账号与连接记录不符；在页面使用 PAT 重新登录并保存连接，重新验证后核对成员绑定。 |
| Workspace 初始化失败 | 查看页面错误和目标目录，保留现场；分支须存在且有提交。核实后按 Workspace 文档显式重试，不删除工作文件来清场。 |
| 模型 HTTP 429 | 等待模型服务额度恢复，再「启用协作」；不要反复发送同一任务。 |
| 创建、发布或评论结果未知 | 先核查远端分支、Review 或评论，再决定后续操作，不重复写入来探测结果。 |

角色职责见[团队 README](../.teamx/teams/software-development/README.md)，验证边界见下节。

## 验证与待验项

固定 CLI 的只读成员调用、三份原生 clone、失败后的显式重试和正常重启已有通过记录。真实 DSH 已完成开发、创建 Review、独立评审、修正、更新同一 Review revision 与复审，并在一次评论响应丢失后只读核查作者、正文、版本与唯一性。续验经过模型限流后的结清与正常恢复，不证明连续无干预协作可用。

实际连接、工具绑定与 Workspace 页面操作，多任务／多账号、完整故障矩阵、复杂设计交接和 Review 合入仍待验证；其他发布平台及非 Unix 进程树结清也未验收。组件或模拟页面通过不替代这些结果。

完整复跑命令及真实写入要求见[测试说明](testing.zh.md#scion-真实验收)。
