# 工作区文件浏览与消息预览方案

状态：F1–F4 已按授权实施；F4 已在隔离环境通过真实 DSH／模型与实际 Chromium 的生成—交付链接—预览—修改刷新、正常重启、目录变化及消息清空验收。前端与定向浏览器回归通过；整体 Go 回归仍有两项既有架构检查失败，另有一次 DSH 清理超时在定向及整包复验中通过，详见 [F4 实施记录](implementation/workspace-files-real-acceptance.zh.md)与 [F1](implementation/workspace-files-browsing.zh.md)、[F2](implementation/workspace-message-links.zh.md)、[F3](implementation/workspace-resources-and-downloads.zh.md) 各阶段记录。本文不授权修改日常 Room 或推进后续扩展。

基于 2026-11-21 当前工作区代码及本轮界面讨论整理。现有目录选择、消息图片与 Markdown 能力可复用；下文保留原方案设计与阶段边界，实际交付和未验项见各阶段实施记录。

## 1. 目标与核心取舍

补齐“用户提出需求 → Agent 生成文件 → 用户在对话中打开文件 → 继续要求修改”的流程。例如 Agent 在工作目录生成 `docs/PREVIEW-DEMO.zh.md` 后，用户可以从右侧文件面板打开，也可以点击消息中的明确文件链接直接预览。

采用以下设计：

- 从消息文件链接或会话右上角菜单进入文件内容页，独占右侧整栏；支持浏览工作目录和预览单个文件。
- 文件面板展示工作区实际文件；消息文件链接突出本次交付。两者共用读取与预览能力，不另建产出物数据库、发布工具或文件复制流程。
- 工作区文件是可变的外部内容，预览显示读取时的当前内容，不承诺保留消息发送时的版本。
- 首版只提供“工作区文件”，不增加“工作区文件／会话附件”切换或附件汇总。已有消息附件继续在原消息中查看，沿用其存储、权限和生命周期。
- Agent 使用普通 Markdown 相对文件链接，无需新增工具调用或必填参数。服务端只为消息保存一个可信工作目录指纹，避免旧链接随目录设置变化而指向其他文件。
- 首版只读，支持 Markdown、文本／代码、PNG／JPEG／WebP 和有界下载。多标签编辑器、运行 HTML、Office 转换及全项目搜索后续扩展。

首个必须完成的闭环是 Markdown 示例的浏览和点击预览；工作区图片、相对资源及有界下载在后续开发阶段补齐。完整首版包含第 10 节的 F1–F3 开发及 F4 真实闭环验收；会话附件汇总属于后续扩展，不是首版完成条件。

## 3. 界面与交互

### 3.1 按入口打开，右侧整栏展示

文件与助理设置共用右侧承载区域，以内容模式互斥展示。文件打开后收起成员列表、助理设置标题和平台／规则等页签，仅保留文件操作头与内容。不常驻“文件／助理设置”上层切换，也不在文件预览上方叠加其他功能页签。

```text
会话右上角菜单 → 工作区文件 → 右侧整栏目录列表 → 右侧整栏文件预览
消息中的文件链接 ────────────────────────────→ 右侧整栏文件预览

右侧文件页（目录与预览互斥，按前后页导航）
┌─────────────────────────────────────────────┐
│ 返回  目录名／文件名           刷新  展开  关闭 │
│ 相对路径；列表时按需显示来源选择和文件名筛选    │
├─────────────────────────────────────────────┤
│                                             │
│          目录列表 或 单个文件内容             │
│                                             │
└─────────────────────────────────────────────┘
```

主要入口为两种：点击消息中的明确文件链接直达预览；点击会话右上角菜单“工作区文件”进入目录浏览。只有多个不同工作目录时才出现目录选择，不提供文件／附件分类菜单，也不为后续附件汇总预留空页签。将来需要独立快捷按钮时再根据使用频率增加。

输入框现有工作区控件继续负责“选择工作目录”，不改成文件浏览按钮。文件页只读展示当前来源，修改目录仍使用现有配置入口。

打开时保存原侧栏是否打开、成员选择及设置页位置；关闭文件页恢复该状态。若原侧栏关闭，关闭文件页也恢复关闭。从头像进入助理设置时按原有入口切换右侧模式，不同时展示两种内容。切换后可在当前会话内保留文件浏览位置，但不让隐藏文件页继续读取。

首次进入会话沿用现有侧栏默认行为，不自动展开文件、不抢走聊天焦点。由用户的明确点击进入文件页。

### 3.2 多成员与共用目录

- 单聊直接使用该助理的有效工作目录；多人 Room 以成员名称标注来源，不用裸绝对路径作为主要标题。
- 多个成员指向完全相同的规范目录时，列表合并为一项，并显示共用成员。默认独立目录分别列出，不能声称整个 Room 共用一个文件系统。
- 合并仅是展示；每次请求仍选择一个实际 membership，服务端验证其当前目录和权限。所选成员退出或换目录后重新获取来源，不能把请求静默转给其他成员。
- 无选择历史时优先当前查看的成员，再取稳定排序第一项；存在多个目录时始终显示当前来源。
- 路径详情可查看服务端目录说明，但浏览器文件选择器和用户本机路径不参与服务端文件读取。

### 3.3 列表、预览与返回

首版用“列表 → 单文件预览 → 返回原目录”的结构；目录和预览各自占用全部内容区，不同时挤入目录树和多个文件标签。返回时保留列表位置、筛选词；预览头显示文件名、工作区相对路径、刷新和展开，下载按当前阶段已实现能力显示。仅在预览 Markdown 时显示源码切换，列表筛选栏不占据预览空间。

Markdown 默认显示渲染结果，可切换源码；文本／代码显示可选中、可复制的源码；图片适应可用区域并复用放大能力。代码高亮不是首版完成条件。

刷新只重新读取当前目录或文件，不重置聊天滚动和输入草稿。Agent 正在写入时可能读到中间状态；读取过程中检测到文件替换、大小／修改时间变化时提示重试，不自动反复读取。刷新后保持原来的源码／预览模式。

“右侧整栏”表示文件内容独占右侧区域；“展开”进一步使用应用主工作区的大部分／全部可用空间，临时覆盖聊天，关闭展开后恢复原尺寸和文件状态。两种模式首阶段即提供，目录浏览同样可以展开。

桌面文件模式默认比助理设置更宽：建议取扣除左侧会话导航后可用宽度的约 45%–55%，空间允许时内容宽度尽量达到 600px，同时为聊天保留约 480px。沿用拖宽能力，文件宽度与助理设置宽度分别记忆；不能直接沿用较窄设置栏宽度或当前 720px 上限阻止展开。窄桌面无法同时满足阅读宽度时，采用覆盖式大面板；不强行压窄两侧。

移动端复用同一组件和操作模型，直接全屏文件页；返回顺序为展开预览 → 文件预览 → 文件列表 → 聊天。从消息直达预览时，返回可直接回到聊天，另提供“所在目录”。接入已有浏览器返回层、Escape、焦点恢复和聊天可见性判定。文件覆盖聊天时暂停原有逐条可见阅读判定，聊天草稿和滚动位置保留。F1 即完成直接浏览入口的桌面、窄屏及移动端基础交互；F2 为消息入口补齐对应返回路径，F3 只扩展新内容类型的交互。

## 4. 文件来源与读取模型

### 4.1 一个受约束的读取源

服务端根据现有 Room 配置和成员身份解析有效工作目录，提供以下来源信息：

```json
{
  "membership_id": "member-id",
  "label": "开发助理",
  "directory_source": "external",
  "root_id": "opaque-root-id",
  "available": true
}
```

`root_id` 是工作目录指纹，建议固定为 `wr1_` 加 64 位 SHA-256 十六进制摘要；输入采用版本、RoomIdentity、membership 和规范绝对目录的确定性编码。Session 绑定与当前目录查询共用同一个纯函数生成指纹，不建立映射表、注册记录或递增代际。

正常服务重启后指纹保持稳定，同路径下文件内容变化不改变它。指纹用于检测来源变化，不是凭据，不替代登录身份、Room 权限和当前配置校验。客户端不能指定任意绝对根路径；服务端始终从当前配置解析真实目录。

请求携带当前完整服务／Room 身份、human caller，以及 `membership_id + root_id + 相对路径`。根目录变更后返回明确的 `workspace_source_changed`，客户端刷新来源并要求用户重新选择，不沿新目录继续旧预览。

无关平台设置或其他成员目录变化不应使该来源失效，因此不能仅以整个 `workspace_version` 作为文件身份。根目录被删除重建且路径相同，或成员换目录后又恢复为同一规范目录，均按“当前目录内容”处理；不承诺历史物理对象身份或永久撤销旧目录链接。

### 4.2 目录列表与定位

- 根内按需进入目录，文件夹优先，再按文件名稳定排序；仅返回名称、相对路径、类型及有界元数据，不读取全部文件正文。
- 默认隐藏点文件，可显式显示。隐藏是展示行为，不是权限控制；受保护路径无论是否显示隐藏项都不能读取。
- 筛选明确标为“筛选当前目录”，仅作用于本次已返回条目；不递归扫描、不建索引、不宣称全项目搜索。
- 增加相对路径定位输入，可直接定位 `docs/PREVIEW-DEMO.zh.md`；绝对路径、shell 表达式和 URL 不作为此入口的输入。
- 建议单目录最多扫描 5,000 项、返回 1,000 项，超限返回 `truncated=true`，页面明确列表不完整并提供相对路径定位。首版不为不完整列表提供误导性的全目录搜索结果。
- 文件列表没有复制、重命名、删除、解压、创建文件或更改工作目录的能力。

### 4.3 类型与资源上限

以下为首版默认值，实施时集中定义并通过能力响应提供给 UI；不得让前后端各自硬编码不同上限。

| 内容 | 默认处理与上限 |
| --- | --- |
| UTF-8 Markdown、文本／代码 | 最多 1 MiB，完整读取后渲染；超限仅显示元数据与下载入口，不把截断文本当作完整文档渲染 |
| PNG／JPEG／WebP | 最多 16 MiB、2,500 万像素，验证真实类型及尺寸后预览；沿用已有解码并发约束 |
| SVG、HTML、PDF、Office、压缩包及其他二进制 | 提供元数据及有界下载；不执行、不解压、不嵌入同源页面 |
| 下载 | 普通文件最多 64 MiB，流式传输、有取消及超时；超限明确提示首版下载限制 |
| 目录／请求 | 路径最多 4,096 字节；内容读取与下载共用服务端有界并发队列，建议全局 4 个，取消后释放资源 |

类型判断结合扩展名、内容探测及文本有效性；上表指定仅下载的类型优先按下载处理。Markdown 仅对 `.md`／`.markdown` 且有效 UTF-8 的文件启用。其他有效 UTF-8 文件可按纯文本查看；包含 NUL、无效 UTF-8 或不支持编码时不强行转换。实际文件大小、MIME、mtime 作为观察结果，不作为历史快照或安全凭证。

## 5. 消息文件引用

### 5.1 Agent 输出约定

推荐输出：

```markdown
已生成示例文件：[预览示例](docs/PREVIEW-DEMO.zh.md)。
```

链接相对于该成员有效工作目录根解析，与服务进程 cwd、浏览器地址、用户本机目录无关。支持标准 Markdown 显式链接与引用式链接；代码块、行内代码、裸文件名及绝对路径不自动转成文件链接。首次实施不为旧消息里的反引号路径增加猜测规则。

只对有可信目录指纹的 Agent 原生发言开放此约定；人类消息、平台通知、引用文本及内部操作结果不借用当前助理目录解析。HTTP／HTTPS 继续作为外链；`file:`、协议相对地址、自定义协议和带查询参数的本地链接均不开放。文件链接的路径转换统一遵循第 6 节规则。

Agent 指引只需增加一句：交付工作区文件时，使用相对工作目录的 Markdown 文件链接。它描述查看方式，不代表 TeamX 已生成、发布或上传文件，也不要求额外的登记调用。

### 5.2 只保存一个可信目录指纹

建议给 `RoomMessage` 增加可选字符串 `workspace_root_id`，值与第 4 节的 `root_id` 相同。作者直接使用已有 `AuthorMembershipID`，不新增包含作者、版本及绝对路径的来源对象。普通服务端通知、延迟 outbox 公告不自动补入指纹。

指纹沿已有边界传递：

```text
Session 已验证的冻结 cwd
    → 计算目录指纹，附加到现有 executionBinding
    → HTTP 认证验证执行凭据，向请求上下文传递可信绑定
    → send 适配层取指纹，填入内部 PostMessage
    → Room 随消息原子保存 workspace_root_id
```

实施要求：

1. 使用本次 Session 实际冻结的规范 cwd；恢复 Session 使用已恢复配置，不读取新配置替代旧执行事实。不因保存指纹扫描目录、读取文件或新增执行许可。
2. 指纹不加入 `/v1/send` 的外部可写 JSON，也不接受 CLI 自报 cwd。HTTP 认证层只传递已校验的执行绑定；新增字段沿用既有凭据签发、撤销和 Session 生命周期，不另建管理器。
3. `Room` 仅接收可选字符串并验证格式、作者类型和作者 membership；不调用 manager、文件系统或 Markdown 解析器。证据不足时不绑定，文字发言仍按原流程发送。
4. `client_message_id` 重试返回原消息及原指纹，不根据新目录重算；保持现有发送去重和冲突语义。来源生成及文件读取失败不引入新的文字发送失败条件。
5. 字符串字段计入消息容量、分段日志的保存／加载及不可变消息比较；值类型随原消息复制，不增加来源对象的深拷贝流程。空字符串按旧消息处理，不做历史迁移或补写。
6. 浏览器可取得该有限字段用于开启文件链接；现有 Agent 业务 DTO 保持白名单投影，不向模型新增技术字段。消息不保存绝对目录、文件正文、快照或访问令牌。

这项字段是核心唯一新增的文件来源事实。消息仍由既有 Room 提交链路发布、保存和清空，不新增引用事务或生命周期数据库。

### 5.3 点击与失效行为

前端通过现有 Markdown 渲染器识别明确文件链接，转换为工作区相对路径。点击时直接调用预览接口，携带原消息 `message_seq + path`，一次完成来源核验、文件元数据和预览读取，不先调用单独的引用解析接口。

服务端验证原消息仍可见且为 Agent 发言，取得其 `AuthorMembershipID + workspace_root_id`，再与当前成员和目录指纹比较，最后按同一文件读取模块验证根内路径。服务端不重复解析 Markdown，也不要求路径必须出现在原消息正文中。

这里的权限边界是用户已获准浏览的当前工作目录，消息仅选择可信来源。链接是导航入口，不证明文件由这条消息生成，也不缩小为“只能读正文列出的几个文件”；额外匹配正文不能替代根内权限校验。

服务端仅在该作者 membership 仍有效、其当前授权目录与原来源一致时读取文件。返回新的当前服务身份下的读取结果，不能复用历史 service epoch。根变更、成员离开、Room 删除或消息清空后拒绝通过该消息发起新的读取；已开始交付的传输按第 7.2 节处理，不能改用其他成员、其他 Room 或同名路径兜底。

旧消息无指纹时不做数据迁移，也不在首次点击时补写；正文继续可读，文件路径可复制到面板定位。历史显式文件链接如提供点击提示，应说明“旧消息未记录文件来源，请在文件面板查找”，不能用当前目录猜测。图中的既有 `docs/PREVIEW-DEMO.zh.md` 可通过列表或相对路径定位打开。

预览页面标明“当前文件内容”，可显示最近修改时间。文件修改后刷新读取新内容；不存在时显示明确错误和“所在目录”，不提供“恢复历史版本”的假承诺。

## 6. Markdown 中的相对资源

消息文件链接以工作目录根为基准；打开文档后，文档内的相对链接和图片以该 Markdown 文件所在目录为基准。这两个基准不能混用。

例如 `docs/readme.md` 中的 `../images/demo.png` 指向工作区的 `images/demo.png`，`guide.md` 指向 `docs/guide.md`。前端共用一个路径转换函数：识别 URL 类型、对 Markdown 路径转义解码一次，再相对基准按 POSIX 风格解析，检查是否越过工作目录根。允许根内的 `..` 导航，越界则拒绝。该函数在 F2 随消息文件链接落地并覆盖基本转换及越界用例；F3 在同一实现上补足文档相对基准、图片和锚点，不另写临时解析器。带 `#fragment` 的文档链接在校验路径后定位标题，纯锚点留在当前文档。

文件 API 始终接收已经转换的根内 `path`，不再增加 `href`、文档基准路径和资源目标等另一套选择器。前端用 `URLSearchParams` 编码传输，后端完成标准查询解码后不额外 URL 解码；对路径重新执行根内、控制字符、反斜杠、绝对路径及受保护目标校验。后端不能信任前端规范化结果。

- 同工作区文档链接通过文件组件切换预览，并维护当前阅读层的返回栈；不修改工作目录绑定。
- 相对图片仅从相同受约束来源读取，复用图片类型和尺寸限制；按需加载，单篇文档最多自动加载 20 张，超限提供显式加载入口并继续受全局并发限制。
- 外部 HTTP／HTTPS 链接由用户点击后打开新页；远程图片默认显示链接，不自动请求第三方资源。
- 复用现有 Markdown 的转义和链接规则；不启用原始 HTML、脚本、iframe、事件属性或任意 data URL。源码视图使用文本节点。
- 相对资源沿用原来源选择器：直接浏览保留 `membership_id + root_id`，消息入口保留 `message_seq`，仅更新根内 `path`。每个新请求仍验证来源；消息被清空或来源变化后不能通过已有图片 URL 发起新的读取。已准入传输的处理见第 7.2 节。

## 7. 后端接口与读取边界

### 7.1 建议接口

接口名称可按现有管理路由惯例微调，职责与选择器保持如下约定。均为经过现有登录／同源／human 身份及完整服务上下文验证的只读 GET。

| 接口 | 输入／职责 |
| --- | --- |
| `/v1/workspace/files/sources` | 列出当前 Room 成员有效目录及能力上限；按当前授权返回可用／不可用状态 |
| `/v1/workspace/files` | `membership_id + root_id + path`，返回当前目录条目、面包屑、是否截断 |
| `/v1/workspace/files/preview` | 一次完成来源核验和预览读取，返回文件元数据与有界文本，或允许的图片内容地址；不支持的类型返回下载能力说明 |
| `/v1/workspace/files/content` | 读取已验证来源下的图片内容，或按 `download=true` 下载普通文件 |

`preview/content` 共用两种互斥来源选择器，均必带根内 `path`：

| 入口 | 业务参数 | 服务端来源依据 |
| --- | --- | --- |
| 文件面板直接浏览 | `membership_id + root_id + path` | 当前配置中的成员目录，计算指纹并比较 |
| 消息直达及其相对资源 | `message_seq + path` | 原消息已有作者 membership 与目录指纹，再比较当前配置 |

混传两组来源字段按请求错误处理；消息方式不能另传 membership 覆盖原作者。每次预览、图片或下载都独立核验，预览成功不产生永久访问许可。响应返回当前目录相对路径及展示所需的来源信息，UI 据此显示面包屑和“所在目录”。从消息预览进入目录列表时显式转为当前工作区浏览，后续按直接浏览权限读取。

文本预览响应示例，外层仍附当前完整服务／Room 身份：

```json
{
  "source": {"membership_id": "member-id", "root_id": "opaque-root-id"},
  "path": "docs/PREVIEW-DEMO.zh.md",
  "name": "PREVIEW-DEMO.zh.md",
  "size": 2048,
  "mtime": "2026-11-21T06:00:00Z",
  "preview_kind": "markdown",
  "text": "# 示例\n\n正文内容。",
  "download_available": true,
  "current_content": true
}
```

`preview_kind` 固定为 `markdown | text | image | unsupported`，文本只在前两种返回。图片返回由服务端构造的受控同源内容地址；超限／类型不支持时返回元数据和明确原因，不向前端发送完整二进制后再决定拒绝。`download_available` 按本阶段已实现能力和服务端上限计算。

目录和文本响应使用有界 JSON；图片／下载响应使用明确 MIME 与 `Content-Disposition`。所有文件响应包含 `X-Content-Type-Options: nosniff`、`Cache-Control: private, no-store`；非白名单内容只作为下载文件交付。这里的 HTTP 附件下载不创建 Room 消息附件。文件名通过标准库安全构造响应头，不直接拼接。

建议统一业务错误：`workspace_source_unavailable`、`workspace_source_changed`、`file_not_found`、`file_not_allowed`、`file_too_large`、`file_changed`、`reference_unavailable`。空目录、类型不支持、资源超限和权限失败不能混成“没有文件”；沿用现有 HTTP 错误封装及状态码映射。

### 7.2 安全打开与生命周期

文件 API 的权限限定为“当前 Room 对该成员当前有效工作目录的可读内容”，不会因为目录选择器允许浏览 HOME，就开放整个 HOME 文件读取。沿用当前服务账号的文件权限，不声称提供新的 Agent 沙箱或跨用户隔离。

建议共用一个受约束的读取模块：解析身份和来源 → 取得根句柄 → 校验相对路径 → 安全打开／检查类型 → 有界读取 → 交付前复核。所有预览入口复用这条路径，不为消息、图片或下载各建一套权限规则。

- 使用根目录句柄及 `os.OpenRoot` 一类受约束打开机制，防止校验后替换符号链接造成根外读取。不能只做字符串前缀比较，或先 `EvalSymlinks` 再无约束 `os.Open`。
- 根内符号链接仅在目标仍位于根内且不触及受保护数据时允许；不支持的文件系统场景明确拒绝，不降级为无约束打开。目录根本身被替换为其他规范路径时返回来源变化。
- 仅允许普通文件；FIFO、设备、socket 等特殊文件在可能阻塞前拒绝。实现时根据支持平台选择非阻塞／防跟随打开及句柄复核方式，用真实 FIFO 场景验证不能卡住读取线程。
- TeamX 管理数据、运行凭据和受保护目录的后代路径同样拒绝，覆盖“项目根中恰好包含 `.teamx`”的情况；`.git` 内部数据首版不进入文件浏览。不得只过滤列表名称而允许直接请求绕过。
- 规范根、打开对象和读取结果均核对；目录重命名、替换、权限变化、读取取消和超时均显式处理。路径校验不承诺识别所有根内硬链接的历史来源。
- 文本／图片发送前，以及流式下载发送响应头前，复核当前 Room、来源和原消息可见性；尚未准入交付的请求遇到失效应拒绝。校验完成后固定使用已打开句柄，不因配置变化重新解析或转读新目录。
- 已开始交付的有界传输按本次准入快照完成，或因客户端取消、既有服务关闭机制及传输超时中止；目录变化、消息清空后拒绝新请求，不新增逐块复核或全局下载撤销协调器。建议下载总时长上限 30 秒，实施时核对目标部署响应写超时；不承诺中断所有底层文件系统阻塞或撤回已交付字节。
- 配置／存储锁只保护身份快照和提交复核，不跨长时间文件读取、图片解码、网络流或 Actor 调用持有 manager 全局锁。复用现有服务关闭、重启及目录切换边界，不另建文件操作事务系统。

文件页可在 Agent 忙碌或暂停时读取，不推进 Agent 的 Inbox／历史读取游标，不触发 Agent 执行，也不因只读查看启动、恢复或轮换 Session。manager 侧优先从已提交配置和持久消息快照读取所需身份；不得调用会隐式拉起 Agent 的运行入口。目录操作尚未结清时仅使用可证明生效的来源；否则返回暂不可用，不能读准备中的目标目录。

## 8. 与现有附件及产出物管理的边界

首版文件面板只浏览当前工作区内容，不建立会话附件列表、摘要接口或附件分页。消息中的图片继续使用现有消息内预览；本次新增工作区文件能力不能改变其读取权限、清空行为或上传草稿隔离。

三个概念保持如下边界：

| 对象 | 来源与生命周期 | 首版处理 |
| --- | --- | --- |
| 工作区文件 | 成员工作目录中的实际文件，随文件系统变化；包含已有项目内容及新生成文件 | 浏览、消息直达、预览、刷新及有界下载 |
| 会话附件 | 随消息提交、由 TeamX 保存的对象，沿用现有消息引用及可见性规则 | 继续在原消息中查看，不新增汇总入口 |
| 产出物管理 | 将交付对象独立登记，管理任务归属、版本、发布状态等 | 不建立；Agent 用文件链接交付即可 |

不新增附件汇总属于界面与功能范围的收敛，不意味着把两种文件的存储和权限合并。第 5 节的消息目录指纹只用于选择和校验来源，不登记独立产出物，也不保存文件历史版本。后续附件汇总可基于已有消息派生列表，与产出物管理分别评估。

## 9. 代码职责与前端状态

建议新增文件读取后端模块及 `features/files.mjs`，将工作区浏览和单文件预览组织在一个功能边界内；实现文件按职责拆分，不把所有逻辑追加到现有 `workspace.mjs` 或 `members.mjs`。无需预建通用文件来源插件或附件页框架。

| 所属位置 | 职责 |
| --- | --- |
| Session／HTTP 装配与发送适配 | 冻结 cwd 指纹、已有执行绑定扩展、认证上下文传递、内部消息字段赋值 |
| manager／文件 HTTP 适配 | 当前配置与原消息查询、来源核验、路由及交付前复核 |
| 工作区文件读取模块 | 根内路径、文件元数据、类型／大小、句柄打开和内容读取；不依赖 UI、不调用模型 |
| Room 消息协议／存储 | 保存可选目录指纹、字段格式校验及容量计算，复用幂等、分段日志和清空；不承担文件扫描或 Markdown 解析 |
| `files.mjs` | 文件页唯一状态、目录／预览读取、返回栈、取消和错误展示 |
| `markdown.mjs` | 按显式选项渲染文件按钮、相对链接与图片；默认消息和平台通知规则维持现有语义 |
| `conversation.mjs` | 提供原消息身份和文件打开回调；不保存第二份文件预览状态 |
| `layout.mjs`／`application.mjs` | 右侧互斥内容模式、原侧栏恢复、文件独立宽度、展开与移动端导航层、刷新及可见性接线 |

核心改动止于一个可选字符串及其既有消息合同适配。不得为文件功能改变 MemberAgent 调度、Inbox／输入流读取确认、Session 轮换或动作授权；文件读取不参与消息提交事务。文字发送不等待文件存在性检查、图片解码或 Markdown 解析，文件读取失败只影响文件页。

前端只增加一个文件功能组件和右侧内容模式，复用现有导航层、面板恢复及阅读可见性通知，不建立通用面板框架或新事件总线。显示文件时暂停隐藏的助理设置诊断读取，不能仅因共用右侧栏仍打开就继续读取隐藏页面。

前端上下文键至少包含 installation、operator、Room 实例、服务 epoch、来源 membership／root_id；消息预览再带原消息 seq。每次切换、关闭、返回和刷新增加请求代次，旧请求应取消且迟到结果必须丢弃。工作区图片加载也执行同一隔离。

列表、正文和 Blob URL 只在当前页面内存保留，来源失效／退出 Room 时清理并回收 URL。会话内可记忆来源、列表位置及模式；不向 localStorage 写文件正文、内部根路径或访问令牌。不默认预加载其他目录和其他会话文件。

打开文件后的自动刷新只处理服务身份、来源失效和消息清空，不周期性重新扫描目录或重读全文。首版用显式刷新获取 Agent 后续修改；关闭或后台时停止额外文件读取。

## 10. 实施阶段与阶段验收

保留 F1–F4 四个正式阶段，按依赖顺序推进。每阶段包含对应入口、提示、错误、必要指引及后端／浏览器验证，交付可独立使用的行为；不增加仅有底层接口的正式阶段，也不把基础稳定性集中留给 F4。长生命周期代码和测试按行为命名，不使用阶段编号。

### 10.1 阶段边界

| 阶段 | 实施内容 | 可独立评估的完成条件 |
| --- | --- | --- |
| F1：工作区文件浏览 | 当前目录来源与指纹、目录／文本读取、会话菜单入口、Markdown 预览／源码、筛选和定位、右侧整栏与展开、桌面／窄屏／移动端导航 | 默认／外部目录的单聊及多人 Room 可通过面板打开示例文件；关闭恢复原侧栏、草稿及滚动；根内权限、文件上限、来源变化和迟到响应受控 |
| F2：消息直达文件 | 冻结目录指纹沿现有执行绑定传到 send；消息字段原子保存；前端共用路径转换、显式链接直达同一 preview；Agent 指引、消息入口返回及旧消息反馈 | 新消息一次预览请求打开正确文件；旧执行不绑定新目录，重试和重启不改变指纹，来源缺失不阻断发言；不新增 resolve 或后端 Markdown 解析 |
| F3：图片、相对资源与下载 | 在已有路径转换和读取模块上扩展图片／文档资源预览及有界下载，按第 10.3 节两个检查点完成 | 文档导航、图片预算和有界下载分别验收；直接浏览与消息入口共用来源规则，各内容类型在既有布局和返回路径中可用 |
| F4：真实闭环验收 | F1–F3 已完成对应验证后，经授权使用真实 DSH／模型及实际浏览器生成、打开、修改文件，并做整体回归 | 真实生成—交付链接—点击预览—修改刷新链路成立；重启、目录变化和清空行为有实际证据，未验项明确记录 |

推荐先实施并评估 F1–F2，获得截图中最核心的浏览和点击闭环；F3 保留为完整首版开发范围，不因分批而取消。F1–F3 的组件及替身测试通过，不等于 F4 真实闭环验收已完成。会话附件汇总不在首版开发或验收范围内。

### 10.2 F1、F2 的实施顺序与完整性

F1 内部按“来源及受约束读取 → 目录与文本预览页面 → 布局导航和验证”组织任务，仍作为一个完整阶段验收：

- 先实现稳定目录指纹纯函数和直接浏览选择器；不要求提前增加消息字段或执行绑定扩展。
- 目录选择、筛选、定位、刷新、源码切换、拖宽、展开、关闭恢复、移动返回及覆盖聊天时的可见性处理均在本阶段完成。不能以“基本返回”为由把正常使用必需的行为推迟到 F3。
- F1 仅开放目录与文本／Markdown；图片、相对文档资源及下载未实现时显示明确占位或能力说明，隐藏不可用操作，不请求错误资源、不回退到本机路径或自动加载远程图片。超限文本不显示尚未实现的下载按钮。
- 阶段退出需覆盖保护路径、根外及特殊文件拒绝、文本上限、目录截断、来源切换、跨会话迟到响应，并通过生产 HTTP 与桌面／窄屏／移动尺寸浏览器验证；同时给出可用的文件面板操作说明。

F2 在 F1 上打通完整消息入口，不拆成“先存字段、以后再接 UI”：

- 共用 F1 的目录指纹函数及 preview 读取模块，新增冻结执行绑定传递和可选消息字段，不扩大核心职责。
- 本阶段建立共用文件链接路径转换函数，包含 URL 转义和根内／根外规范化；随后接入显式链接、Agent 输出指引、消息入口返回及“所在目录”。
- 阶段退出需覆盖伪造字段、原子保存、分段日志、幂等、正常重启、目录切换与旧消息反馈，并通过实际 TeamX 后端及浏览器执行发送链接—点击预览。可用受控执行适配验证 Session 凭据链路；真实 DSH／模型的整体证明归 F4，不能将替身结果计为已通过真实模型验收。

### 10.3 F3 的两个内部检查点

以下为同一正式阶段内的交付检查点，可分别实现和验证，不新增正式阶段或通用资源框架：

| 检查点 | 增量内容 | 本检查点验证 |
| --- | --- | --- |
| 资源预览 | 根内图片预览及放大；扩展 F2 同一路径转换函数，支持文档相对链接、图片和锚点；复用已有阅读层与返回栈 | 类型伪装、尺寸／像素及自动图片数量上限、根外目标、远程图片、消息清空与来源变化、直接／消息两种入口、桌面与移动尺寸阅读 |
| 有界下载 | 普通文件下载、大小／并发限制、固定句柄、交付前复核、取消与传输超时；按能力开放下载入口 | 超限拒绝、响应头、取消释放、服务关闭、交付前失效拒绝及已开始传输有界完成，不转读新目录、不建立撤销协调器 |

F3 完成要求两个检查点均通过；完成一个检查点不能将整个阶段标为完成。它只为新资源类型补充交互和验证，不承担 F1、F2 遗留的通用导航、错误处理或来源隔离。

## 11. 验证范围

第 10 节规定各阶段的退出门槛，以下列出具体覆盖范围。F1–F3 各自运行相关 Go 测试、前端测试和生产 HTTP／浏览器验证，失败在对应阶段修复；F4 负责真实模型闭环及整体回归，不替代此前阶段验证。后端及浏览器验证均使用隔离测试环境，不要求操作日常部署。仅使用前端 fixture 返回数据不能计为实际 TeamX 后端验证；真实后端配受控执行适配也不等于真实模型验收。

### 11.1 后端与协议

- 默认目录、外部目录、串行共用目录及多个成员独立目录；不可用来源不能回退到服务 cwd。
- 路径规范化、根内／根外符号链接、编码变体、保护目录后代、隐藏项直接读取、根被替换和真实特殊文件；拒绝和取消不导致阻塞或句柄泄漏。
- 类型伪装、无效 UTF-8、大文件、图片像素上限、目录截断、下载中断、有限并发及服务关闭。
- 冻结目录指纹沿既有执行凭据传递，伪造 JSON／CLI 路径不能覆盖；字段原子保存、重复发送、容量计算、分段日志加载、正常重启、成员退出、根变更及旧消息无指纹；模拟旧执行与目录切换交错，不能绑定新目录。
- 消息查询只选择来源，不验证目标是否出现在正文；在已授权根内仍可读其他合法路径，根外一律拒绝。测试来源选择器互斥及原作者不能被覆盖，不增加后端 Markdown 解析合同。
- 消息清空与内容／相对图片／下载并发：交付前失效拒绝，已开始交付仅使用原句柄有界完成或取消，之后新请求拒绝；两 Room 同名文件不能互读。直接浏览仍取决于当前来源，清空消息不删除磁盘文件。
- 回归已有消息附件的读取与清空权限、上传草稿隔离；工作区文件预览和下载不创建或改变附件引用。

### 11.2 前端与浏览器

- 消息点击、会话菜单入口、右侧文件／成员内容互斥、关闭恢复原侧栏、返回所在目录、展开关闭、源码切换和焦点恢复；预览不保留目录筛选和助理设置页签占用空间。
- Markdown 标题、表格、任务列表、代码、引用、根内相对图片／文档链接、锚点、危险 HTML 和原有平台图片回归；显式链接、引用式链接、URL 转义及根内／根外相对路径覆盖同一前端转换函数。
- 快速切换 Room／来源／文件、连续刷新、先关闭再到达的结果、epoch 变化及 Blob URL 清理。
- 宽屏、窄桌面与手机尺寸；聊天草稿、滚动、现有侧栏拖宽、浏览器返回和 Escape 不退化。

使用现有 `node --test internal/web/tests/*_test.mjs`、相关 Go 包测试和浏览器框架组织验证；新增用例应覆盖实际边界，不为简单样式或实现细节建立镜像测试。

### 11.3 真实验收与证据口径

真实后端验收使用隔离测试 home、Room 和专用工作目录，不修改日常会话。至少记录以下流程：

1. 真实模型生成示例 Markdown、相对引用的图片／文档，并发送明确文件链接。
2. 用户通过实际 Chromium 点击链接、切换源码、进入所在目录及展开阅读。
3. 要求 Agent 修改文件，手动刷新看到当前新内容；没有多发消息或自动启动额外执行。
4. 正常停服／重启后，新 epoch 下原链接仍按相同来源打开；切换目录后旧链接明确失效。
5. 清空原消息后，链接及相对资源的新请求拒绝；已开始下载按第 7.2 节完成或取消，文件面板仍可按当前来源浏览未删除文件。

记录后端版本、启动配置、模型／DSH 来源、Room 与成员、操作步骤、截图及未验项，不公开凭据和私有文件正文。手机尺寸 Chromium 仅证明响应式行为；实体手机和远程设备未实际测试时单列未验，不混称真实设备完成。

## 12. 本轮边界与后续扩展

本方案不增加图片生成工具。图片生成能力由 Agent 后端或已有工具另行提供；本功能负责呈现已经存在于工作目录的文件。

后续可在实际使用后扩展会话附件汇总、PDF／Office 预览、隔离域 HTML 运行预览、多文件标签、全项目搜索、文件上传／编辑、历史版本和正式产出物发布。它们分别涉及渲染依赖、执行隔离、索引或存储合同，应独立设计与验收，不作为首版的隐含前置。

若后续实施会话附件汇总，仍从已提交且当前可见的消息引用派生列表，处理完整保留历史、分页、去重及清空，不把当前浏览器已加载消息当作全部附件；不包含上传草稿，也不默认导入平台 Inbox 图片。该扩展无需以产出物登记系统为前置。

文档获评估认可后，实施按明确授权的阶段推进；仅更新本方案不代表已经实施或允许更改日常部署。
