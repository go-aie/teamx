# Agent 指定工作目录与服务端目录选择方案

状态：**阶段一、阶段二及阶段三本机真实运行验收与使用文档已实施；真实设备与容器内真实 DSH 仍待验**。基于 2026-11-18 工作区源码及讨论整理；实现、实际交付 DSH／Chromium 和容器挂载检查的结果与边界见[实施记录](implementation/agent-workspace-directories.zh.md)。后文保留完整设计与独立验收要求，未将待验项计为整体交付完成。

## 1. 交付目标与范围

保留每个 Agent 默认的独立工作目录，增加按成员设置已有本地目录的能力。多个成员可以选择同一个目录，轮流处理同一份未提交文件；成员的身份、私有 Session、公共消息、读取进度和使用记录仍独立。

用户操作为：进入成员详情 → 工作目录 → 选择目录 → 应用。选择器浏览 TeamX 服务进程所在机器的文件系统，本机、远端服务器和容器部署使用同一套网页交互。

本次交付包括：

- 按 Room 成员覆盖实际工作目录；留空恢复默认目录。
- 服务端目录浏览、按钮选择、路径直接定位，以及桌面和手机界面。
- 切换时结清旧执行、按需轮换受影响 Session，重启后继续使用已保存目录。
- 同一串行 Room 内多个 Agent 共用一个外部目录。
- 保留 Git／Scion 的默认受管目录初始化能力，并明确外部目录与受管仓库认证的关系。

本次不扩展 ACP、不修改 DSH、不迁移文件，不增加原生系统目录弹窗、目录上传、远端 SSH 文件浏览、自动挂载、共享文件冲突合并或新的通用配置框架。第一版不提供跨 Room 共用外部目录，也不实现跨进程的全局目录锁。

## 2. 已核实的现状与改造入口

| 源码 | 当前行为 | 本方案安排 |
| --- | --- | --- |
| `internal/room/workspace_config.go` | Room 配置保存 `root/repository/binding`；成员默认路径为 `root/<membership_id>`；root 必须是 Room 相对路径 | 保留默认路径规则，增加成员目录覆盖值与统一解析函数 |
| `internal/room/management.go` | `managedMember.Workspace` 是 Room 相对路径；创建／恢复检查受管目录 | 保留其含义，不混入外部绝对路径 |

| `internal/room/runtime_assembly.go` | 将 Room 目录与成员 Workspace 拼成 DSH 工作目录 | 改用统一解析结果 |
| `internal/agent/dsh/session.go` | `session/new` 已经通过 `cwd` 传入绝对目录 | 复用现有参数，无需新增 ACP 方法 |
| `internal/agent/dsh/state.go` | 恢复要求原 Workspace 与当前配置一致 | 保留检查，通过轮换切换目录 |
| `internal/room/workspace_management.go`、`workspace_records.go` | 已有稳定操作 ID、版本、结清、准备、提交、轮换与恢复流程 | 扩展既有操作，区分目录修改和仓库准备 |
| `internal/room/tools.go`、`workspace_git_managed.go` | 工具进程也直接拼接成员默认目录 | 分别适配实际 cwd 与受管仓库能力 |
| `internal/room/model_references.go`、`model_migration.go` | 生成模型执行配置时也引用成员工作目录 | 统一解析当前有效目录；旧 Session 的恢复继续使用原冻结证据 |

| `internal/room/server_access.go`、`config.go` | 已有 human 访问认证、来源检查和部署配置 | 目录接口沿用认证，增加可选择根目录配置 |

ACP 的 `session/new` 可以指定 `cwd`；当前接入没有运行中修改 cwd 的接口。本地打包 DSH 的 ACP 实现也会拒绝用不同 cwd 恢复原 Session。因此本方案采用“保存目录 → 结清旧执行 → 以新 cwd 创建新 Session”。不能通过改 `backend.json` 或忽略恢复指纹实现切换。

协议依据：[ACP Session Setup](https://agentclientprotocol.com/protocol/v1/session-setup)。实际发布前仍需使用交付的 DSH 版本验证，不能把本地依赖源码检查当作运行验收。

## 3. 配置模型与路径语义

### 3.1 默认目录与覆盖值

扩展现有 `workspaceConfig`，建议增加：

```go
MemberDirectories map[string]string `json:"member_directories,omitempty"`
```

键使用当前 Room 的 `membership_id`，值为规范化后的服务端绝对目录。它表达成员设置，但与已有 Workspace 目标一起持久化，复用 `workspace_version` 与操作记录，不新增一套成员目录文件和版本系统。

以下为拟议的 Room 配置片段；成员 ID 为示意值：

```json
{
  "workspace": {
    "root": "workspaces",
    "member_directories": {
      "membership-developer": "/srv/projects/teamx",
      "membership-reviewer": "/srv/projects/teamx"
    }
  },
  "workspace_version": 2
}
```

规则：

1. `managedMember.Workspace` 始终保存原默认相对路径，继续满足 `root/<membership_id>`，不会被外部路径替换。
2. 覆盖值缺省表示使用默认目录；恢复默认通过删除对应 map 项表达。空 map 规范化为 nil，不持久化空字符串。
3. 实际 cwd 为覆盖目录，或者 Room 绝对路径与成员默认相对目录的组合。
4. 覆盖值只属于当前 Room 成员，不能按显示名或 AgentID 跨 Room 继承。拒绝不存在的 membership；移除成员时清除其覆盖值。
5. 团队模板第一版不接受非空 `member_directories`。模板中的 root／仓库建议保持现状，不把某台机器的路径隐式传播到新房间。该限制放在团队模板校验入口；当前 `normalizeWorkspace(..., true)` 也用于管理请求规范化，不能据此一并拒绝合法请求。
6. 旧快照缺少该字段时保持当前行为，无需批量迁移和重写。更改后的 Room 不应再用不认识新字段的旧程序启动。

选择自定义路径后，页面显示“指定目录”；清空覆盖后显示“默认目录”及其准确路径。默认目录可能已经是 Git／Scion 副本，因此“恢复默认”指恢复该成员当前的受管默认目录，不一定是新建的空文件夹。

### 3.2 统一解析，避免不同入口使用不同目录

增加小型领域辅助函数，例如 `resolveMemberWorkspace(roomDir, config, member)`，返回：

```text
directory          实际绝对目录
source             managed | external
default_directory  默认绝对目录
```

区分静态配置解析与文件系统验证；解析函数不创建目录、不访问平台、不启动子进程。所有当前运行配置和工具 cwd 都从同一结果派生，不在每处分别判断 map 或拼接路径。

需要同步检查的消费者至少包括 runtime 组装、模型当前配置生成、普通平台工具的执行目录、Workspace 状态展示和目录切换的前后比较。迁移／恢复代码若处理的是历史 Backend，必须保留历史冻结 cwd，不能以新的覆盖值覆盖历史证据。

`normalizeWorkspace`、`equalWorkspace`、`cloneWorkspaceOperation`、Room／操作快照比较均需要处理 map：深拷贝、按键值比较、nil／空值规范化。不能只修改运行时组装而漏掉持久化、回执防重或恢复检查。

快照解码／静态验证只检查结构、成员归属和规范路径，不因目录暂时不可用或部署根配置变化而拒绝读取整个配置；实时文件系统和根策略验证放在应用／执行准入。否则失效路径会连状态查询与修复入口一起堵住。`normalizeWorkspace(..., true)` 当前也用于请求规范化，模板禁用覆盖值的检查应放在团队模板加载入口，不能直接按这个布尔参数拒绝所有覆盖值。

### 3.3 与默认仓库能力的关系

`root/repository/binding` 继续描述默认受管目录及其仓库准备。初始化仓库时仍只准备默认目录，不修改任何成员选择的外部目录；覆盖值随目标保留。

纯目录修改只修改 `member_directories`，保持其他 Workspace 字段与成员 Instructions／ToolEnv 原样，不执行 clone、平台查询、仓库 Configure 或凭据刷新。它应有独立的“本地目标验证”分支，不能无条件调用当前 `ensureWorkspaces(..., true)`。

房间重新打开时，默认目录继续沿用现有本地回访检查；实际使用的外部目录额外接受路径策略与存在性检查。默认目录也仍由 TeamX 管理，删除 Room 时沿用受管数据清理规则。

外部目录只作为工作目录使用：

- 可以已经包含 Git／Scion、dirty 文件、任务分支和用户配置；绑定时不自动 fetch、sync、checkout、reset、清理或修改认证。
- 普通本地编辑、diff、commit 由 Agent 在实际 cwd 执行。
- 独立启用的平台工具仍使用其明确的成员连接，进程 cwd 改用实际目录；指定目录不会新增工具绑定或平台授权。
- 当前 `teamx workspace-git` 强绑定 Room 的受管仓库与连接。第一版对使用外部目录的成员明确返回 `managed_repository_required`，不能继续在隐藏的默认副本里操作，也不能把受管仓库凭据自动用于外部目录。
- 现有受管仓库工具引用、环境变量和指导文案须标明作用于默认受管仓库；外部目录生效时不能仍向 Agent 宣称“当前目录就是该受管仓库”。采用运行时按目录来源生成的说明／过滤，保留原持久配置以便恢复默认。

## 4. 服务端目录策略与部署

### 4.1 可选择根目录

增加部署级配置，拟议名称：

```toml
[server]
workspace_roots = ["/srv/projects", "/mnt/shared"]
```

该配置同时限制外部目录浏览与绑定；手工填写路径也不能绕过。当前成员自己的受管默认目录另提供只读浏览入口，不能作为外部目录绑定。配置在服务启动时加载，修改后重启生效，第一版不增加在线配置页面。

- 未配置时，使用服务账号可用的用户主目录作为默认根目录，页面直接展示其实际路径。
- 明确配置 `[]` 表示关闭外部目录选择与绑定，默认受管目录仍可用。实现时用能区分缺省和空数组的配置类型。
- 默认 home 无法解析、不是可用目录或等于文件系统根时，不自动扩大为 `/`；关闭外部目录入口并给出可操作诊断，其他功能继续运行。
- 显式配置的根目录要求绝对路径，最多 16 个；格式错误在启动时报告配置错误。挂载未就绪、目录缺失或权限不足则把该根标为不可用并展示原因，其他根和服务继续工作；恢复后重新检查，不能默默删除失败项或回退到更大范围。
- 规范化、解析真实路径并去重；根目录重叠可以合并，不按字符串前缀判断包含关系。

路径只接受服务器当前平台的绝对路径，允许空格和中文；不展开 `~`、环境变量或 shell 表达式。不通过 shell 拼接路径。外部目录浏览／绑定采用同一个校验入口，限制路径长度为 4096 字节，拒绝 NUL 和控制字符。

符号链接可以用于定位，但最终路径必须解析为真实路径且仍在允许根内；保存和返回该真实路径。越界链接不允许进入或选择，链接环和失效链接返回明确错误。现有受管默认目录的“禁止符号链接”规则保持不变。

拒绝把 TeamX 自身的运行数据、认证、模型凭据、Session 或资源管理目录及其内部目录绑定为外部 Workspace，目录列表也不展示这些受保护入口。项目目录可能包含 `.teamx` 等管理子目录，选择项目祖先目录不等于承诺屏蔽其全部后代；目录选择策略不是完整的 Agent 文件系统隔离边界，实际访问仍受运行账号和现有沙箱约束。

目录选择器可以单独进入当前成员自己的受管默认目录及其子目录，只读枚举一层目录，不扩展到受管父目录或其他成员。默认根路径的选择表示恢复默认设置，子目录仅供浏览；即使外部目录选择关闭，此入口仍可用。该例外不改变受保护路径的外部绑定限制。

选择、受理应用、提交目标以及后续打开／启动 Session 时重新检查目录存在、可进入、可列举和策略范围。权限检查使用服务账号与真实打开操作，不只依据 mode bits；不为验证而写探针文件。界面不把“可选择”描述成已保证所有文件均可写，实际写权限与现有沙箱仍在执行时生效。

外部目录不自动创建。目录缺失、权限不足、根配置收窄或真实路径越界时阻止该目标执行并报告原因，不能静默改用默认目录。只影响相关 Room，不能阻止整个部署启动或浏览其他房间。

快照的结构校验与上述实时可用性检查必须分离：旧路径失效时仍能读取配置、查询操作和展示修复入口，不能在反序列化阶段因目录不可用而把整个 Room 配置判为损坏。

### 4.2 部署行为

| 部署 | 页面中看到的目录 | 部署者需要做的事 |
| --- | --- | --- |
| 本机服务 | 服务账号可见的本机目录 | 默认 home 可用，其他位置按需增加根目录 |
| 远端 server | 远端服务机器的目录 | 配置项目路径与服务账号权限 |
| Docker | 容器文件系统内的目录 | 先挂载，例如宿主 `/data/projects` 挂到容器 `/workspace`，再配置 `/workspace` |

界面统一提示“选择 TeamX 服务所在机器的目录”；不根据 localhost、访问 IP 或代理请求头猜测用户与服务是否在同一台机器。

浏览器原生 `showDirectoryPicker()` 面向浏览器设备的文件系统且返回目录句柄，不适合统一绑定服务端绝对路径，本方案不依赖它。参见 [File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)。

## 5. 服务端目录浏览接口与界面

### 5.1 只读浏览接口

拟新增 `GET /v1/workspace/directories`，由目录级管理器提供，使用管理器 `service_epoch`、human `caller_id`、RoomID／RoomInstance 和准确成员 AgentID／MembershipID。它在 Room 的 Workspace 操作期间仍可查询，但不依赖正在关闭的成员服务 epoch。

可选参数 `path` 为希望进入的服务端绝对目录。省略时优先使用该成员当前生效目录，包括受管默认目录，否则展示可用根目录并进入第一个根，通过 `current_directory_error` 提示原因。保留现有配置，不自动修改设置。

示意响应：

```json
{
  "roots": [{"path": "/srv/projects", "label": "projects"}],
  "path": "/srv/projects",
  "directory_source": "external",
  "parent": null,
  "entries": [
    {"name": "teamx", "path": "/srv/projects/teamx"},
    {"name": "notes", "path": "/srv/projects/notes"}
  ],
  "can_select": true,
  "truncated": false
}
```

外部目录策略关闭时返回空 roots；当前成员的受管默认目录仍可浏览与恢复默认。没有可浏览目录时返回明确的 `unavailable_reason`。受管目录返回 `directory_source=managed`，仅默认根路径的 `can_select=true`，其子目录为 false。接口只枚举一层子目录，不读取文件正文，不返回文件列表，不递归扫描。

每次最多扫描 5000 个目录项、返回 1000 个可见子目录，并限制响应为 256 KiB；对已取得的结果排序。达到任一上限返回 `truncated=true`，界面说明列表不完整并保留路径定位。第一版不建设全文搜索索引、持久浏览游标或后台目录扫描任务。

只返回已通过外部根策略或当前成员受管浏览检查的真实路径。不可读的子目录可以省略；请求路径本身不可用时返回错误，不能伪装成空目录。执行文件系统 IO 时不持有 Room 管理器全局锁，返回前复核身份、epoch 和 Workspace 版本。

接口沿用现有 human 认证与来源校验，不加入 Agent 的 `executionPath`，不允许成员执行凭据枚举服务器目录。沿用现有本机免登录规则，不新增一次选择授权。响应 `Cache-Control: no-store`；前端以文本渲染目录名，不把文件名解释成 HTML。

建议错误码：`directory_unavailable`、`directory_not_allowed`、`directory_not_found`、`directory_not_directory`、`directory_permission_denied`、`directory_path_changed`。用户错误提示与系统日志分开，不返回原始系统异常或敏感凭据路径。

### 5.2 界面布局与交互

成员详情增加“工作目录”，显示当前来源、准确路径和操作状态：

```text
工作目录
指定目录 · /srv/projects/teamx
[选择目录]  [恢复默认]

选择 TeamX 服务所在机器的目录。
```

「选择目录」打开网页弹窗，初始位置为当前生效目录：顶部为始终可编辑的路径栏、返回上级与 home 快捷按钮，多个允许根时提供切换；中间为一层子目录，底部为“使用此目录”“取消”，默认根路径显示“使用默认目录”。目录行进入子目录；返回上级不能越过当前允许根或成员默认根，home 可一键回到允许根目录。不要求选择后再粘贴路径。

- 选择只更新表单草稿；点击“应用”才提交 Workspace 操作。浏览和取消不修改配置、不轮换 Session。
- “恢复默认”把草稿改为默认来源，并展示默认目录；仍需应用。
- 已有 Session 时，应用前就地说明“应用后会结清当前执行并重置该成员私有上下文，工作文件保留”。沿用应用按钮，不额外叠加确认弹窗。
- 同目录成员可展示“与 Developer 共用”等说明；显示名只用于展示，目标仍以完整成员身份定位。
- 房间级 Workspace 页面同时展示各成员默认／实际目录及来源，避免仍声称所有成员使用独立副本。仓库设置需说明它配置的是默认受管目录。
- 多名成员的目录同时失效时，房间级表单允许一次修正多个覆盖值，并提供“全部恢复默认目录”。提交前展示受影响成员，避免严格全目标验证导致逐成员修复无法保存；不自动清空其他成员设置。
- 浏览目录的返回值只有在 RoomInstance、成员身份、目录请求序号均匹配时才能更新弹窗。切房、切成员、关闭重开和连续导航都应丢弃迟到响应。
- 轮询不覆盖未提交草稿；状态版本改变时提示冲突，由用户刷新并重新选择，不能自动覆盖其他成员的设置。
- 目录名允许换行以外的正常文本；长路径可换行／横向滚动，不能挤出按钮。手机采用适合窄屏的弹窗布局，保留返回与确认操作，沿用 TeamX 绿色控件和键盘焦点规范。

目录选择器独立为一个前端模块，例如 `features/directory-picker.mjs`；复用现有 dialog／按钮样式，不引入新 UI 框架。

## 6. 应用、Session 与恢复流程

### 6.1 复用 Workspace 管理 API

沿用 `GET /v1/workspace`、`POST /v1/workspace/apply`、`POST /v1/workspace/retry`。目标仍为完整 Workspace 配置，增加 `member_directories`；成员表单基于已观察版本只修改对应键，保留其他成员覆盖值、root、repository 和 binding。

继续使用完整 human／Room 身份、稳定 operation ID 和 `expected_version`。多个成员表单同时保存仍可能发生 Workspace 版本冲突，第一版明确刷新后重试，不另建自动字段合并机制。同 ID 同请求查询原操作，同 ID 不同请求拒绝。

状态响应的成员项保留既有 `workspace` 默认相对路径字段，新增 `default_directory`、`effective_directory`、`directory_source`。不要改变旧字段语义。操作记录中的 `Members[].Workspace` 也保留默认路径；有效目录从冻结 Target／PreparedConfig 解析。

需要同时保留“原始请求目标”和“解析后的规范目标”：符号链接输入在准入时固定真实路径，同 ID 重试复用原目标，不重新跟随链接生成新目标。

仅覆盖值改变时，进入本地目录分支；仓库／绑定改变时沿用原仓库准备分支。前端第一版将二者分开提交，不在一次表单保存中混合切换外部路径和初始化仓库；后端也明确拒绝这种混合请求，降低中断恢复的组合复杂度。

当前 HTTP apply 会先调用 `prepareWorkspacePlatform`，管理准入还会调用 `workspacePlatformTargetLocked`。目录修改分支必须在这些平台准备入口之前识别，并在锁内核对仓库字段确实与当前快照一致；不能因为表单携带原 repository／binding 就触发远端查询或凭据准备。请求规范化、实际受理与提交仍复查原版本，不能依赖锁外读取到的分类结果。

同一规范目标不产生目录切换、版本增长或 Session 轮换；前端禁用无变化应用，后端返回 `unchanged=true`，不创建变更操作。真实变更则必须先落原操作记录再执行。

### 6.2 执行顺序

```text
校验身份／版本／目录策略／共用约束
  → 保存固定目标和原快照，预留目标目录
  → 停止 Room 新回合并结清旧执行
  → 本地复核目标，冻结受影响成员及 Session 代际
  → 保存新 Workspace 配置
  → 仅轮换实际运行配置变化的已有 Session
  → 重组 Room 服务、保存完成回执、发布状态
```

第一版复用当前 Room 级 Workspace 结清，可能短暂中断／暂停整个 Room，不承诺成员级无感热切换。当前 `runWorkspace` 会关闭服务并取消活动回合，不能把它描述成自然等待任务完成；界面要如实显示结清状态，沿用 `pausePendingWorkspaceTurns` 对未读／未完成工作要求显式继续的行为。

目录修改分支需要修正当前“所有已有 Session 都加入 RotateMembers”的逻辑：按前后实际执行配置比较，只轮换 cwd 或实际运行说明／环境发生变化的成员。未改变且满足既有恢复条件的成员在结清后使用原 Backend 配置恢复原 SessionID；首次启动的成员直接使用新 cwd，不制造空轮换。原本就不满足恢复条件的成员继续显示既有修复要求，不放宽恢复合同。纯目录修改必须避免重新追加受管仓库指导造成所有成员被误判为变化。

保留公共历史、成员身份、游标、预算使用与原暂停意图；目录设置不发送新消息、不自动发起模型回合、不重放失败／中断任务。恢复默认也要经过相同流程，不能复活过去在默认目录工作的旧私有 Session。

操作完成后“配置已生效”表示目录配置及 Session 引用已经更新，新 Session 可在下一次用户明确继续时按需创建；不代表模型已经执行或完成业务任务。

### 6.3 失败与重启

- 提交前失败：保留原配置与目录现场，失败操作阻止冲突执行，显式重试使用固定目标；沿用现有允许修订失败准备目标的机制。
- 配置已提交、轮换未完成：沿用 `ConfigCommitted`、`PreparedConfig`、`SessionsUpdated` 等证据恢复，不允许旧 Session 在新 cwd 下继续运行，不自动回滚文件。
- 写入结果不确定：冻结相关配置并核查持久状态，不能把超时当成未执行，也不能用新 ID 盲目重发。
- 重启只做本地目录与原 Session 配置复核。路径不可用时保留已保存值、显示错误，允许查看历史和修复路径，不静默恢复默认。
- 需要修复不可用外部路径时，管理界面与 apply 必须能够在 Room 成员服务尚未成功打开时工作。扩展当前 `startWorkspaceApply` 对活动 service 的要求：仅纯目录变更允许以目录级 human 身份进入，要求完整 Room 快照、无冲突操作，并由原有进程／执行归属记录证明 Room 已结清；不能以“内存中没有 service”代替结清证据。此时 `SourceEpoch` 可为空，记录验证仅对该纯目录分支接受空值，历史读取使用目录级已有入口；重试仍重新核对结清状态，不伪造一个成员 service epoch。
- 重试和正常重启不会重复轮换已完成成员、重新执行仓库准备或访问远端。正常恢复始终保留原绝对 cwd 和 Backend 指纹校验。

删除成员／Room 或恢复默认只解除外部目录引用。不得删除、移动、chmod、递归清空外部目录，也不得把其内容打包进 Room 备份。现有删除与备份仅处理受管目录，需用回归测试证明没有沿新覆盖值遍历外部文件。

## 7. 共用目录与并发边界

第一版支持同一 Room 中多个成员选择完全相同的规范外部目录，条件是 Room 冻结调度模式为 `serial`。Room／Inbox 输入继续共用现有调度名额；不创建新的文件锁或改变调度模式。

| 情况 | 第一版处理 |
| --- | --- |
| 串行 Room，多成员相同外部目录 | 允许，页面显示共用成员 |
| 并行 Room，各成员外部目录互不重叠 | 允许 |
| 并行 Room，成员外部目录相同或父子重叠 | 拒绝，提示需串行 Room 或独立目录 |
| 同一 Room，不同外部目录为父子关系 | 拒绝，第一版只提供清晰的独立目录或完全相同目录 |
| 同一部署不同 Room，外部目录相同或父子重叠 | 拒绝，提示已有 Room 占用 |

跨 Room 检查针对外部目录绑定，不把整个项目祖先目录与其中 TeamX 自身保存的默认目录一概视为外部共享。受管目录内部不能被指定为外部目录，沿用第 4 节保护规则。

在管理器现有锁下检查已保存的外部绑定及未结清操作的原／目标路径并登记预留；复用 Room 快照和 Workspace 操作作为权威证据。可维护可重建的内存索引，不新增持久目录锁服务。启动时从配置和未完成操作重建，检测到历史冲突时冻结相关 Room 并显示诊断，不任选一个自动执行。

恢复默认、切换到其他路径、删除成员或 Room 后，须等相关旧执行和操作结清才释放旧路径占用。失败操作保留必要占用直到显式恢复，不能仅因 HTTP 请求返回错误就释放。

以上协调只覆盖同一 TeamX 部署。不同 home 的服务、编辑器、人工终端及脱离管理的后台进程不受 Room 调度保护。共用目录不提供独立分支或独立 Git 暂存区；一个 Agent 提交时可能包含另一个 Agent 的修改。相关说明放在共用目录提示和开发指南中，不把串行回合描述成完整的文件系统互斥保证。

## 8. 开发拆分与源码落点

### 阶段一：成员目录覆盖与完整后端行为

交付可通过既有管理 API 使用的完整切换流程：

- `workspace_config.go`：覆盖字段、规范化、相等比较、路径解析及快照验证。
- `config.go` 与配置样例：`workspace_roots` 的默认值、空数组和重启生效语义。
- 建议新增 `workspace_directories.go`：根策略、规范路径验证、共用约束、可重建的目录引用检查；名称按长期行为命名。
- `workspace_management.go`、`workspace_records.go`：本地目录分支、固定目标、操作深拷贝、受影响成员轮换、关闭状态下的修复和冲突协调。
- `runtime_assembly.go`、`model_references.go` 及当前配置生成入口：统一实际目录；保留历史恢复快照。
- `tools.go`、`workspace_git_managed.go`、相关运行时说明生成：正确 cwd、外部目录下受管仓库能力拒绝和说明过滤。
- 删除、备份和成员移除入口：解除覆盖引用并验证外部目录不被清理。

验收达到：默认目录不变，API 可设置／恢复／共用目录，切换与重启一致，工具执行目录一致，失败可恢复。该阶段不以手工编辑快照代替正式入口，也不宣称按钮体验已交付。

### 阶段二：服务端目录选择与成员界面

交付 human 目录浏览 API、网页选择器、成员设置与房间总览、操作观察和错误反馈。更新 `server_access.go` 的接口边界、管理器路由，以及 `features/workspace.mjs`、`features/members.mjs`、`index.html` 和相关样式；目录浏览模块可独立复用。

验收覆盖按钮选择、路径定位、取消、恢复默认、版本冲突、迟到响应、远端部署语义、桌面／手机布局与键盘操作。沿用现有绿色视觉体系，不重做整个成员设置页。

### 阶段三：真实运行验收与使用文档

使用隔离部署和实际交付的 DSH 完成第 9 节真实场景。更新 `docs/workspace.zh.md`、`docs/reference/workspace.zh.md`、必要的服务配置与开发说明，解释实际路径、默认仓库、共用目录、外部认证限制和容器挂载。

三个阶段均完成后才宣称整体交付；跨 Room 共享、并行共享写入、原生目录弹窗仍不在本方案范围。现有 Git／Scion 的真实平台待验项不能因为本地目录功能通过而被标为已完成。

## 9. 验证与验收标准

### 9.1 组件与集成

| 类别 | 必须验证 |
| --- | --- |
| 默认兼容 | 旧快照无覆盖字段；默认普通目录、Git／Scion 独立副本与认证流程保持现有行为 |
| 配置一致性 | 错误 membership、空值、map 深拷贝、相等比较、同目标无变化、旧版本表单拒绝、其他成员设置不丢失 |
| 路径策略 | 默认 home、配置空数组、多个根、根不可用、空格／中文、文件冒充目录、权限不足、越界、链接环、链接改指向、受保护目录 |
| 浏览接口 | human／Agent 凭据隔离、来源检查、一层目录、真实空目录与错误区分、数量／响应上限、目录名按文本渲染 |
| 实际执行 | DSH cwd、普通平台工具 cwd、模型切换后 cwd 一致；`workspace-git` 在外部目录明确拒绝 |
| 生命周期 | A → B → 默认；仅受影响 Session 轮换；从未启动成员；同目标不轮换；外部文件、未提交状态及仓库配置保留 |
| 恢复 | 受理、提交和轮换各边界中断；同 ID 查询／重试；提交结果未知；路径失效后在服务未打开时修复；重复恢复不重复轮换 |
| 共用约束 | 同 Room 串行共用、并行拒绝、父子目录拒绝、跨 Room 绑定与未完成操作争用、启动重建、结清后释放占用 |
| 清理边界 | 删除 Room／成员、备份和恢复默认不遍历或删除外部内容；默认目录清理保持现状 |
| UI | 草稿／轮询隔离、切房和切成员迟到响应、操作 ID 恢复、关闭弹窗不取消已受理操作、手机长路径与焦点 |

沿用仓库的验证入口，按实际改动选择测试，不新增仅镜像实现的断言：

```sh
go test -timeout=3m ./internal/room ./internal/agent/dsh ./internal/web
go test -tags=integration -timeout=8m ./internal/room -run 'Workspace|Directory|Tool|Model'
go test -race -tags=integration -timeout=8m ./internal/room -run 'Workspace|Directory'
```

上述入口的实际执行结果以实施记录为准。新增测试名按行为命名，不使用阶段编号；真实 DSH 测试归入现有 e2e 验证方式，不把 `-run '^$'` 编译通过当成功能验收。

### 9.2 真实 DSH 与浏览器

1. 在隔离配置、隔离 Room 和专用已有测试目录中启动 TeamX；不选择生产项目执行验收写入。
2. 用实际桌面浏览器选择外部目录，让 Agent 报告 cwd 并创建一个约定测试文件；服务端和文件系统共同核对路径。
3. 同一串行 Room 的第二个 Agent 选择相同目录，读取第一个 Agent 尚未提交的文件，验证同一份文件可见，同时私有 SessionID 各自独立。
4. 仅切换其中一名成员到另一测试目录，核对该成员新 Session、新 cwd、旧文件保留；另一成员结清恢复后的 SessionID 与原 cwd 保留。
5. 正常停服重启，验证各自路径与私有 Session 恢复；再恢复默认，核对回到原受管目录，外部文件仍存在。
6. 让外部目录暂时不可用，验证相关 Room 显示错误且不回退默认；从管理界面修复目录，显式继续后恢复执行。
7. 用另一设备或手机浏览器访问同一服务，确认选择器返回服务端测试目录，布局、路径显示和选择操作正确。若交付支持 Docker，另做实际挂载路径验收；未执行则明确记为待验。

分别报告组件／模拟集成、真实 DSH、真实浏览器和部署证据。DOM 驱动连接生产 HTTP 只能证明接口与交互逻辑，不能替代真实浏览器；本地目录功能验收不需要远端 push、MR 或 Scion 写入。

## 10. 完成条件

用户能通过按钮为指定成员选择服务端已有目录，在同一串行 Room 中让多个 Agent 共用文件；默认目录和默认仓库能力仍可恢复。目录切换、工具执行、模型配置与重启恢复使用一致的有效路径，外部文件生命周期仍由用户掌握。

开发范围以“成员目录覆盖 + 现有 Workspace 操作 + 服务端目录选择器”为界，不将其扩展为 Workspace 管理平台或新的 ACP 协议能力。
